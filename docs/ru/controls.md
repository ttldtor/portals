# Базовые элементы управления {#controls-ru}

[Подробная английская версия](../controls.md)

Label, Button и CheckBox реализуют `SizedWidget`, владеют проверенным
`GraphemeText`, измеряются в ячейках терминала и создают команды текста/заливки.
Собственная высота — одна строка; политика компоновки может выделить больше.
Управляющие байты текста показываются заменяющими символами текстовой подсистемы.

Для приложения используйте [декларативные фабрики](declarative-ui.md).
Дерево владеет виджетами; [наблюдающие ссылки](glossary.md) `ui::Ref<T>` и `Node<T>` обращаются к ним без продления времени жизни. ManagedScene удерживает
стандартные привязки и синхронизирует отображение.

## Защищённое поле пароля {#password-control-ru}

`Password` — отдельный `SizedWidget` для защищённого однострочного значения.
Подключи `<portals/ui_password.hpp>` для managed-рецепта и `ui::PasswordRef`,
псевдонима `ui::Ref<Password>`. Сцена владеет полем, моделью и привязкой; Ref
наблюдает за ними и становится доступен после полного монтирования рецепта.
См. [владение managed-объектами](managed-controls.md).

Эта полная программа сообщает, введено ли значение. F10 завершает работу.
Callback получает `SecretView` только на время синхронного вызова и не копирует
пароль в подпись.

```cpp
#include <portals/ui_password.hpp>

int main() {
  using namespace portals;

  ui::PasswordRef password;
  ui::Ref<Button> check;
  ui::Ref<Label> status;

  return ui::scene(ui::vbox(
    ui::password(password).placeholder("Password"),
    ui::button(check, "Check"),
    ui::label(status, "Enter a password")))
    | ui::onClick(check, [password, status] {
        return password.withPlaintext([status](SecretView value) {
          status.text() = value.empty() ? "Empty" : "Supplied";
        });
      })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Проверяемая операция Ref однократно сохраняет ошибки в сцене. Возвращаемый
результат проходит через адаптер клика в `runApp` без повторного отчёта. Приложение может само проверить
`expected<void, ManagedError>`. `ManagedError::password` сохраняет типизированный
`PasswordFailure`, в том числе независимые причины отказа защищённого доступа,
callback и очистки, без форматирования секретных байтов. Передавай view только
синхронному потребителю. Если сохранить его указатель или сделать обычную копию
байтов, временем жизни и очисткой этой копии управляет приложение.

`password.value()` возвращает проверяемое владеющее значение `PasswordValue`
текущего защищённого черновика. `password.value(value)` применяет защищённого
кандидата по режиму редактирования поля. Обе операции выполняются на UI между
кадрами. `PasswordValue::create(bytes, options)` проверяет создание; значение
по умолчанию недоступно, а проверяемое создание допускает корректное пустое
значение. Копии совместно удерживают неизменяемые защищённые байты и сравнивают
identity без сравнения и расшифровки содержимого. После замены старые зашифрованные
значения могут жить в snapshot до освобождения последнего владельца.
Plaintext-borrow остаётся доступен только в потоке создания.

У поля нет text/draft/caption getter, formatter, истории Undo/Redo, копирования
или вырезания в буфер обмена. `.readOnly()` запрещает пользовательские изменения,
сохраняя явный защищённый setter. `ui::password(ref, config)` принимает
`PasswordConfig`; необязательный provider `initial` один раз при монтировании
возвращает `expected<PasswordValue, PasswordFailure>`. Его предикат `validate`
синхронно заимствует `SecretView`; `false` сохраняет защищённый черновик без
публикации. Для общей committed-модели
создай `ManagedState<PasswordValue>` в принимающей сцене и передай его в
`ui::password(ref, state)`. Внешнюю модель и initial provider нельзя совмещать.

### Редактирование, отображение и ограничения

По умолчанию `EditMode::IMMEDIATE` публикует каждое принятое семантически корректное
изменение. `.editMode(EditMode::ON_COMPLETION)` сохраняет защищённый черновик до
Enter, программной активации или потери фокуса. `EXPLICIT` публикует по Enter или
активации и сохраняет черновик при потере фокуса. Некорректный UTF-8, разделители
строк и превышение лимита сохраняют прежний черновик. Семантический отказ
сохраняет новый защищённый черновик. Внешняя ревизия не перезаписывает изменённый
отложенный черновик: подтверждение возвращает `CONFLICT`, а Escape через проверяемый
защищённый доступ принимает последнюю модель. Escape не отменяет изменение,
уже опубликованное в immediate-режиме.

Успешный `PasswordResult::commit` владеет точной квитанцией
`PropertyUpdate<PasswordValue>`. Отклонённые уведомления наблюдателей не отменяют
commit; проверяй счётчики доставки отдельно. Отказ callback результата тоже не
отменяет публикацию. Managed-сцена восстанавливает последнюю чистую модель перед
кадром, даже если уведомление было отклонено.

Обычный режим показывает одну ASCII `*` на расширенную графему и раскрывает их
число. `.noEcho()` и ведущий pipe `| ui::noEcho()` скрывают значение, placeholder
и выделение, задают ширину в одну ячейку и фиксируют каретку у начала поля.
`false` восстанавливает маску. Layout и paint используют подготовленные числовые
метаданные и публичный текст маски/placeholder без расшифровки значения.
Placeholder — публичный текст; секрет в него передавать нельзя.

`PasswordOptions::limits` и `securePolicy.maxBytes` по умолчанию допускают до 4096
входных байтов; действуют оба ограничения. Явно увеличенные лимиты ограничены
`MAX_SECRET_BYTES`, 1 МиБ. Изменение отклоняется целиком, без усечения значения.
Поля `securePolicy`: `maxBytes`, `storage`, `lockPages`, `excludeFromDumps`
и `encryptWhileIdle`. Password требует native guarded storage и шифрование
между borrow на Windows или Linux. Он отклоняет `WIPE_ONLY`, отключённое
шифрование и неподдерживаемые гарантии, в том числе native policy на WASM;
автоматического ослабления защиты нет. Блокировка страниц опциональна;
исключение из дампов — отдельная гарантия Linux, недоступная на Windows.

Вставка по умолчанию отключена. Явно задай
`PasswordOptions::pastePolicy = PasswordPastePolicy::ENABLED`, чтобы принимать
routed paste или читать внедрённый сервис `Clipboard`. Собственный payload
сервиса и временные байты кодирования scalar затираются после использования.
Системный буфер обмена, вход декодера, внутренние буферы сервиса и память
вызывающего остаются вне защищённого хранилища.

Guard pages, затирание и idle encryption не гарантируют защиту от отладчика или
инструмента просмотра памяти наподобие ArtMoney с доступом к процессу. Plaintext
существует во время допущенного borrow. Обычный [LineEdit](line-edit.md) в режиме
`PASSWORD` и с `noEcho()` сохраняет plaintext-модель, getter и историю;
его маскирование относится к отображению.

### Ресурсы и явное владение

Ресурс может объявить `Password#password { text = "", placeHolder = "Password" }`
или опустить `text`. Непустые текстовые литералы и выражения text-resource
отклоняются, в том числе в наследуемых настройках. Передавай секреты через
типизированную C++-модель, проверяемый provider или кодовую привязку ресурса
`ManagedState<PasswordValue>`. В ресурсах доступны все поля `securePolicy` и `pastePolicy`;
секретный текст документа не становится защищённым хранилищем.
См. [ресурсы сцен](scene-loading-guide.md).

Диагностика строкового ресурса теперь обозначает источник фиксированной публичной
меткой `<string resource>`, в том числе при ошибках разбора и лимитов. Полный
входной документ больше не сохраняется в этом поле диагностики. Код отображения
или сопоставления такого payload должен учитывать это изменение совместимости.
Для файлового ресурса источником остаётся путь. Отклонение литерала не стирает
исходный буфер или файл вызывающего.

Для явного низкоуровневого владения подключи `<portals/password.hpp>`, создай
`Password` в дереве и передай общий `Property<PasswordValue>` в
`bindPassword(tree, router, node, model, onResult, clipboard, validate)`.
Храни полученный `PasswordBinding` на UI; дерево, router и scheduler должны
переживать привязку и её модель. Вызывай `binding.sync(routerFocus)` перед кадрами
после изменений модели и ввода. Проверяемые `setValue`, `confirm` и `cancel`
сохраняют типизированные ошибки. Допущенные callback переживают удаление поля,
его предка и уничтожение привязки. [Managed API](managed-controls.md) владеет
этими регистрациями и выполняет синхронизацию за прикладной код.

## Активация и фокус

Button реагирует на немодифицированный `Action::ACTIVATE`, включая Enter,
на `TextInputEvent` с `U' '` и на левое нажатие мыши. Отпускание, движение,
вставка и другой текст не активируют кнопку. Повторные события активации
вызывают повторные действия. Состояния удержания, наведения указателя и его захвата
этот компонент не ведёт. Обработчики кнопок с параметрами в декларативном API допускают
модификаторы; подробности — в [привязках](bindings-guide.md).

Маршрутизатор исключает скрытые и отключённые поддеревья. Обработчик может удалить
себя, предка или собственную привязку: принятый вызов и виджет сохраняются до
возврата. Исключение даёт `CALLBACK_FAILED`; выполненные внешние действия сохраняются.

Равная синхронизация текста, стиля и состояния ничего не меняет. Изменение текста
или политики ширины требует компоновки; стиль, фокус и отметка — отрисовки.
Методы и привязки выполняются на UI между кадрами.

## Привязка CheckBox к модели

Низкоуровневый `bindCheckbox(tree, router, node, sharedModel, callback)` возвращает
`CheckBoxBinding`. Модель `Property<bool>` и цель должны принадлежать одному
дереву. Привязка хранит подписку и регистрацию маршрутизатора, удерживает модель.
Дерево, Scheduler и маршрутизатор должны пережить привязку и модель.
Уничтожайте и перемещайте привязку на UI. Захваты могут освобождаться при следующей
очистке маршрутизатора.

Жест читает последний снимок, один раз выполняет `set(!value)`, синхронизирует
CheckBox и вызывает обязательный обработчик `CheckBoxResult`.
При `unexpected` модель и CheckBox сохраняются. Успешная квитанция содержит
зафиксированные значение и ревизию; отказы уведомлений не отменяют изменение.
Проверьте `rejected`, `cancelled` и `notification_error`; повторять переключение
при отказе уведомления нельзя.

Внешние изменения и доставка наблюдателям не вызывают обработчик прикладного действия.
Наблюдатель читает текущий снимок. В низкоуровневом коде вызывайте `binding.sync()`
перед каждым кадром после внешнего `set` или диспетчеризации: это восстанавливает
представление даже при отказе всех уведомлений. Равный `set` уведомления не повторяет.
Несколько CheckBox могут использовать одну модель; перед кадром синхронизируйте
все привязки, включая отключённые представления.

Если цель удалена во время публикации, принятый обработчик действия всё равно
получает квитанцию. Обновлять удалённое представление не требуется.
После дополнительного изменения модели из обработчика синхронизация повторяется.

## Низкоуровневая подготовка и рисование

EventRouter владеет фокусом. Получите `router.focused()` до `tree.frame` и передайте
его в `syncControl` для всех базовых элементов, включая Label. Синхронизация проверяет
состояние предков. Кэш отображения используется только при рисовании.
Внутри кадра `focused()` вызывать нельзя: восстановление фокуса меняет UI.

`ControlStyle` хранит normal/focused/disabled `CellStyle`. По умолчанию фокус
выделяется жирным/подчёркиванием, отключённое состояние — серым/курсивом.
Button добавляет `[ ` и ` ]`, CheckBox — `[ ] ` или `[x] `.
После изменения текста украшения пересоздаются под его политикой ширины.

Команды локальны относительно виджета. Владелец кадра переносит их через
`NodeGeometry::surface`, пересекает `NodeGeometry::clip` и вызывает
`renderFullFrame` до выхода из `tree.frame`. Заимствованный текст остаётся внутри
кадра; готовый владеющий `CellBuffer` передаётся FrameWriter после него.

Галерея показывает интерактивную форму; `--help` печатает справку до открытия
терминала. Конечный сценарий в памяти выполняет отдельный тест `portals_gallery_check`. Запуск и параметры описаны в [примерах](examples.md).
См. также [фокус](focus.md), [свойства](property.md), [компоновку](layout.md)
и [рисование](render.md).

## CheckBox с тремя состояниями {#check-box-with-three-states-ru}

`CheckState::UNCHECKED`, `CHECKED` и `MIXED` — явные значения модели.
`checkState()` возвращает последнее корректное представление, а прежний
`checked()` — true только для `CHECKED`. Boolean API, `Property<bool>`,
`CheckBoxResult` и старый цикл ввода сохранены.

Полная программа использует штатное владение сценой, маршрутизацию и cleanup:

\include check_state/main.cpp

По умолчанию `CheckBoxOptions::cycle = CheckCycle::TWO_STATE`: unchecked → checked,
checked → unchecked, mixed → checked. `THREE_STATE` явно включает цикл unchecked →
checked → mixed → unchecked. Enter/Space без модификаторов и нажатие левой кнопки
мыши используют одну политику; отпускание, движение, paste и ввод с модификаторами
не активируют контрол. Hidden/disabled предки запрещают ввод. Отдельного режима
read-only нет. `[-] ` отличается от `[ ] ` и `[x] ` без помощи цвета и имеет ту же
ширину, в том числе при disabled, linear и high-contrast выводе. Используются
обычные стили normal/focused/disabled; новый PSS pseudo-state не добавлен.

Общую модель создают через `ManagedScene::state(CheckState::MIXED)`, затем
`scene.bind(node, state, callback, options)` либо декларацию
`ui::checkbox(text, state, callback, style, sizePolicy, options)`. Callback
`CheckStateResult` необязателен. `.reference(ref)` и overload с Ref для managed
state публикуют прежний наблюдающий `Ref<CheckBox>` после успешного mount.
Callback получает точный результат `Property::set`: успешный commit может иметь
отклонённые или отменённые уведомления. Равные значения не публикуются повторно.
Callback не откатывает commit, его исключения проходят прежнюю typed boundary.
Внешнее изменение модели не вызывает business callback.

Низкоуровневый `bindCheckbox(tree, router, node, sharedProperty, callback, options)`
возвращает move-only `CheckStateBinding`. Он разделяет владение моделью, заимствует
tree/router/scheduler; они должны пережить token и модель. Уничтожение/перемещение
выполняется на UI между кадрами. Допущенный callback переживает удаление узла и
собственного binding. `sync()` перемещённого token возвращает `INVALID_ARGUMENT`.
Вызывай `sync()` перед кадрами после внешних изменений: отклонённое уведомление
не отменяет commit, равный `set()` не повторяет доставку. Managed scene выполняет
такую синхронизацию сама. Старое уведомление не заменяет новый snapshot.
Только изменение представления инвалидирует paint; ошибка invalidation сохраняет
старое представление. Смена состояния не выделяет память.

Некорректный `CheckCycle` или значение `CheckState` в модели дают
`TreeError::INVALID_ARGUMENT`. Ошибочное сырое значение Property остаётся
committed, но не попадает в glyph и не превращается молча в корректное при вводе.
Ошибки регистрации, UI-affinity, stale identity, закрытого владельца, активного
кадра и памяти используют прежние `TreeError`/`ManagedError`. Неуспешная
регистрация не оставляет action/subscription. Создание аргументов может бросить
до входа в API, как у boolean API.

### Агрегат и частичный отказ

`aggregateCheckState(span<const CheckState>)` не выделяет память и поддерживает
constexpr: пустой/полностью unchecked набор даёт unchecked, полностью checked —
checked, остальные корректные сочетания — mixed. Результат —
`expected<CheckState, TreeError>`, некорректный enum даёт `INVALID_ARGUMENT`.

Обновление группы — политика приложения без транзакционных гарантий. Полный
helper пытается обновить каждого ребёнка по порядку, сохраняет каждый настоящий
результат и затем пересчитывает агрегат по авторитетным snapshot:

\include check_state/group.hpp

Вызывай `checkbox_example::updateSelection(children, CheckState::CHECKED)` либо
`UNCHECKED` на UI. Проверяй каждый `children` receipt и его поля
`rejected`/`cancelled`, показывай частичный отказ; обновляй агрегат родителя,
только если `aggregate` успешен. Старое committed значение отказавшего ребёнка
участвует в расчёте. Пустая группа даёт unchecked; null owner — явная ошибка
ребёнка. Ошибка выделения хранилища receipts возникает до записи. Helper ничего
не удерживает; borrowed captures callback приложения должны переживать
допущенный вызов. Не связывай parent/child business callbacks рекурсивно:
внешние Property updates уже обходят business callback.
Оба исходника показаны выше полностью.

Готовый вариант с тремя состояниями: `ui::threeState("Selection", CheckState::MIXED)`.
Он возвращает `Description<ThreeState>`; первым аргументом можно передать
`ui::Ref<ThreeState>`. Тип `ThreeState` использует поведение CheckBox с фиксированным
циклом из трёх состояний. К нему применяются селекторы типов `ThreeState` и
`CheckBox`. Состояния экземпляров независимы, если явно не передать общий managed state.

Явный цикл CheckBox задаётся без позиционных заглушек:
`ui::checkbox(text, CheckState::MIXED,
CheckBoxOptions{.cycle = CheckCycle::THREE_STATE})`.
Та же форма принимает общий `ManagedState<CheckState>`; необязательный callback
квитанции следует после options. Options копируются сразу, в том числе из
временного значения. Прежние callback-first/trailing-options вызовы сохранены;
exact-type constraint не делает старый callback `{}` неоднозначным.

`GroupUpdate` отдельно возвращает `committed`, `unchanged`, `failed`,
`rejectedNotifications` и `cancelledNotifications`. `reportGroupUpdate(result, output)`
выводит эти счётчики, сохраняя у вызывающего все receipts и результат агрегата.

## Рамки и внешний размер {#control-frames-ru}

Рамка рисует выбранные одноклеточные границы вокруг содержимого. Добавь
`.framed()` к рецепту с размерами или используй `| ui::framed()`. Тип рецепта,
наблюдающая ссылка и обработчики сохраняются. Эта полная программа закрывается
по кнопке, F10 или Ctrl+C:

```cpp
#include <portals/ui_style.hpp>

int main() {
  using namespace portals;

  ui::Ref<Button> exit;
  auto scene = ui::scene(ui::vbox(ui::button(exit, "Exit").framed("rounded").width(18).height(3)));

  return scene
    | ui::style("Border:focused { foreground: #62b4d7; }")
    | ui::onClick(exit, ui::quit)
    | ui::onKey("F10 | Ctrl+C", ui::quit)
    | ui::runApp();
}

```

Встроенные варианты: `single` (также `plain`), `rounded`, `double`, `heavy` и
`ascii`. Неизвестное имя даёт типизированную ошибку `frame.pattern` при подготовке.
Символы проверяются по политике ширины терминала; встроенный символ не в одну
ячейку заменяется ASCII. Собственный набор содержит шесть печатных графем шириной
в одну ячейку, не более 64 байтов UTF-8 каждая.

Обычный рецепт получает пассивного родителя `Border`. Модификаторы ширины,
высоты, flex, видимости и доступности холодного рецепта относятся к внешней рамке
независимо от положения относительно `.framed()`. Пользовательский setup
по-прежнему получает исходный виджет. Для наблюдения за обёрткой или её удаления
объяви `ui::Ref<Border> outer` и используй `.framed(outer, "rounded")`.
Операции дерева во время работы над исходным ребёнком остаются локальными:
удаление ребёнка оставляет рамку, удаление внешней рамки убирает всё поддерево.
Ссылка на ребёнка не перенаправляется на родителя.

Например, `.height(6)` запрашивает шесть **внешних строк терминала**. При верхней
и нижней границе для содержимого остаётся не более четырёх строк. Это не число
дочерних контролов: их собственные размеры и политики компоновки сохраняются.
Родитель может ограничить выделение. Заголовок не увеличивает собственную ширину.

Для расширенной настройки есть `FrameOptions`. `sides` задаёт каждую границу и
её отступ; `title` хранит UTF-8 заголовок верхней границы; `titleAlignment` задаёт
START, CENTER или END. Ограничение заголовка по умолчанию — 4096 байтов.
`customGlyphs` задаёт углы, горизонталь и вертикаль. `border.maxPaintCells` по
умолчанию равен 16384; работа с заголовком учитывает все переданные байты и
графемы, включая обрезанный хвост. Ошибка подготовки не отправляет команды рамки.
Рисование не сохраняет чужие ссылки на текст и само не выделяет память.

`ScrollArea.framed(...)` настраивает собственную рамку без второго Border и
двойного отступа. При `ScrollPlacement::ON_FRAME` потенциально видимой
горизонтальной дорожке нужна нижняя сторона, вертикальной — правая. Дорожки
имеют приоритет над рамкой и заголовком. Перегрузки с внешним Ref у ScrollArea
нет: дополнительный узел не создаётся.

Цвета, жирность и состояния фокуса/недоступности используют существующие слои
стилей. Тип обёртки — `Border`; тип, ID и классы ребёнка сохраняются. Фокус
потомка включает оформление рамки с фокусом; отключённый предок имеет приоритет.
Геометрия и наборы символов задаются при создании, новых свойств PSS для них нет.
Существующие `BorderOptions`, `ScrollAreaOptions`, `ui::border` и `ui::frame`
остаются доступны.
