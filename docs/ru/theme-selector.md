# Выбор темы {#theme-selector-ru}

[English version](../theme-selector.md)

`ui::themeSelector` предоставляет модальное окно каталога для
[модели предпросмотра тем](theme-selection.md). Контрол управляет списком,
предпросмотром и действиями восстановления через существующие механизмы
диалогов, фокуса и клавиатурных привязок. Переопределения стилей приложения
и пользователя сохраняются.

## Полный нативный пример

Откройте Themes кнопкой или сочетанием `Ctrl+K, Ctrl+T`. Перемещение по списку
включает предпросмотр. Apply сохраняет выбранную тему, Cancel восстанавливает
предыдущую. F10 завершает приложение из основной формы. Модальное окно
обрабатывает собственные клавиши отмены.

\include{lineno} examples/guide_theme_selector.cpp

Программа собирается как
`portals_docs_theme_selector` и включён в потребитель установленного пакета.
В его main нет транспорта воспроизведения или эмулятора терминала.

## Композиция и команды

Объявите селектор слоем сцены через `ui::scene(body, selectorRecipe)` и передайте
каталог прямо в `ui::themeSelector(reference, choices)`. Сцена владеет моделью
и контролом. Отдельная ссылка на модель и стадия её установки не требуются.
Повторная установка модели возвращает типизированную ошибку подготовки.

Для лимитов каталога, преобразования текста или начального выбора можно передать
владеющую `ui::ThemeSelectorCatalog`. Поле `choices` содержит те же элементы,
а `selection` — прежние `ThemeSelectionOptions`. Для синхронной фабрики необязательный `initialId`
включает и подтверждает выбранную тему после конфигурации сцены, до публикации
ссылки на селектор. Начальный выбор не вызывает `onCommitted`. Его ошибка
обрабатывается обычным путём подготовки и очистки до открытия терминала.
При запуске через `ui::Scene` фабрика начальной темы выполняется в контексте её подготовки. Собранная
ошибка короткой команды предотвращает подтверждение начальной темы и публикацию
ссылки на селектор. Уже выполненные действия приложения не откатываются.
Подготовленные рабочие фабрики откладывают начальный выбор до готовности executor;
см. [подготовленные темы](theme-selection.md#prepared-theme-worker-ru). Их ошибки
запуска поступают в диагностику времени выполнения, а прежняя тема остаётся активной.

Перегрузка с явным `ui::ThemeSelectionRef` и стадия `ui::themeSelection`
сохраняются для приложений со своей моделью или контролами. Модель и контрол
должны принадлежать одной сцене. Подключение следует за конфигурацией сцены;
сочетать каталог по умолчанию со второй явной установкой модели нельзя.

`ui::Ref<ThemeSelector>` наблюдает за контролом сцены; прежняя
`ui::ThemeSelectorRef` также поддерживается. Копии ссылок не удерживают сцену
или виджеты. Проверяемые команды возвращают
`std::expected<void, ManagedError>`:

| Команда | Поведение |
|---|---|
| `open()` | Открывает окно или возвращает ему фокус; само открытие не вызывает фабрику темы. |
| `apply()` | Подтверждает выбранный активный предпросмотр, однократно вызывает необязательный callback и пытается закрыть окно. |
| `cancel()` | Восстанавливает сохранённую тему, затем пытается закрыть окно. |
| `closeKeepingPreview()` | Скрывает окно, не подтверждая и не отменяя предпросмотр. |

Через эту же ссылку доступны проверяемые `preview(id)` и `commit()` для
программной смены темы в существующей модели. `commit()` подтверждает активный
предпросмотр; он не вызывает `onCommitted`, не закрывает окно и не заменяет
`lastApply()`. Для выбранного в интерфейсе элемента, callback и результата
закрытия используйте `apply()`. `snapshot()` возвращает владеющий неизменяемый
снимок каталога и полномочий предпросмотра. Эти операции требуют подключённого
живого контрола. Ранее полученные снимки читаются и после его удаления;
ссылка не удерживает модель.

Escape и щелчок снаружи используют проверяемую отмену. Ошибка восстановления
оставляет окно доступным. **Close (keep preview)** — явное действие для случая,
когда восстановление недоступно. После него сессия предпросмотра модели
остаётся активной; скрытие не означает успешной отмены.

Сами команды не публикуют диагностику и не останавливают приложение.
Возвращённый из обработчика приложения проверяемый результат использует
обычную политику ошибок runner. Встроенные действия селектора сообщают
восстановимые ошибки через существующую диагностику, сохраняя доступ к
действиям восстановления.

## Настройки и успешное применение

`ThemeSelectorOptions` содержит владеющие подписи, ограничения текста,
необязательный resolver, существующие `DialogOptions`, `openingShortcut`
и `onCommitted`. По умолчанию окно модальное, по центру, размером 60 на 20
ячеек с отступом в одну ячейку. Сочетание открытия — `Ctrl+K, Ctrl+T`;
`std::nullopt` отключает привязку. Удаление контрола прекращает действие
сочетания, в том числе незавершённой последовательности.

Для открытия нужны завершённое подключение, выполненное размещение и корректный
viewport размещённого host. Одного `prepareChecked()` недостаточно для размещения.
После учёта
отступов и максимального размера диалога доступная панель должна быть не меньше
4 на 9 ячеек. Меньший размер возвращает проверяемую ошибку. Список резервирует
место для полос прокрутки: в узком окне полоса не занимает последнюю ячейку
содержимого. Диалог и кнопки настраиваются обычными [слоями стилей](style-layers.md);
правила приложения и пользователя остаются выше темы предпросмотра.

`onCommitted` — необязательный синхронный callback UI-потока, возвращающий
строго `std::expected<void, ManagedError>`. Аргумент ID заимствован только
на время вызова; для хранения его нужно скопировать. Библиотека не выполняет
файловый ввод-вывод. Callback не должен блокировать UI.

Ошибка callback не отменяет успешное подтверждение и не пропускает попытку
закрытия. `lastApply()` возвращает владеющий неизменяемый `ThemeApplyOutcome`:
подтверждённый ID, фактическое состояние закрытия и отдельные полные ошибки
callback и закрытия. Если возникли обе ошибки, `apply()` возвращает первую,
а результат сохраняет обе. Метаданные читаются и после удаления контрола.
До первого подтверждения результат null; ошибка до подтверждения сохраняет
предыдущий результат. Повторная попытка закрытия сама по себе не повторяет
callback.

Закрытие может уже примениться, а последующее уведомление фокуса — завершиться
ошибкой. Тогда результат содержит `CLOSED`: селектор не открывается заново
ради имитации отката. Ошибка до применения закрытия оставляет `OPEN`.

## Внешние изменения и ограничения

Успешная внешняя смена темы вытесняет предпросмотр, даже если цвета совпали.
Открытый контрол обновляется через существующую инвалидацию. Apply недоступен
до нового явного предпросмотра; обычная отмена не может затереть более новую
внешнюю тему. Действие восстановления позволяет скрыть окно, сохранив текущий
вид.

Ограничения каталога и стилей задаются моделью и движком стилей. Селектор
не создаёт второй каталог, таймер опроса, реестр тем или scheduler. Обычные фабрики
без аргументов и callback сохранения выполняются синхронно в UI-потоке и не должны
блокировать его. Для дорогой подготовки используйте `ui::preparedTheme`. Импорт тем
и автоматическое сохранение конфигурации — отдельные возможности.
