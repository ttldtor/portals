# Ограниченные запросы к модели {#model_queries-ru}

[Подробная английская версия](../model-queries.md)

`<portals/model_query.hpp>` предоставляет экспериментальные явные запросы к неизменяемым индексированным снимкам. Запросы используют существующие `Model` и `Scheduler`. Язык запросов, база данных и неявный ввод-вывод в этот слой не входят.

## Источник, критерии и страница

`Query<T, Q>` владеет исходным снимком, критериями `Q` и `RowRange` в отфильтрованном и отсортированном результате. Критерии и достижимые из рабочего потока данные должны владеть своей памятью, оставаться неизменяемыми при совместном использовании и допускать уничтожение в потоке последнего владельца. Заимствованные UI-ссылки в критериях запрещены.

`transformSnapshot` локально фильтрует, стабильно сортирует и выбирает страницу. Предикат имеет сигнатуру `bool(const T&, const Q&)`, компаратор — `bool(const T&, const T&, const Q&)` и задаёт строгий слабый порядок. Равные ключи сохраняют исходный порядок. Строки результата сохраняют полный `RowId`, включая поколение. Локальное вычисление требует копируемых строк: страница хранит непрерывный массив переупорядоченных значений. Оно не обращается к провайдеру для загрузки ещё неготовых исходных строк.

Результат `expected<QueryPage<T>, QueryError>` содержит собственную страницу с исходной ревизией и числом строк после фильтрации до разбиения на страницы либо типизированную ошибку. Исключения обработчиков, отмена, нехватка памяти, неготовность источника и исчерпание лимита различаются.

| Лимит по умолчанию | Значение | Что ограничивает |
|---|---:|---|
| `maxInFlight` | 4 | Резервы запросов, включая отменённые токены, которые ещё удерживают рабочие потоки |
| `maxOutputRows` | 256 | Размер запрошенной и возвращённой страницы |
| `maxSourceRows` | 65536 | Число строк, рассматриваемых локальным вычислением |
| `maxComparisons` | 1048576 | Число вызовов компаратора за одно локальное вычисление |

Все лимиты положительны. Страница по умолчанию — `{0, 256}`. Они не ограничивают длительность обработчиков и общий расход памяти процесса; провайдер ограничивает свою работу отдельно. Для большого индексированного источника можно использовать собственный провайдер вместо полного локального сканирования.

## Применение в UI-потоке

`QueryController<T, Q>::create(tree, context, source, provider, options)` создаёт долгоживущий `Model<T>` и ограниченные каналы завершений. Дерево должно жить дольше контроллера. Создание, отправка, получение снимка кадра, повтор доставки и закрытие выполняются в UI-потоке владельца. Рабочий поток может завершить свой токен запроса.

`MemoryQueryProvider` выполняет локальное преобразование. Пользовательский `QueryProvider` получает токены `QueryRequest` и может выдавать результаты с задержкой. Замещённый запрос кооперативно отменяется. Его резерв учитывается до освобождения всех владельцев в рабочих потоках и очередях. Позднее или устаревшее завершение не заменяет новый принятый запрос.

Успешная отправка или уведомление подтверждает принятие очередью. Для применения обслуживайте `Scheduler` и вызывайте `retryPublication()`, чтобы повторить сохранённые уведомления и проверить результат применения. Отклонённое уведомление или нехватка памяти модели сохраняет ожидающий результат для повтора. Проверяйте типизированные результаты, `lastError()` и `lastQueryError()`. Уже применённая модель остаётся доступной, пока новый запрос ожидает завершения.

`pin()` возвращает обычный неизменяемый кадр модели. `snapshot()` возвращает `QuerySnapshot<T>` со сведениями об источнике результата. `sourceRevision()` обозначает исходные данные; ревизия модели — принятую проекцию. Разные фильтры, сортировки и страницы могут иметь одну исходную ревизию и разные ревизии проекции. Эти два счётчика нельзя сравнивать как временные метки.

Начальная модель показывает исходный снимок. После запроса число строк модели равно размеру возвращённой страницы; `totalRows()` содержит число строк после фильтрации до выбора страницы. Приложение явно задаёт страницы. Автоматически загружаемого постраничного управляемого представления этот API не создаёт. `openRange()` остаётся обычным низкоуровневым потребителем модели.

Полный пример источника и запроса: [клиент query.cpp](../../tests/package_consumer/query.cpp). Он фильтрует цены, сортирует их по убыванию, запрашивает две строки, обслуживает планировщик, проверяет ревизии и идентичности строк, затем закрывает контроллер.

Закрытие отменяет работу и отключает каналы доставки без ожидания рабочих потоков. Токены могут пережить контроллер, но не должны захватывать его UI-объект. Автоматический перенос истории, мост к управляемой модели, SQLite, разбор произвольных запросов и внешние исполнители не поддерживаются.
