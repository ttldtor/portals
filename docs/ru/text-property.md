# Работа с текстовыми свойствами {#text-property-ru}

[Подробная английская версия](../text-property.md)

Один [`ui::Ref<T>`](../../include/portals/ui.hpp) позволяет менять текст, регистрировать обработчики кнопок и управлять историей редактора. Тип определяет доступные операции; это не только текстовая ссылка. В примере кнопка **Greet** меняет надпись; F10 закрывает приложение.

Подключите `<portals/ui.hpp>`. [Наблюдающая ссылка](glossary.md) `ui::Ref<T>` получает доступ к контролу только
после успешного монтажа всего описания. `text()` доступен у Label, Button,
CheckBox, открытых подклассов Control и LineEdit. Ссылки сохраняют идентичность
виджета и сцены без продления их времени жизни.

```cpp
#include <portals/ui.hpp>

int main() {
  using namespace portals;

  ui::Ref<Label> message;
  ui::Ref<Button> greet;

  auto scene = ui::scene(ui::vbox(
    ui::label(message, "Ready"),
    ui::button(greet, "Greet")));

  return scene
    | ui::onClick(greet,
                  [message] {
                    message.text() = "Hello!";
                  })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

## Программная активация кнопки

`button.onClick(callback)` регистрирует обработчик. У `ui::Ref<Button>` пока нет метода `click()` или `activate()`.
В собственной интеграции с существующим `EventRouter &router` вызывайте семантическую активацию на UI-потоке между кадрами:

```cpp
auto activated = router.invoke(button.node(), {Action::ACTIVATE});

if (!activated) {
  // Report activated.error() through the application's error policy.
}
```

Вызов `invoke` внутри обработчика клавиши или нажатия вернёт `WOULD_BLOCK`: вложенная доставка событий запрещена. Для обработчиков можно использовать общую функцию действия.


Здесь `button` — уже опубликованный `ui::Ref<Button>`, а маршрутизатор принадлежит тому же дереву. Это тот же путь обработчиков, который использует Enter; фокус не меняется. Проверяйте также успешный `DispatchResult`: недоступная кнопка даёт `DispatchStatus::NO_TARGET`. Ошибка или успешный результат не означают, что обработчик обязательно был вызван. Низкоуровневый контракт: [`EventRouter::invoke`](../../include/portals/action.hpp).
Для действия по клавише часто достаточно передать один и тот же callback в `ui::onClick` и `ui::onKey`, без искусственного нажатия.

## Изменить текст

Присваивание `message.text() = "Ready"` заменяет надпись, а `message.text() += "!"` добавляет текст в конец. Операции выполняются на UI-потоке с живой опубликованной ссылкой и сообщают ошибки коллектору сцены.

[Сборка самостоятельных примеров](examples.md).

`=` заменяет весь текст или черновик; `+=` дописывает в конец независимо от
выделения редактора. Методы `set` и `append` выполняют те же операции, поддерживают
цепочки и явное место вызова. Результат цепочки владеет своим объектом-посредником.
`result()` возвращает `expected<void, ManagedError>` конкретной операции;
`get()` — владеющий снимок `expected<std::string, ManagedError>`.
Снимок сохраняется после изменения или удаления виджета.

Присваивание `message.text() = other.text()` копирует значение источника
в получателя. Самоприсваивание равного значения ничего не меняет. Копирование
и перемещение самого посредника переносят наблюдаемую ссылку и необязательный
обработчик ресурсов.

Редактор использует `LineEditOptions::programmaticChange`, по умолчанию RECORD.
`field.text(ProgrammaticChange::RESET_BASELINE)` задаёт режим для всех последующих
операций посредника. Равное присваивание RESET очищает историю без перерисовки
и публикации. Детали — в [истории редактора](editor-history.md).

**Объединение текста**

```cpp
message.text() = message2.text() + message3.text();
auto saved = message2.text() + " " + text("{}", 123.0);
```

`+` читает источники и создаёт `ui::TextResult` с собственным проверенным
`GraphemeText` или исходной типизированной ошибкой. Источники и запрос кадра
сохраняются. При каждом объединении текст заново разбивается на графемы, включая комбинируемые знаки
и эмодзи с ZWJ. `result()` возвращает владеющую копию `expected<GraphemeText, ManagedError>`
и может выделять память. Сохранённый результат переживает удаление источников.

Объединение использует политику ширины левого текстового свойства и стандартные
`TextLimits`. Получатель повторно проверяет итог под своими ограничениями и
политикой ширины. Глобальная локаль или перенос между потоками не выбираются
автоматически. Ошибка чтения сохраняет причину, узел и место получения;
коллектор получателя добавляет `text.assign.concat` или `text.append.concat`.

**Текстовые ресурсы**

```cpp
auto localized = message.text(
  [](std::string_view key) -> std::expected<std::string, TextResourceError> {
    if (key == "currency") {
      return "USD";
    }

    return std::unexpected(TextResourceError::MISSING_RESOURCE);
  });
localized += i18n("currency");
auto joined = localized + " " + i18n("currency");
```

Посредник владеет обработчиком поиска ресурса; объекты захватов по ссылке должны
пережить его использование. Поиск выполняется синхронно только для ключей.
Суффиксы ресурсов при `+` используют обработчик крайнего левого свойства или
результата. Отсутствующий обработчик даёт `RESOLVER_REQUIRED`; остальные ошибки
сохраняют `TextResourceError` или `TextError` и смещение байта.
Смещение ошибки выражения относится к выражению, а ошибки итоговой проверки —
к объединённому тексту. Допустимые Unicode CR/LF/U+2028/U+2029 отклоняются
LineEdit с `INVALID_ARGUMENT`.

**Черновик и ошибки**

Изменение LineEdit принимает локальный черновик, перемещает курсор и якорь
в конец, сохраняя исходную ревизию модели. IMMEDIATE проверяет и публикует каждый
изменённый кандидат; ON_COMPLETION ждёт потери фокуса или Enter; EXPLICIT ждёт
Enter или программной активации. Принятое изменение вызывает обработчик результата.
Обновление модели из обработчика ресурсов не даёт старому кандидату новую
ревизию автоматически.

Отклонённая текстовая операция сохраняет текст, выделение и инвалидацию.
Принятый черновик может позднее получить VALIDATION_FAILED, CONFLICT или FAILED
при смысловой проверке/публикации. Он остаётся видимым; `.result()` сообщает
принятие текста, отдельный `LineEditResult` — результат публикации.
Предыдущие успешные операции цепочки сохраняются. Равная замена и пустое
добавление не требуют перерисовки. Внешние эффекты обработчиков не откатываются.

**Поток и время жизни**

Создавайте Ref на потоке UI получателя. Неуспешный монтаж оставляет Ref пустой.
После синхронизированной публикации копии и уничтожение Ref допускаются на другом
потоке; операции виджета и `node()` остаются на UI. Изменения отклоняются во время
кадра, подготовки или отчёта управляемой сцены и вложенной операции цепочки вызовов текста,
включая вход через другую Ref. Посредник должен пережить собственный вызов.

Удалённая цель даёт `STALE_NODE`, закрытая/уничтоженная сцена или пустая ссылка —
`CLOSED`, другой поток — `WRONG_THREAD` до чтения изменяемого состояния.
Если запись в коллектор сцены недоступна, ошибка остаётся в возвращённом результате.
Обработчик ресурсов может удалить цель или закрыть сцену: после него проверяется
её существование. Ref сохраняет слабое наблюдение сцены.

Форматирование, создание Ref, захваты обработчика и копии результатов могут
выделять память до входа в операцию. Внутри операции память даёт `NO_MEMORY`,
ёмкость — `NODE_LIMIT`. Причина сохраняется даже при нехватке памяти для контекста
диагностики. `get()` возвращает ошибку напрямую; изменения дополнительно
записывают её в ограниченный коллектор согласно политике сцены.
Смотрите [декларативный API](declarative-ui.md) для обработки ошибок подготовки.
