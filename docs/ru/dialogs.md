# Диалоги и overlay host {#dialogs-ru}

[English version](../dialogs.md)

Overlay host удерживает одно основное содержимое и зарегистрированные слои
диалогов в том же retained-дереве. Открытие меняет видимость, допуск ввода и фокус
без второго event loop и пересоздания сцены. Закрытый диалог остаётся смонтированным
и сохраняет состояние дочерних контролов.

## Полная modal-форма

\include guide_dialog.cpp

[Полный исходник](../examples/guide_dialog.cpp). Подключите `portals::core`;
см. [пакет](package.md). [Отдельный проект руководств](examples.md) собирает
`guide_dialog`, корневая сборка с `PORTALS_BUILD_TESTS=ON` — `portals_docs_dialog`.
Installed consumers компилируют этот же сопровождаемый исходник. Программа
открывает нативный терминал; CLI и режима автоматического replay у неё нет.

Поле и CheckBox хранят состояние сцены; пример не подключается к feed и не
сохраняет настройки. Tab остаётся внутри активного modal-слоя. Escape сначала
получают дочерние контролы; непринятая отмена закрывает верхний modal. Дочерний
контрол может принять Escape. Фоновый F10 и основная кнопка Exit недоступны, пока
modal открыт. Сначала используйте Close или непринятый Escape; F10 завершает
основную форму через штатный runner с восстановлением терминала.

Основное содержимое и изначально закрытые диалоги можно объявить вместе:
`ui::scene(body, layers...)`. Сцена создаёт для этих слоёв один overlay host.
Обычная `ui::scene(body)` сохраняет прежнюю композицию без дополнительного host.
Открытие и закрытие повторно используют смонтированные host и контролы диалогов.

Явная `ui::overlayHost(body, layers...)` пригодится для настройки host или
получения ссылки на него. Если передать такой host как основное содержимое сцены,
он останется выбранным и для дополнительных слоёв сцены. Диалоги передаются
аргументами слоёв, а не дочерними элементами `ui::vbox` или другого обычного layout.

Эта форма принимает и ленивую фабрику основного содержимого с аргументом
`ManagedScene&`, при необходимости дополненным `Application&`. Для расширенных
настроек запуска передайте `SceneOptions` первым аргументом:
`ui::scene(options, body, layers...)`. Прежние перегрузки настроек для одного
основного содержимого остаются доступными. Форма
`ui::scene(options, origin, body, layers...)` сохраняет переданное место создания
для диагностики; компактные адаптеры слоёв иначе указывают место вызова адаптера.

В позиции слоя можно передать существующий рецепт `ui::resource(...)`, если его
зарегистрированная фабрика возвращает диалог. Тип стёртого корня проверяется до
публикации ссылок: обычный контрол в этой позиции даёт `INVALID_ARGUMENT`,
а созданная часть композиции удаляется. Побочные действия фабрик сохраняют
прежний контракт. Host, скрытый внутри стёртого resource-рецепта основного
содержимого, не считается типизированным переопределением корневого host;
добавлять к такому содержимому слои сцены нельзя.

`ui::overlayHost(body, layers...)` принимает одно обычное содержимое и recipes
диалогов. `ui::dialog(reference, title, body, options)` создаёт изначально закрытый
слой. Заголовки используют существующие владеющие преобразования текста/ресурсов.
Формат конфигурации загружаемых сцен также предоставляет `Dialog` и `OverlayHost`;
см. [руководство по загрузке](scene-loading-guide.md). Копии Ref, захваченные до
mount, наблюдают общий слот: публикация происходит только
после успешного полного монтажа. Повторно откройте закрытый диалог, не монтируя его
контролы заново при каждом показе.

## Checked-команды и публикация

`reference.open()` и `reference.dismiss()` возвращают владеющий
`ui::DialogCommandResult`. В допущенных button/key/dismissal callbacks короткая
запись участвует в существующих диагностике и остановке runner. Вне этого контекста
проверяйте результат: boolean test сообщает успех, `error()` копирует владеющую
ошибку, `result()` возвращает `std::expected<void, ManagedError>`. Нового типа
результата callback, exception shortcut, скрытого retry или очереди открытия нет.
`reference.opened()` — checked-запрос `std::expected<bool, ManagedError>`, а не
долгоживущая ссылка на состояние.

Выполняйте UI-affine операции на потоке владельца. Cold/неопубликованный Ref или
закрытый owner возвращает `CLOSED`, удалённая identity — `STALE_NODE`, чужая сессия —
`WRONG_SESSION`. Первое открытие с привязкой к anchor до пригодного завершённого
layout возвращает `WOULD_BLOCK`, не планируя будущий показ. После штатной подготовки
приложение может явно повторить checked-команду, если панель ещё нужна. Открытие по
центру не требует ранее опубликованной геометрии: штатная подготовка вычисляет
положение панели.

Ошибки валидации и выделения памяти до публикации оставляют переход неопубликованным.
После публикации видимости/ввода/фокуса ошибка blur/gain или dismissal callback
сохраняет уже выполненный переход. Проверяйте `opened()`, а не считайте любую ошибку
доказательством неизменившегося состояния. `ManagedError` сохраняет phase, node,
исходную cause и независимую информацию cleanup; runner сообщает итог после попытки
восстановления терминала.

## Ввод, фокус и retirement

Modal ограничивает новый ввод и фокус своим поддеревом. Открытие из допущенного
callback не прерывает его и не воспроизводит событие у новой цели. Фоновый pointer
capture отменяется до дальнейшей доставки наружу. Tab и Shift-Tab используют
существующий порядок внутри верхнего modal. Даже modal без допустимого дочернего
фокуса закрывает доступ к body: фокус пуст, непринятый Escape работает. Вложенные
modal используют верхний слой; закройте его до закрытия нижнего. Удалённый opener
не используется повторно как identity возврата фокуса.

`.onDismiss(callback)` получает `DialogDismissReason::PROGRAMMATIC` для явной
команды или `CANCEL` для managed-отмены. Допустимы `void` и ровно
`std::expected<void, TreeError>`. Уведомление следует после commit; ошибка не
открывает панель заново и не повторяет callback при retry. Dismiss уже закрытого
живого слоя — no-op. Reentrant open/dismiss того же host во время staging,
focus/capture delivery, dismissal notification или teardown возвращает
`WOULD_BLOCK`. Не уничтожайте владеющие scene/application из callback.

Скрытие завершает activation. Disable завершает допуск ввода/modality и возвращает
фокус, сохраняя картинку disabled-слоя. Raw show/reenable не активирует managed-сессию:
нужен новый checked `open()`. Удаление завершает registrations и capture. Эти пути
retirement не вызывают пользовательский onDismiss. Допущенные callbacks удерживают
captures до возврата, в том числе при self-removal.

Отказ доставки model notification не откатывает опубликованное значение модели
или синхронную команду диалога. Equal assignment не повторяет отвергнутую доставку.
Сохраняются [property receipts](property.md) и [managed-подготовка](managed-controls.md).
Прикладная задача, намеренно вызывающая живой Ref позже, — новая команда, а не
автоматически отменяемое библиотечное уведомление.

## Немодальные панели и anchors

`DialogOptions::mode = DialogMode::NON_MODAL` сохраняет интерактивность body.
Открытие не забирает клавиатурный фокус. Pointer activation автоматически не вводит
keyboard focus scope; явный focus или Tab позволяет войти в панель. Закрытие
возвращает фокус только при сохранённом владении соответствующим переходом;
новый выбор body остаётся. Escape закрывает немодальную панель только при
маршрутизации отмены в этот слой; фоновый Escape не является глобальным close.

Эти options компилируются в installed consumer:

\snippet dialog.cpp dialog-options

Передайте их в `ui::dialog(reference, title, body, helpOptions)`. Consuming modifier
`.anchor(opener, DialogPlacement::BELOW_START)` разрешает cold Ref body при полном
монтаже; `ABOVE_START` предпочитает другую сторону. Anchor должен принадлежать
обычному body этого точного host. Другой host или любая dialog-owned цель даёт
`INVALID_ARGUMENT`, включая скрытое содержимое диалога. Неудачный полный mount не
публикует частичные Ref и завершает созданное поддерево.

Первое anchored open требует живой пригодной опубликованной геометрии; отсутствие
или полная обрезка даёт `WOULD_BLOCK`. У уже открытой панели stale/hidden/полностью
обрезанный anchor даёт центрирование на следующем prepared pass. Disabled anchor
с живой геометрией остаётся пригодным. Используется владеющая геометрия существующей
ограниченной подготовки, включая окружающие scroll areas. Граф anchors между
диалогами и дополнительные passes не вводятся.

## Геометрия и оформление

Intrinsic size host зависит только от body. Каждый диалог имеет structural root
размером с host и непрозрачную панель с рамкой. Это не `SizedWidget`: задавайте
размер панели через owning options вместо `ui::width/height`:

| Option | Значение по умолчанию и ограничение |
| --- | --- |
| `mode` | `MODAL`; `NON_MODAL` сохраняет ввод снаружи. |
| `placement` | `CENTER`; anchored preferences — `BELOW_START`/`ABOVE_START`. |
| `maximumPanelSize` | 60 на 20 ячеек; оба cap строго положительны. |
| `viewportMargin` | 1 ячейка, неотрицательный; уменьшается на tiny viewport. |
| `anchorGap` | 1 ячейка, неотрицательный. |
| `closeOnEscape` | `true`; дочерние контролы всё равно получают отмену первыми. |
| `frame` | Существующая glyph/paint-budget политика `BorderOptions`. |

Панель уменьшается до доступного места; tiny/zero viewport даёт обрезанную или
пустую геометрию без отрицательных размеров. Центрирование округляется вниз.
Anchored placement может выбрать сторону с большей высотой, затем ограничивает
координаты host. Paint и hit testing используют те же clipping и порядок sibling.
Shadow/backdrop engine, draggable window manager и отдельного style cascade нет;
поддерживаемое оформление задают существующие [слои стилей](style-layers.md).

`OverlayHostOptions::maxLayers` по умолчанию равен 32 и должен быть положительным.
Он считает все зарегистрированные слои, включая скрытые. Options-first overload:
`ui::overlayHost(hostOptions, body, layers...)`. Удаление завершает регистрацию;
повторный open/close не регистрирует ещё одну копию.

Закрытым и неизменившимся диалогам не нужны polling timer и постоянная перерисовка.
Завершение сцены освобождает их вместе с остальными управляемыми ресурсами.
Описанные ниже помощники предоставляют результаты выбора и действия сохранения
через те же host и планировщик.

## Готовые варианты с выбором

Для modal с одним из поддерживаемых наборов кнопок используйте
`ui::messageBox`, `ui::confirmDialog` или `ui::unsavedChangesDialog`.
[Полный исходник](../examples/guide_message_box.cpp) включён ниже; подключите
`portals::core`, как в руководстве по диалогам. Отдельный проект собирает
`guide_message_box`, корневая сборка с `PORTALS_BUILD_TESTS=ON` —
`portals_docs_message_box`.

\include guide_message_box.cpp

| Вариант | Кнопки | Начальный безопасный фокус |
| --- | --- | --- |
| `messageBox` | `ACKNOWLEDGE` | `ACKNOWLEDGE` |
| `confirmDialog` | `CONFIRM`, `CANCEL` | `CANCEL` |
| `unsavedChangesDialog` | `SAVE`, `DISCARD`, `CANCEL` | `CANCEL` |

`MessageOptions::defaultChoice` выбирает другую кнопку из набора этого варианта.
Для начального выбора `CONFIRM` или `DISCARD` требуется явное разрешение
`allowDestructiveDefault`. Эти помощники требуют modal-настройку `DialogOptions`
с включённым Escape. Для своего содержимого и стандартного набора кнопок можно
использовать перегрузку `ui::dialog` с результатом, описанную ниже; для немодальной
панели — обычный `ui::Ref<Dialog>`. Заголовок, текст и подписи владеющие; для них
доступен существующий синхронный resolver. Подписи должны быть непустым текстом
в одну строку. По умолчанию `textLimits` ограничивает ввод 16 384 байтами,
кластер 4 096 байтами, текст 16 384 graphemes и 32 768 ячейками;
`maxBodyLines` ограничивает перенос 4 096 строками.

`MessageBox` — наблюдатель, операции которого привязаны к UI-потоку. Его копии
не владеют сценой, виджетом или callback. Для холодного handle возвращается
`CLOSED`, для завершённой identity — `STALE_NODE`; поток и сцена проверяются.
Смонтируйте соответствующий диалог, затем вызывайте `open(callback)` или `cancel()` из
обычной цепочки обработчика. Обработчик получает `const MessageResult&` и должен
проверить результат до чтения выбора. Значение означает пользовательский выбор,
ошибка — технический отказ с полным исходным `ManagedError`. `CANCEL` — выбор,
а не техническая ошибка. `SAVE` фиксирует только запрос: пример не сохраняет
данные и не подтверждает успешную запись.
Пример отображает успешные запросы действий. Для восстановления, специфичного
для приложения, проверяйте полный объект managed-ошибки в callback.

`lastResult()` после завершения возвращает владеющий неизменяемый снимок;
до завершения он сообщает `WOULD_BLOCK`. Запрос остаётся занятым, пока ожидается
callback-доставка или завершение async-запроса. Callback выполняется штатным
UI-планировщиком и runner. `receive()` встраивается в существующую `UiTask` и
`UiAsyncContext`; отдельного event loop, собственного awaiter или coroutine-runtime
нет. Если ограниченная очередь completion заполнена, async-доставка откладывается;
повтор после dispatch использует освободившуюся ёмкость. По умолчанию сцена
ограничивает число ожидающих, зарезервированных и завершившихся, но ещё не
доставленных MessageBox-запросов значением 32 (`ManagedOptions::maxMessageRequests`).
Очередь и завершение сцены всё ещё могут отклонить или отменить доставку, поэтому
асинхронный результат не является долговечной бизнес-записью.

## Своё содержимое и стандартные наборы кнопок

В тело диалога с выбором можно передать владеющее описание контролов. Кнопки,
доставка результата и модальный фокус остаются под управлением существующей
сцены. [Полный пример](../examples/guide_dialog_actions.cpp) показывает результат
вопроса с ответами YES/NO:

\include guide_dialog_actions.cpp

Отдельный проект руководств собирает `guide_dialog_actions`, корневая тестовая
сборка — `portals_docs_dialog_actions`. В приложении нет эмулятора терминала или
replay-драйвера. Пример только показывает запрошенный выбор и не меняет настройки.

| `ui::DialogButtons` | Доступные ответы | Начальный фокус |
| --- | --- | --- |
| `OK` | `ACKNOWLEDGE` | `ACKNOWLEDGE` |
| `OK_CANCEL` | `ACKNOWLEDGE`, `CANCEL` | `CANCEL` |
| `YES_NO` | `YES`, `NO` | `NO` |
| `YES_NO_CANCEL` | `YES`, `NO`, `CANCEL` | `CANCEL` |
| `CONFIRM_CANCEL` | `CONFIRM`, `CANCEL` | `CANCEL` |
| `SAVE_DISCARD_CANCEL` | `SAVE`, `DISCARD`, `CANCEL` | `CANCEL` |

В `ui::dialog(reference, title, body, buttons, options)` аргумент `body` может
быть обычным владеющим текстом или холодным описанием контрола. Для получения
результата используйте `ui::Ref<MessageDialog>`. Прежняя перегрузка с
`ui::Ref<Dialog>` подходит для панелей, действиями которых управляет приложение.

Для расширенной настройки `MessageOptions::labels` содержит владеющие
локализуемые подписи, включая `yes` и `no`. Пустой `order` оставляет порядок
набора; явно заданный должен содержать каждый доступный ответ ровно один раз,
без посторонних ответов и не более трёх элементов. `defaultChoice` должен
принадлежать выбранному набору. Для `CONFIRM` и `DISCARD` сохраняется явное
разрешение на начальный выбор потенциально разрушительного действия.

Необработанный клавиатурный Enter активирует доступное действие по умолчанию.
Если Enter обработал дочерний контрол, он остаётся у него: поле может подтвердить
или проверить ввод без одновременного выбора ответа диалога. События с признаком
`KeyAction::REPEAT` не активируют кнопку результата или закрытие на рамке.
Если протокол терминала сообщает только отдельные нажатия, приложение не может
отличить удержание клавиши от нескольких самостоятельных нажатий. Необработанный Escape
и закрытие на рамке дают `CANCEL`, в том числе для `YES_NO`, где видимой кнопки
Cancel нет. Техническая ошибка остаётся ошибкой `MessageResult` и не превращается
в `NO` или `CANCEL`.

## Кнопка закрытия на рамке

К обычному диалогу или диалогу с результатом можно добавить `.closeButton()` либо
равнозначный модификатор `| ui::closeButton()`. Без явного запроса внешний вид
прежних диалогов не меняется. По умолчанию маркер `[x]` находится в конце верхней
границы и использует существующую маршрутизацию ввода и класс `dialog-close` для
стилей.

`DialogCloseOptions` позволяет выбрать `DialogClosePlacement::START` или `END`
и включить доступ с клавиатурным фокусом. По умолчанию кнопка не входит в обход
Tab и не заменяет начальный фокус действия. Она занимает три ячейки между углами,
не отнимая столбец у содержимого. Заголовок диалога остаётся ниже этой границы.
У диалогов сохраняется четырёхсторонняя рамка `BorderOptions`; отдельный
расширенный API `FrameOptions` для sized-контролов не меняет геометрию диалога.
При внешней ширине меньше пяти ячеек нет ни рисунка кнопки, ни цели для указателя
и фокуса. Отключённый, скрытый или удалённый диалог не может её активировать.

Если селектор тем включает эту кнопку, она выполняет его команду Cancel:
предпросмотр отменяется перед закрытием. Конфликт предпросмотра или повторный
вход в команду сохраняет существующую типизированную ошибку вместо молчаливого
закрытия селектора. Кнопка не обходит защиту выполнения команд.
