# Общие действия {#actions-ru}

[English version](../actions.md) · [Базовые элементы управления](../controls.md)

Используйте `ui::ActionSet`, если одной команде нужны одинаковые callback и
состояние представления в нескольких местах, например у кнопки и явно
назначенного сочетания клавиш. Для единственной кнопки без общего состояния
передайте callback непосредственно в `ui::button`.

## Полное приложение

\include guide_actions.cpp

[Полный исходник](../examples/guide_actions.cpp) подключает `portals::core`;
см. [описание пакета](package.md). Фабрика создаёт оба действия до возврата
описания сцены. Рецепты кнопок и этапы клавиатурной привязки удерживают
декларации до подключения к managed-сцене, поэтому локальный `ActionSet` может
выйти из области видимости до отложенного монтирования. После подключения
сцена владеет действиями в течение своей сессии и освобождает их callback при
закрытии.

Ключ `add` — организационное имя записи внутри набора. Оно отдельно от
`exclusiveGroup`, которая объединяет взаимоисключающее отмеченное состояние
представления. Краткая перегрузка `action(key, caption, callback)` подходит для
простого действия. Используйте `ui::Action` и `ui::ActionMetadata`, если нужны
текст сочетания клавиш или справки, а также начальные значения enabled,
visible, checked или exclusive-group. `add(...)` возвращает проверяемый
`std::expected`; краткая форма `action(...)` переносит типизированную ошибку
допуска к последующей привязке. Создание callback и его захватов происходит до
допуска и может выбросить исключение. В этом примере создание происходит
внутри фабрики, поэтому `ui::runApp` сообщает о `std::bad_alloc` как о
`NO_MEMORY`, а о другом исключении фабрики — как о `CALLBACK_FAILED`; после
очистки он возвращает 1. Создание самого объекта фабрики или её захватываемых
аргументов до вызова `runApp` находится вне этой границы.

`ui::ActionRef` — слабая ссылка на запись набора. Callback удерживает
подключённая сцена; при её закрытии ссылки становятся недействительными, а
callback освобождаются, даже если исходный `ActionSet` или холодные рецепты
ещё существуют. Одну ссылку можно передать нескольким кнопкам и в
`ui::onKey`. Если набор уже подключён к другой сцене, привязка сообщает
`WRONG_SESSION`.

Подпись и состояния enabled, visible и checked общие для всех кнопок и
обновляются из одной версии метаданных. Отключённое или скрытое действие не
вызывает callback. `checked` задаёт состояние представления и не переключается
автоматически при вызове. Непустая `exclusiveGroup` допускает не более одного
отмеченного действия с таким именем в наборе; организационные ключи для групп
не используются.

Поле `shortcut` содержит только текст для отображения. Оно не регистрирует
ввод и не создаёт глобальную привязку; действия также не добавляются в
`KeyHints` автоматически. Назначайте каждое сочетание через существующий
`ui::onKey`, чтобы сохранить обычные правила областей, модальных окон и
сопоставления клавиш. В примере привязки F2, F10 и Ctrl+C заданы явно.

Для каждого набора действуют положительные пределы: по умолчанию 256 действий,
1024 кнопки-представителя, 65536 байт для активных ключей и текущих метаданных,
256 байт на ключ. Измените их через `ui::ActionSetOptions`. Предел метаданных
учитывает активные данные набора; внешние снимки и уже выполняемый callback
могут независимо удерживать предыдущие данные. Ошибки допуска типизированы и
не публикуют частичную запись. Изменения и ошибки вызова возвращают
`EditorCommandResult`; метод `result()` предоставляет проверяемый результат
для непосредственной обработки. Managed-callback возвращают существующий
проверяемый результат, который сборщик ошибок сцены учитывает один раз.

Действия — декларации, создаваемые в коде. Загруженные ресурсы сцен не задают
исполняемые действия.
