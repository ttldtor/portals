# Компоновка Row и Column {#layout-ru}

[Подробная английская версия](../layout.md)

Размеры задаются целыми столбцами и строками терминала. Прямоугольники локальны
относительно родителя и используют полуоткрытые границы. `WidgetTree::arrange`
переносит координаты и пересекает области отсечения. Row располагает видимые
дочерние элементы слева направо, Column — сверху вниз. Отключённые элементы
занимают место; скрытые поддеревья не измеряются и не создают промежутков.

## Политики размеров

`LayoutItem` задаёт политику каждой оси. Обычный Widget использует автоматическую
политику и результат `measure`; `SizedWidget` хранит настраиваемую пару политик.
Для оси задаются минимум, предпочтительный размер, максимум, режим и положительный
вес гибкого распределения (`flex`). `INTRINSIC_EXTENT` выбирает измеренный размер; остальные предпочтительные
значения неотрицательны и ограничиваются минимумом и максимумом.
Недопустимые границы, режимы, веса и параметры дают `INVALID_ARGUMENT`.

Фиксированный и автоматический элементы начинают с предпочтительного размера.
Элемент в режиме `flex` начинает с того же размера и делит свободное место пропорционально весам.
Целочисленные остатки выдаются по порядку детей. Достигшие максимума пропускаются,
а их доля перераспределяется. После достижения всех максимумов остаётся свободное
место. Два равных веса в 11 ячейках получают 6 и 5 ячеек.

При нехватке места поздние автоматические и flex-элементы уменьшаются первыми
до минимума. Фиксированные размеры и минимумы сохраняются. `LayoutOverflow::CLIP`
сохраняет размеры, промежутки и отступы даже при выходе за доступную область;
отсечение предков ограничивает рисование и проверку попадания. Переполнение
представления координат даёт `INVALID_GEOMETRY`.

Отступы применяются с каждой стороны; промежутки — между участвующими детьми.
Выравнивание основной оси использует место, оставшееся после распределения:
start и stretch начинают от начального отступа, center оставляет перед группой
`floor(free/2)`, end — всё свободное место. На поперечной оси stretch или flex
заполняет доступный размер в пределах границ; фиксированный размер сохраняется.
Start/center/end используют те же правила. При нехватке места начало совпадает
с начальным отступом.

## Кадр и ошибки

`layoutTree` выполняет два прохода на потоке UI: собирает владеющие снимки через
`inspect` и `read`, измеряет детей перед родителями, затем размещает родителей
перед детьми. Временная таблица исчезает после прохода. Обычный родитель передаёт
область единственному ребёнку; для нескольких детей требуется контейнер `Layout`.

Вызывайте `layoutTree` внутри уже открытого `tree.frame`. Один кадр охватывает
компоновку, рисование и потребление заимствованных команд:

```cpp
// Between frames, after a viewport change:
auto invalidation = tree.invalidate(root, portals::Invalidation::LAYOUT);
if (!invalidation) {
  return invalidation;
}

std::expected<void, portals::TreeError> layout;
auto frame = tree.frame([&] {
  layout = portals::layoutTree(tree, root, viewport, viewport);

  if (!layout) {
    return;
  }

  // Paint the arranged tree and render borrowed commands before returning.
});
```

Предварительный проход может создать владеющий `LayoutSnapshot`, как при
[подготовке виртуальных представлений](virtual-preparation.md).
Он не удерживает ссылки на виджеты или команды рисования. Заключительная
компоновка и рисование выполняются в общем кадре.

`setSizePolicy` и `setLinearOptions` проверяют значения, меняют их между кадрами
и запрашивают компоновку. Собственные источники политик должны делать то же.
После изменения области просмотра запросите `invalidate(layout)` до нового кадра.
При ошибке прохода прекратите его использование для рисования и попаданий:
откат и автоматическая инвалидация внутри кадра не гарантируются.

Ошибки дерева передаются вызывающему коду. Арифметика даёт `INVALID_GEOMETRY`,
память — `NO_MEMORY`, исключения пользовательских функций — `CALLBACK_FAILED`.
`Layout` и `LayoutItem` вызываются под проверяемым заимствованием чтения.
Им запрещены операции дерева, рекурсивная компоновка, изменение моделей и I/O.
Рекурсивный `layoutTree` технически отклоняется с `WOULD_BLOCK`; пользовательский
C++ обязан самостоятельно соблюдать остальные ограничения.

## Собственные контейнеры

Наследуйте Widget для собственного измерения или `SizedWidget` для политик.
Grid/Overlay могут реализовать `Layout`: `childAvailable` даёт ограничения,
`measureChildren` объединяет владеющие `MeasuredChild` со стабильными `NodeId`,
а `arrangeChildren` возвращает один локальный прямоугольник на видимого ребёнка.
Указатель интерфейса используется только внутри `tree.read`.
