# DocumentView {#document-view-ru}

[English version](../document-view.md) · [LogView](log-view.md) · [Контролы прокрутки](scroll-controls.md)

`DocumentView` показывает документ в текстовом или шестнадцатеричном виде ограниченными окнами, не загружая целиком файл или логическую строку. Чтение и декодирование выполняются фоновым исполнителем приложения. UI рисует последнее неизменяемое подготовленное окно и продолжает обрабатывать ввод, пока готовится следующее.

@image html document-view.gif "Прокрутка документа, переключение источников и возврат к сохранённой позиции."

## Полная программа {#document-view-example-ru}

Соберите `portals_document_view_example` с `PORTALS_BUILD_EXAMPLES=ON` и запустите из каталога исходников Portals, где находятся `README.md` и `ReleaseNotes.md`. Кнопки переключают тот же контрол между файлами, обновляют текущий источник и возвращают к началу. При возврате к сохранённому дескриптору источника восстанавливается его байтовая позиция. F10 или Ctrl+C завершают приложение через стандартный runner.

[Полный исходник](../../examples/document_view/main.cpp)

\include document_view/main.cpp

Кратчайший файловый вариант — `ui::viewer("README.md")`. Сохраните `ui::Ref<DocumentView>`, если обработчикам нужно менять источник или позицию чтения. `ui::documentFile(path)` владеет UTF-8-путём; создание рецепта не открывает файл. Для возврата к сохранённой позиции используйте тот же дескриптор.

## Подсветка исходников SQL и Markdown {#document-view-syntax-ru}

Соберите `portals_document_highlight_example` с `PORTALS_BUILD_EXAMPLES=ON` и запустите из каталога исполняемого файла. Сборка копирует туда `orders.sql` и `notes.md`. Обе панели используют обычный Viewer: Tab меняет фокус, колесо и PgUp/PgDn прокручивают документ, F6 запрашивает точный цвет, F7 возвращает AUTO, F10 или Ctrl+C завершают приложение.

[Полный исходник](../../examples/document_view/highlight.cpp)

\include document_view/highlight.cpp

\htmlonly
<details><summary>Исходные файлы SQL и Markdown из примера</summary>
\endhtmlonly

\verbinclude document_view/orders.sql

\verbinclude document_view/notes.md

\htmlonly
</details>
\endhtmlonly

@image html document-view-highlight.gif "Подсветка SQL и Markdown с независимой прокруткой документов."

`.language("mysql")`, `.language("sql")` и `.language("markdown")` выбирают ограниченные лексические профили. Регистр имени не важен: `postgres`, `postgresql` и `sql` включают правила PostgreSQL, `md` служит алиасом `markdown`. Неизвестное имя включает обычный текст. Типизированный вариант принимает `DocumentLanguage`; `.language(DocumentLanguage::PLAIN)` отключает подсветку. HEX продолжает показывать исходные байты.

Профиль Markdown раскрашивает исходные заголовки, разделители, код внутри строки и ограждённые блоки, в том числе SQL. Преобразования Markdown в оформленный HTML здесь нет. SQL-профили распознают лексическую структуру; схемы базы и смысл запросов не анализируются. Профиль MySQL поддерживает ограниченную обработку разделителей и SQL mode. Неподдерживаемая конструкция или исчерпание лексических лимитов оставляют читаемый текст и отдельный статус подсветки.

Чтение, декодирование и лексическая обработка выполняются в фоновых задачах. При выборе языка по умолчанию действует `syntax::AUTO`: контрол быстро показывает ограниченную локальную подсветку и использует доказанный точный контекст, когда он доступен. Суффикс ` ~` рядом с процентом помечает предварительный цвет. Точный результат заменяет цвета одним обновлением и убирает метку, сохраняя текст и байтовую позицию.

| Политика | Поведение |
| --- | --- |
| `syntax::AUTO` | Быстрый локальный цвет и точное уточнение в пределах ограниченного дополнительного чтения. |
| `syntax::PREVIEW` | Локальный цвет либо уже известный точный; без длительного разбора контекста. |
| `syntax::EXACT` | Явно разрешённое отменяемое вычисление контекста от доказанной контрольной точки или начала источника. |

Запросите точный цвет через `.syntax(syntax::EXACT)` в описании или обработчике. `.syntax(syntax::AUTO)` возвращает стандартную политику. Начальный предел AUTO — 512 КиБ дополнительного чтения исходника на отображаемое окно; положительный `DocumentViewConfig.maxAutoHighlightBytes` позволяет его изменить. Это ограничение объёма, а не гарантированное время. Перерисовка и смена палитры не выдают уже завершённой попытке новый бюджет.

Предварительная подсветка может ошибаться, если окно начинается внутри длинной строки, комментария или Markdown-блока. Если всё окно находится внутри длинного комментария, предварительный режим может показать весь его текст обычным цветом до точного уточнения. Она не доказывает окружающий лексический контекст и не становится точной контрольной точкой источника. Точность ограничена выбранным лексическим профилем: это не проверка SQL или полный CommonMark. Точный цвет на далёкой позиции может потребовать большого чтения префикса и заметного времени. Навигация отменяет устаревшую работу; AUTO не запускает неограниченный проход от начала.

Объём файла не определяет резидентную память: сохраняются ограниченные окна, необязательные данные предварительной подсветки и фиксированный кеш точных контрольных точек, без полного индекса строк или токенов.

### Настройка ролей подсветки

Встроенные темы задают цвета текста для семантических ролей. Фокус сохраняет обычный фон `DocumentView`. Переопределяйте роли через PSS: смена палитры перерисовывает готовые диапазоны без повторного чтения и лексической обработки.

```css
DocumentView {
  role-keyword-foreground: #88c0d0;
  role-keyword-bold: true;
  role-string-foreground: #ebcb8b;
  role-comment-foreground: #81a1c1;
}
```

| Роль | Значение в исходнике | Значение из встроенной темы |
| --- | --- | --- |
| `keyword` | Ключевое слово SQL | Акцент, жирное начертание |
| `number` | Число SQL | Цвет заголовка |
| `string` | Литерал SQL или код Markdown | Акцент |
| `comment` | Комментарий SQL | Приглушённый цвет |
| `identifier` | Идентификатор SQL | Основной цвет текста |
| `operator` | Разделитель или оператор SQL | Основной цвет текста |
| `heading` | ATX-заголовок Markdown | Цвет заголовка, жирное начертание |
| `markup` | Разделитель Markdown или директива клиента MySQL | Акцент |

После каждого префикса `role-<имя>-` доступны `foreground`, `background`, `bold`, `italic` и `underline`. Фон задаётся по желанию. Обычный текст наследует `body`; значения `gutter` и `position` сохраняются. Отключённый контрол использует приглушённый цвет темы без добавления курсива.

`document.language("md")` собирает ошибку отклонённой команды в сцене; `document.setLanguage("md")` возвращает проверяемый результат. Загружаемая сцена в формате конфигурации принимает `DocumentView { file="notes.md" language="markdown" }`.

`document.status()` возвращает запрошенную политику `syntax`, точность показанного цвета `syntaxAccuracy`, состояние `highlighting` и необязательный `highlightErrorOffset`. Точность имеет значения `NONE`, `PREVIEW` и `EXACT`. `PENDING` означает ожидание точного контекста; завершённый `PREVIEW` — остановку ограниченного уточнения с предварительными цветами; `READY` требует доказанного точного результата. `UNSUPPORTED_PROFILE`, `RESOURCE_LIMIT`, `REPLAY_UNAVAILABLE` и `UNAVAILABLE` описывают ограничения подсветки отдельно от ошибки источника. При отказе необязательного уточнения сохраняются читаемый кадр и точность его фактически показанных цветов. `document.setSyntax(policy)` возвращает проверяемый результат, а `document.syntax(policy)` собирает ошибку отклонённой команды в сцене.

Для источника только с последовательным чтением задавайте язык в описании до монтирования. После подключения переход к другому непустому профилю возвращает проверяемую ошибку неподдерживаемой операции. Отключение цвета сохраняет принятые буферизованные байты. История ограничена: переразмещение, требующее уже вытесненных байтов, не является произвольной перемоткой назад. Если исходный диапазон превышает бюджет удерживаемого окна, следующий опасный запрос чтения отклоняется с `PAGE_TOO_LARGE`. Это не откатывает предыдущие чтения той же фоновой задачи и не обещает автоматического восстановления неперематываемого источника.

## Выбор файла {#document-view-files-ru}

Соберите `portals_document_files_example` с `PORTALS_BUILD_EXAMPLES=ON`. Введите путь и нажмите **Open** или Ctrl+O. F2 включает текстовый вид, F3 — шестнадцатеричный, F5 обновляет текущий источник. F10 или Ctrl+C завершают приложение. Подготовка источника выполняется в фоне, и интерфейс продолжает обрабатывать ввод.

@image html document-view-files.gif "Открытие README, ошибка отсутствующего файла и успешное открытие release notes. Кольцо обозначает введённое нажатие мыши."

[Полный исходник](../../examples/document_view/files.cpp) · [Цель сборки](../../examples/document_view/CMakeLists.txt) · [Манифест Windows](../../examples/document_view/windows-utf8.manifest)

\include document_view/files.cpp

Первый позиционный аргумент задаёт начальный путь. Без него пример открывает `README.md` из текущего рабочего каталога. Из каталога с EXE в Windows можно запустить следующие команды, заменив путь своим документом:

```powershell
./portals_document_files_example.exe --help
./portals_document_files_example.exe "C:\logs\session.txt"
```

В Linux используйте имя программы без `.exe` и путь файловой системы. Справка выводит назначение и параметры без открытия терминала. Код завершения: 0 при штатном выходе или показе справки, 2 при ошибке разбора командной строки, 1 при ошибке приложения. Имя, начинающееся с `-`, может быть буквальным путём; второй позиционный путь приводит к ошибке разбора.

Относительный путь отсчитывается от рабочего каталога приложения. В поле вводится сам путь; кавычки оболочки относятся к запуску из командной строки. Поддерживаются UTF-8, пробелы и абсолютные пути платформы. Расширенные пути Windows передаются файловой системе; работа сетевого пути также зависит от ресурса, разрешений и доступности. Переменные окружения и `~` автоматически не раскрываются. Манифест примера включает UTF-8 для аргументов процесса и поддержку длинных путей только у этого EXE.

Ошибка чтения показывается внутри рамки документа и остаётся доступна в поле `DocumentViewStatus::error` через проверяемый результат `reader.status()` и в управляемой диагностике. Исправьте путь и снова нажмите **Open**. Подпись использует стиль `body` и не становится строкой документа, номером строки или значением прогресса. Если памяти для необязательной подписи не хватит, исходная типизированная ошибка всё равно передаётся в диагностику.

Каждое нажатие **Open** создаёт дескриптор источника. Сохраните дескриптор, чтобы вернуться к его прежней позиции чтения; этот подход показан в [предыдущем примере](#document-view-example-ru).

## Чтение и навигация {#document-view-navigation-ru}

| Ввод | Результат |
|---|---|
| Up / Down, колесо мыши | Переход по визуальным строкам. |
| PageUp / PageDown | Переход на размер окна с настроенным перекрытием. |
| Home | Запрос байтовой позиции ноль. |
| End | Запрос последней полной страницы; подготовка может продолжаться, пока источник читается. |
| Left / Right при отключённом переносе | Сдвиг горизонтального окна ячеек. |
| Вертикальная полоса прокрутки | Запрос байтовой позиции при известном точном размере источника. |
| F5 | Обновление текущего источника. |

По умолчанию один нормализованный шаг колеса перемещает текст на одну экранную строку. Быстрый ввод накапливается, пока загружается окно. Ожидающие движения в противоположных направлениях могут компенсировать друг друга; попытка выйти за подтверждённую границу не создаёт долг для следующего движения. Home, End, переход ползунком и замена источника задают новую цель навигации. Другой шаг можно передать низкоуровневому конструктору через `ScrollAreaOptions::wheelStep`.

Положение ползунка — приблизительная проекция видимого окна на известный размер в байтах; это не значение покрытия в нижней строке. Промежуточные позиции ползунка отображаются на диапазон от нуля до `extent - visibleSpan`. На время перетаскивания этот диапазон фиксируется, а готовые окна не сдвигают удерживаемый ползунок относительно указателя. Перетаскивание в крайнюю нижнюю позицию запрашивает последнюю полную страницу, как клавиша `End`. Для доступного для позиционирования источника с известным точным размером подготовка сначала подтверждает кодировку у начала источника, затем ищет достаточно границ строк в обратном направлении и декодирует найденный хвост в фоновом потоке. Контрол сохраняет ограниченное окно строк без полного индекса. Номера логических строк в удалённом хвосте остаются неизвестными. Очень длинная строка без предшествующей безопасной границы по-прежнему может потребовать значительного фонового прохода. Для источников без нужных возможностей позиционирования или известного размера сохраняется отменяемый прямой проход. Явные команды `seekByte(offset)` сохраняют запрошенный исходный байтовый якорь и используют ограниченные локальные переходы без прохода всего предшествующего файла.

Промежуточные порции подготовки End не ждут следующего кадра; обычный путь layout и отрисовки нужен для готового окна. Длинные участки печатного ASCII при включённых переносах обрабатываются группами с сохранением тех же экранных строк и исходных байтовых позиций. Ограничение памяти не означает ограничение суммарного чтения: часть байтов может читаться повторно, а очень длинные логические строки по-прежнему могут потребовать значительного прохода. Мгновенный переход к EOF для произвольного источника не гарантируется.

Нижняя строка показывает приблизительное покрытие исходных байтов до нижнего края видимого содержимого. Уже на первом экране процент может быть больше нуля. Значение `100.0%` появляется только когда виден последний исходный байт; упреждающее чтение декодера и размер декодированного UTF-8 не считаются видимым покрытием. Если длинная строка без переноса обрезана справа, значение не станет 100%, пока не виден последний байт источника. При неизвестном размере показывается `progress unknown`, пока видимый последний байт не подтвердит конец; временное ожидание provider не означает EOF. Завершающий перевод строки не добавляет пустую строку отображения, но реальные пустые строки документа остаются видимыми. Исходный байтовый якорь и подтверждённый логический номер строки остаются доступны через `reader.status()`. Нумерация опциональна, по умолчанию выключена и использует только подтверждённые проходом номера. Перенесённые фрагменты сохраняют номер логической строки. Девятиячеечное поле показывает до семи цифр: `?` означает неподтверждённый номер строки, а `+` — подтверждённый номер больше отображаемого диапазона; этот предел отображения не ограничивает 64-битные байтовые смещения.

Доступный для позиционирования источник позволяет подготовить холодный переход далеко по документу из ограниченного локального окна, без прохода всего предшествующего префикса. Решение о кодировке повторно используется только если оно подтверждено у начала источника; запрошенный исходный байтовый якорь сохраняется. Номера логических строк и их общее количество остаются неизвестными, пока не подтверждены; локальный EOF не доказывает число строк во всём документе. На известном EOF или за ним непустой источник показывает доступную последнюю строку или фрагмент, сохраняя запрошенное смещение на EOF либо на байт после него; завершающий перевод строки не добавляет ещё одну строку отображения, а пустые строки, присутствующие в источнике, сохраняются. Пустой источник остаётся пустым. Пустой ответ в произвольной удалённой позиции сам по себе не доказывает EOF. Во время подготовки остаётся последнее готовое окно. Если источник вернул пустой ответ без окончательного EOF, контрол переходит в ожидание; после появления данных вызовите `reload()` или нажмите F5. Автоматического опроса файла здесь нет; для следования за дописываемым журналом используйте [файловый LogView](log-view.md#log-view-file-ru).

## Быстрое прокручивание и страницы {#document-view-fast-navigation-ru}

`.fastScroll()` включает дополнительный шаг в восемь строк: Ctrl вместе с Up/Down или Alt вместе с колесом. Обычные стрелки и колесо сохраняют шаг по умолчанию в одну строку. Быстрый шаг задаётся абсолютным числом визуальных строк: `.scrollStep(3).fastScroll(8)` означает три и восемь строк, а не умножение. Второй и третий аргументы `fastScroll` типа `key::Modifier` меняют модификаторы клавиатуры и колеса. Дополнительные модификаторы не совпадают с выбранным сочетанием.

PageUp/PageDown перемещают на полезную высоту viewport минус `.pageOverlap(rows)`, но не менее одной строки. По умолчанию перекрытие — одна строка. Полезная высота не включает рамку и footer. Команда страницы использует arranged-геометрию в момент принятия; resize не переосмысливает уже принятое движение. Быстрый шаг не меняет размер страницы.

@image html document-view-navigation.gif "Обычное колесо, быстрый шаг в восемь строк, страницы с перекрытием в две строки и последний полный экран. Подпись описывает приблизительный ввод событий."

[Полная программа навигации](../../examples/document_view/navigation.cpp), target `portals_document_navigation_example`:

\include document_view/navigation.cpp

После нажатия кнопки щёлкните внутри документа, чтобы вернуть ему фокус клавиатуры. Кнопки и встроенный ввод используют один путь принятия команд, без чтения источника в UI-потоке. Относительные перемещения накапливаются во время подготовки; противоположные могут компенсироваться, а Home/End заменяют относительную цель. Правила смены источника и отмены сохраняются.

Ненулевая программная команда страницы до расчёта пригодной области просмотра возвращает `WOULD_BLOCK`: checked-вариант возвращает ошибку, краткий вариант передаёт её общему обработчику ошибок. Встроенный ввод PageUp/PageDown при нулевой ширине или высоте рассчитанной области поглощается без движения. Нулевые команды строк/страниц проверяют ссылку и поток, затем завершаются без движения и redraw. Переполнение отвергается до изменения очереди. Ввод учитывает disabled и read-only настройки навигации; программные команды сохраняют правила `seekByte` и могут перемещать представление независимо от этих ограничений ввода.

Терминал может перехватить сочетание: [Windows Terminal использует Ctrl+колесо для масштаба шрифта](https://learn.microsoft.com/en-us/windows/terminal/tips-and-tricks). Поэтому для быстрого колеса по умолчанию выбран отдельный Alt. Portals не может обработать событие, которое host не передал приложению. Те же Ref-команды доступны кнопкам и пользовательским `ui::onKey`.

## Шестнадцатеричный просмотр {#document-view-hex-ru}

`.hex()` показывает исходные байты в том же контроле. Строка содержит байтовое смещение в шестнадцатеричном виде, группы байтов и безопасную символьную колонку. В ней видны печатные ASCII-символы, остальные байты заменяются точками. Эта колонка не декодирует UTF-текст и не исполняет управляющие последовательности. Настройки текстовой кодировки и номеров строк сохраняются для возврата в текстовый режим.

@image html document-view-hex.gif "Переключение UTF-16LE-документа между байтами и текстом, колесо мыши, быстрый шаг и End."

[Полная программа TEXT/HEX](../../examples/document_hex/main.cpp), target `portals_document_hex_example`:

\include document_hex/main.cpp

F2 выбирает текст, F3 — шестнадцатеричный вид. Источник и запрошенная байтовая позиция остаются общими. Нижняя строка по-прежнему сравнивает последний видимый байт с размером источника: при смене представления процент может измениться без перемещения запрошенного якоря. Успешная смена режима отменяет ещё не выполненные перемещения старого представления: текстовые строки не становятся строками HEX. Повторное назначение того же режима сохраняет ожидающее движение. Отклонённое изменение сохраняет прежний режим, позицию, подготовленный кадр, ожидающие перемещения и палитру.

По умолчанию строка содержит 16 байтов, группы по восемь, заглавные цифры и символьную колонку. При фиксированном размере узкое окно не уменьшает число байтов строки: оставшиеся колонки доступны горизонтальной прокруткой. `.hex({.bytesPerRow = 32, .autoFit = true})` разрешает уменьшить число байтов под доступную ширину. Изменение ширины окна или параметров строки не переписывает запрошенный байтовый якорь. Пустой файл и неполная последняя строка не дополняются вымышленными байтами.

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `bytesPerRow` | Максимум байтов строки, 1–4096 | 16 |
| `groupSize` | Байтов в группе, 1–4096; группа длиннее строки не добавляет внутренних промежутков | 8 |
| `uppercase` | Заглавные шестнадцатеричные цифры | `true` |
| `showAscii` | Безопасная символьная колонка | `true` |
| `autoFit` | Уменьшать фактическое число байтов под ширину, не превышая `bytesPerRow` | `false` |

Это ограничения строки и подготовки, а не размера файла. Дополнительно действуют прежние лимиты кадра, работы и памяти источника. Файловый источник поддерживает произвольную байтовую позицию; источник только с последовательным чтением не может обещать возврат или смену режима, для которых уже утратил нужные байты. Неподдерживаемая операция возвращает типизированную ошибку. Неизвестный размер остаётся неизвестным: контрол не сканирует весь источник ради процента или количества строк.

В режиме TEXT изменение HEX-параметров только сохраняет их для будущего переключения в HEX. Оно не читает источник, не подготавливает новый текстовый кадр и не отменяет ожидающее текстовое перемещение.

Для источника только с последовательным чтением задавайте начальный режим, `bytesPerRow` и `autoFit` в описании до монтирования. Когда источник уже подключён, смена режима, а также изменение этих параметров при активном HEX пока возвращают типизированную ошибку неподдерживаемой операции, даже если нужные байты остаются в кеше. Это ограничение реализации. Группировку, регистр цифр и видимость символьной колонки можно менять по сохранённым строкам. Изменение ширины и высоты окна при фиксированной сетке поддерживается. У файловых и других позиционируемых источников доступны смена режима и все параметры строки.

| Команда | Со сбором ошибок | Checked-вариант |
|---|---|---|
| Выбрать представление | `document.mode(DocumentViewMode::HEX)` | `document.setMode(DocumentViewMode::HEX)` |
| Изменить параметры строки | `document.hexOptions(options)` | `document.setHexOptions(options)` |

Для возврата используйте `DocumentViewMode::TEXT`. `DocumentViewStatus::mode` сообщает выбранное представление; строки HEX не выдаются за логические строки текста.

В загружаемой сцене задайте `mode="text"` или `mode="hex"` и при необходимости блок `hex` с теми же пятью именами параметров. Отсутствующее свойство сохраняет значение по умолчанию; явно заданное `false` учитывается.

## Источники и команды {#document-view-sources-ru}

Файл — один из вариантов источника. `ui::document(provider, budget)` принимает worker-safe `ByteDocumentProvider`, а `ui::document(sharedText)` показывает существующее неизменяемое хранилище без полной копии. Пользовательский provider объявляет возможности поиска позиции и неизменяемости; размер может быть неизвестен. Принятые чтения должны относиться к точной ревизии. Замена источника сбрасывает несовместимые подготовленные данные; отменённая или устаревшая работа не может подменить активную модель.

| Операция | С автоматическим сбором ошибок | Checked-вариант |
|---|---|---|
| Визуальные строки | `reader.scroll(rows)` | `reader.scrollRows(rows)` |
| Страницы | `reader.page(pages)` | `reader.scrollPages(pages)` |
| Начало / последний полный экран | `reader.home()` / `reader.end()` | `reader.goHome()` / `reader.goEnd()` |
| Заменить источник | `reader.model(source)` | `reader.setModel(source)` |
| Запросить исходную байтовую позицию | `reader.byte(offset)` | `reader.seekByte(offset)` |
| Обновить данные у текущего якоря | `reader.reload()` | `reader.refresh()` |
| Показать или скрыть номера строк | `reader.lineNumbers(enabled)` | `reader.setLineNumbers(enabled)` |
| Переключить номера строк | `reader.toggleLineNumbers()` | — |
| Прочитать сохранённый статус без I/O | `reader.currentStatus()` | `reader.status()` |

Краткие команды передают ошибки в существующий коллектор сцены. Checked-команды возвращают `std::expected`, оставляя обработку вызывающему коду. Принятие команды не означает, что данные уже показаны: подготовка может продолжаться. Вызывайте команды в UI-потоке владельца, например из обработчика кнопки или клавиши. `runApp` управляет фоновой службой и восстановлением терминала.

Первая версия доступна только для чтения. Выделение текста, экспорт в clipboard, редактирование, поиск и автоматическое семантическое перебазирование при произвольной внешней перезаписи в неё не входят.

## Сжатые gzip-документы {#document-view-gzip-ru}

При сборке Portals включите `PORTALS_ENABLE_GZIP=ON` и подключите опциональную
цель `portals::gzip`. Заголовок `<portals/ui_gzip.hpp>` добавляет короткую запись
`ui::viewer(ui::gzipFile("archive.sql.gz"))`. Обычная сборка ядра не получает
зависимость от gzip. Исходники распаковщика входят в поставку для сборки без
сети; потребителю установленного пакета не нужна отдельная установка zlib.

```cmake
find_package(Portals CONFIG REQUIRED COMPONENTS gzip)
target_link_libraries(my_viewer PRIVATE portals::gzip)
```

Соберите `portals_document_gzip_example` с `PORTALS_BUILD_EXAMPLES=ON` и запустите
из каталога исполняемого файла. Сборка помещает рядом одинаковые SQL-данные в
обычном и gzip-файле. F2 выбирает исходный файл, F3 — архив; каждый сохранённый
дескриптор запоминает свою позицию чтения. Home и End перемещают по выбранному
логическому документу. F10 закрывает приложение.

[Полный исходник](../../examples/document_view/gzip.cpp)

\include document_view/gzip.cpp

@image html document-view-gzip.gif "Чтение обычного и gzip SQL, возврат к позиции каждого источника и последняя полная страница."

Фабрика сохраняет путь и создаёт холодный дескриптор. Открытие, проверка gzip,
распаковка и переходы выполняются существующей фоновой службой приложения.
Выбор gzip явный: адаптер проверяет содержимое и не определяет формат только
по расширению имени. `ui::gzip(provider)` принимает существующий провайдер
байтов с произвольным доступом; работа с файлами — один из вариантов источника.

Во вьюхе отображаются распакованные байты. Точный логический размер неизвестен,
пока не проверены все входящие gzip-потоки и физический конец источника, поэтому внизу
может быть `progress unknown`. 32-битное поле ISIZE не используется как общий
размер. Последовательность gzip-потоков образует один документ. Ошибки CRC,
оборванный поток и посторонние данные в конце сообщаются как ошибка источника,
а не успешный EOF. При ошибке целостности тело заменяется сообщением об ошибке. Ранее
подготовленные данные сохраняются для восстановления; этот префикс не означает,
что весь архив прошёл проверку.

В памяти хранится ограниченное число контрольных точек распаковщика, включая
словарь и битовое состояние. При переходе назад может понадобиться повторная
распаковка с более ранней точки или начала после вытеснения кеша. Холодный End
может суммарно распаковать весь архив. Сначала провайдер определяет логический
размер без разметки промежуточного текста, затем Viewer готовит ограниченный
суффикс для последней полной страницы. При определении размера проверяется
весь gzip-поток, а распакованные данные отбрасываются; сохраняются только
ограниченные буферы и контрольные точки. Это всё ещё может занять значительное
время и занять рабочий поток. Отмена проверяется
между ограниченными порциями входа и выхода; блокирующее чтение нижележащего
провайдера подчиняется его собственному контракту отмены. `DocumentViewConfig.workBytes`
не ограничивает скрытую работу по повторной распаковке.

`GzipDocumentOptions` задаёт размеры входных и выходных буферов, шаг и число
контрольных точек, размер буфера повторного чтения, лимит памяти распаковщиков
и лимит байтов заголовка. Распаковщики и контрольные точки используют общий
корневой `SourceBudget` вместе с окном Viewer. Временных файлов и постоянного
дискового кеша нет. Для нескольких вьюх используйте один gzip-адаптер; не
обращайтесь к нижележащему провайдеру одновременно через независимые обёртки
или других владельцев. Изменение сжатого источника нарушает закреплённую
ревизию и сообщается как `REVISION_CHANGED`.

Настройки по умолчанию в `GzipDocumentOptions`:

| Поле | По умолчанию | Назначение |
|---|---|---|
| `compressedBlockBytes` | 64 КиБ | Порция сжатого ввода; допустимо 1–64 КиБ. |
| `inflateOutputBytes` | 32 КиБ | Максимум выхода одного вызова распаковки перед проверкой отмены. |
| `checkpointStrideBytes` | 4 МиБ | Логический интервал между необязательными контрольными точками. |
| `maxCheckpoints` | 8 | Число хранимых точек; 0 отключает их, максимум 64. |
| `replayBytes` | 64 КиБ | Кольцевой буфер распакованных байтов; 0 отключает его. |
| `maxInflateBytes` | 512 КиБ | Общий лимит памяти живых распаковщиков, включая копии состояния. |
| `maxHeaderBytes` | 1 МиБ | Лимит сжатых байтов заголовка каждого gzip-потока. |

Лимиты числа и памяти действуют одновременно: фактических точек может быть меньше.
При нехватке памяти освобождаются простаивающее состояние распаковщика и точки;
следующее чтение вне кеша повторяет распаковку с доступной начальной позиции.

## Кодировки и свойства ресурса {#document-view-settings-ru}

Подсказка UTF-8 по умолчанию применяется после явно выбранной кодировки или распознанного BOM. Доступны UTF-8, UTF-16LE/BE, UTF-32LE/BE, Windows-1251 и Windows-1252. Пример выбора — `.encoding(DocumentEncoding::UTF16LE)`. `.wrap(false)` включает горизонтальное окно, `.lineNumbers()` — нумерацию. Изменение этих настроек сохраняет исходный байтовый якорь.

По умолчанию повреждённый ввод декодируется с заменой. Низкоуровневый `DocumentViewConfig::decoder` поддерживает строгую проверку с typed-ошибкой подготовки. Локальный переход или быстрый переход к EOF проверяет выбранную декодируемую область, включая начало источника для определения кодировки; пропущенный префикс этим не проверяется. Терминальные управляющие символы показываются видимыми escape-последовательностями. Обычные многоскалярные графемные кластеры сохраняются и при переходе через границы страниц. При локальном перезапуске используется до 4 КиБ контекста графем, отдельно от упреждающего чтения декодера. Слишком большой кластер или непроверяемый в ограниченном контексте кластер (например, цепочка региональных индикаторов длиннее 4 КиБ) отображается как продолжение с видимым кружком и устанавливает `fragmentedCluster`. Для начальной цепочки региональных индикаторов чётность остаётся неподтверждённой до символа, который сбрасывает это состояние; это относится и к повторному переходу рядом с кешированной позицией. Ограничение локального отображения не ограничивает длину логической строки.

Нативный тип ресурса — `DocumentView`. В CONFIGURATION его свойства: `file` — буквальный UTF-8-путь, `lineNumbers`, `wrap`, `encoding`, `language`, `syntax`, положительный `maxAutoHighlightBytes`, `fastScroll`, `fastKeyModifier` и `fastWheelModifier`. Положительный `fastScroll` включает абсолютный быстрый шаг; имена модификаторов `CTRL`, `ALT`, `SHIFT` не зависят от регистра. Существующие `keyStep` и `wheelStep` вместе соответствуют сокращению `scrollStep`, а `pageOverlap` задаёт перекрытие страниц. Общие размеры, рамка и полосы прокрутки имеют ту же семантику, что C++-модификаторы. Viewer-свойства не принимаются посторонними контролами.

## Стилизация {#document-view-styling-reference-ru}

Селектор типа — `DocumentView`. Текст, фон и нижняя строка используют обычное, `:focused` или `:disabled` оформление. Встроенные темы сохраняют поверхность документа при фокусе и выделяют его обрамление; явное правило `DocumentView:focused` может изменить поверхность. `foreground`, `background`, `bold`, `italic` и `underline` работают через обычный [каскад стилей](styling-guide.md).

Шаблоны рамки, оформление заголовка, стрелки, направляющие и отдельные части ползунка описаны в [справочнике рамок и прокрутки](scroll-controls.md#scrollbar-styling-reference-ru). `.framed("rounded", "Document")` задаёт заголовок; одноаргументный `.framed("rounded")` выбирает шаблон, как у остальных контролов.

DocumentView регистрирует три базовые семантические части оформления: `body` для текста
документа, `gutter` для номеров строк и `position` для нижней строки. Поле
`gutter` отображается при включённом `.lineNumbers()`. Для каждой части доступны
пять свойств PSS: `role-<part>-foreground`, `role-<part>-background`,
`role-<part>-bold`, `role-<part>-italic` и `role-<part>-underline`. Значения и
правила каскада приведены в [справочнике свойств стилей](styles.md#styles-semantic-role-properties-ru).
Эти части используют существующий каскад темы и прикладных/пользовательских
слоёв. Пример перед своим слоем ролей устанавливает `nordTheme()`, поэтому
незаданные фоны наследуются от её тёмной поверхности. Для каждого состояния
незаданные свойства наследуют разрешённое оформление `DocumentView`. Изменение
оформления обновляет отображение без повторной загрузки источника документа.


| Часть | Текст | Фон | Жирность | Курсив | Подчёркивание |
| --- | --- | --- | --- | --- | --- |
| `body` | `role-body-foreground` | `role-body-background` | `role-body-bold` | `role-body-italic` | `role-body-underline` |
| `gutter` | `role-gutter-foreground` | `role-gutter-background` | `role-gutter-bold` | `role-gutter-italic` | `role-gutter-underline` |
| `position` | `role-position-foreground` | `role-position-background` | `role-position-bold` | `role-position-italic` | `role-position-underline` |
| `hex-zero` | `role-hex-zero-foreground` | `role-hex-zero-background` | `role-hex-zero-bold` | `role-hex-zero-italic` | `role-hex-zero-underline` |
| `hex-printable` | `role-hex-printable-foreground` | `role-hex-printable-background` | `role-hex-printable-bold` | `role-hex-printable-italic` | `role-hex-printable-underline` |
| `hex-control` | `role-hex-control-foreground` | `role-hex-control-background` | `role-hex-control-bold` | `role-hex-control-italic` | `role-hex-control-underline` |
| `hex-high-byte` | `role-hex-high-byte-foreground` | `role-hex-high-byte-background` | `role-hex-high-byte-bold` | `role-hex-high-byte-italic` | `role-hex-high-byte-underline` |

В HEX добавляются роли `hex-zero` (нулевые байты), `hex-printable` (печатные ASCII и пробел), `hex-control` (остальные ASCII-коды) и `hex-high-byte` (байты от 0x80). Для смещений действует `gutter`, для разделителей и пустых позиций — `body`. HEX-роли регистрируются только для этого режима; цвета задаются тем же каскадом PSS и темы.


Запускайте пример из каталога исходников Portals, где доступен `README.md`. F2 показывает или скрывает поле номеров во время чтения. Источник и якорь чтения сохраняются, включая уже принятую прокрутку во время загрузки. Повторное назначение прежнего значения не запускает новую загрузку или перерисовку.

## Ограничения ресурсов {#document-view-limits-ru}

Лимиты ограничивают хранимую ёмкость и работу, а не размер документа. Стандартный корневой бюджет источника — 8 МиБ; приложение может настроить и совместно использовать `SourceBudget`. По умолчанию `DocumentViewConfig` допускает 16 384 реальные ячейки окна, 64 КиБ подготовленного содержимого и 256 КиБ исходных байтов на один фоновый шаг. Размер страницы источника по умолчанию — 64 КиБ. Слишком большое для настроенного лимита окно получает `PAGE_TOO_LARGE`, а не молчаливое усечение.

Удерживаемые страницы, неизменяемые снимки сканера, готовый вывод и отменённая работа сохраняют свои кредиты до завершения реального владельца. Доменное хранилище пользовательского provider не входит в SDK-учёт сохранённых страниц. Память процесса, кредиты источника, задержка холодного перехода и физическое появление кадра в терминале — разные измерения.

Контрол хранит до 16 позиций источников в пределах текущего запуска. Для дополнительных источников слоты используются по кругу; источник без сохранённой позиции открывается с байта ноль. Между запусками эти позиции не сохраняются.

## Поиск в большом документе и экспорт {#document-view-search-ru}

В примере с полем пути и CLI тоже есть строка поиска: откройте свой файл и
используйте F6 или Shift+F6 для перехода по совпадениям. Прежняя клавиша F3
по-прежнему включает hex-режим. Небольшая программа ниже использует готовый файл.

Соберите `portals_document_search_example` и запустите из каталога исполняемого
файла: сборка копирует туда `archive.sql`. Строка поиска может предшествовать
Viewer в сцене. Измените запрос или используйте Previous/Next, F3 и Shift+F3.
F4 показывает те же найденные байты в hex-режиме, F5 возвращает текст.

[Полный исходник](../../examples/document_view/search.cpp)

\include document_view/search.cpp

@image html document-view-search.gif "Поиск литерала, Next/Previous, те же найденные байты в HEX и экспорт копии."

`ui::findBar(search, reader, "INSERT")` ищет в текущем логическом источнике
Viewer на рабочих потоках. Контрол хранит одно выбранное совпадение и
ограниченные буферы запроса и декодирования, без загрузки документа или списка
всех результатов. Поиск учитывает регистр, допускает пересечения и требует
целых графем источника. Нормализации Unicode нет. Запрос записывается в UTF-8,
а диапазон результата относится к байтам исходной кодировки.
`FindMatch::sourceByteOffset()` и `sourceByteLength()` возвращают этот диапазон;
`begin()` и `end()` относятся к ограниченному UTF-8-контексту результата.
`storedCount()` — число сохранённых результатов, а не всех совпадений в файле.

Пока идёт поиск, новый Next/Previous отклоняется с `WOULD_BLOCK`; можно
редактировать запрос и независимо перемещаться по документу.

Next продолжает потоковый проход. Previous может повторно прочитать необходимый
префикс, сохраняя только последнее подходящее совпадение; далеко от начала он
может работать дольше. В обоих направлениях есть переход через границу файла.
UI остаётся доступным, изменение запроса отменяет устаревшую работу. Замена
источника или кодировки снимает прежнее выделение, сохраняя запрос и позицию
чтения. Для поиска в новом источнике измените запрос или нажмите Next/Previous.
Ручная навигация во время поиска запрещает позднему результату менять позицию.

Выделение в текстовом и hex-режимах использует опциональную роль `match`:

```css
DocumentView {
  role-match-foreground: #202630;
  role-match-background: #ebcb8b;
  role-match-bold: true;
}
```

Темы задают контрастные цвета совпадения, в том числе при отключённом контроле.
Поддерживаются обычные foreground/background/bold/italic/underline. Неиспользуемое
расширение поиска не добавляет стилевой payload каждому контролу.

`ui::exportFile(reader, output, completed)` запускает фоновый экспорт текущего
источника Viewer. `ui::startExport` возвращает проверяемый результат допуска.
Существующий выходной файл не перезаписывается, в том числе сам исходник.
Завершение приходит на UI с `DocumentExportResult`: фактически принятые байты
и ошибка источника или записи. Ошибки выполнения также попадают в обработку
ошибок сцены. Для одного Viewer одновременно допускается один экспорт.
Замена модели не перенаправляет уже принятый экспорт; удаление Viewer или
закрытие сцены запрашивает отмену. Частичный файл остаётся после ошибки или
отмены. Завершение не обещает физического сохранения на носитель или отката.

Для фоновых интеграций `copyDocumentBytes(source, range, maxBytes)` возвращает
владеющую копию исходных байтов; предел по умолчанию — 64 КиБ. Превышение
отклоняется до чтения содержимого; при неизвестном размере нужен явный конец
диапазона. `exportDocument` передаёт порции фиксированного размера в
`DocumentExportSink`. Обе операции используют бюджет источника и сохраняют
исходную кодировку текста; для gzip результатом служат распакованные байты.
Буфер обмена ОС не изменяется. Пользовательский sink сам определяет хранение
данных и задержку блокирующей операции или отмены.
