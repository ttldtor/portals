# DocumentView {#document-view-ru}

[English version](../document-view.md) · [LogView](log-view.md) · [Контролы прокрутки](scroll-controls.md)

`DocumentView` читает текстовый документ ограниченными окнами, не загружая целиком файл или логическую строку. Чтение и декодирование выполняются фоновым исполнителем приложения. UI рисует последнее неизменяемое подготовленное окно и продолжает обрабатывать ввод, пока готовится следующее.

@image html document-view.gif "Прокрутка документа, переключение источников и возврат к сохранённой позиции."

## Полная программа {#document-view-example-ru}

Соберите `portals_document_view_example` с `PORTALS_BUILD_EXAMPLES=ON` и запустите из каталога исходников Portals, где находятся `README.md` и `ReleaseNotes.md`. Кнопки переключают тот же контрол между файлами, обновляют текущий источник и возвращают к началу. При возврате к сохранённому дескриптору источника восстанавливается его байтовая позиция. F10 или Ctrl+C завершают приложение через стандартный runner.

[Полный исходник](../../examples/document_view/main.cpp)

\include document_view/main.cpp

Кратчайший файловый вариант — `ui::viewer("README.md")`. Сохраните `ui::Ref<DocumentView>`, если обработчикам нужно менять источник или позицию чтения. `ui::documentFile(path)` владеет UTF-8-путём; создание рецепта не открывает файл. Для возврата к сохранённой позиции используйте тот же дескриптор.

## Чтение и навигация {#document-view-navigation-ru}

| Ввод | Результат |
|---|---|
| Up / Down, колесо мыши | Переход по визуальным строкам. |
| PageUp / PageDown | Переход на размер окна с настроенным перекрытием. |
| Home | Запрос байтовой позиции ноль. |
| End | Запрос последней полной страницы; подготовка может продолжаться, пока источник читается. |
| Left / Right при отключённом переносе | Сдвиг горизонтального окна ячеек. |
| Вертикальная полоса прокрутки | Запрос байтовой позиции при известном точном размере источника. |
| F5 | Обновление текущего источника. |

По умолчанию один нормализованный шаг колеса перемещает текст на одну экранную строку. Быстрый ввод накапливается, пока загружается окно. Ожидающие движения в противоположных направлениях могут компенсировать друг друга; попытка выйти за подтверждённую границу не создаёт долг для следующего движения. Home, End, переход ползунком и замена источника задают новую цель навигации. Другой шаг можно передать низкоуровневому конструктору через `ScrollAreaOptions::wheelStep`.

Положение ползунка — приблизительная проекция видимого окна на известный размер в байтах; это не значение покрытия в нижней строке. При известном размере промежуточные позиции ползунка отображаются на диапазон от нуля до `extent - visibleSpan`. Крайняя позиция сохраняет явный исходный байтовый якорь `extent` (`tail=false`), поэтому перетаскивание в конец или вызов `seekByte(extent)` может показать последнюю строку сверху, а не последнюю полную страницу. `End` запрашивает последнюю полную страницу. Такие явные переходы по байтам используют ограниченный локальный поиск и не сканируют весь предшествующий файл.

Нижняя строка показывает приблизительное покрытие исходных байтов до нижнего края видимого содержимого. Уже на первом экране процент может быть больше нуля. Значение `100.0%` появляется только когда виден последний исходный байт; упреждающее чтение декодера и размер декодированного UTF-8 не считаются видимым покрытием. Если длинная строка без переноса обрезана справа, значение не станет 100%, пока не виден последний байт источника. При неизвестном размере показывается `progress unknown`, пока видимый последний байт не подтвердит конец; временное ожидание provider не означает EOF. Завершающий перевод строки не добавляет пустую строку отображения, но реальные пустые строки документа остаются видимыми. Исходный байтовый якорь и подтверждённый логический номер строки остаются доступны через `reader.status()`. Нумерация опциональна, по умолчанию выключена и использует только подтверждённые проходом номера. Перенесённые фрагменты сохраняют номер логической строки. Девятиячеечное поле показывает до семи цифр: `?` означает неподтверждённый номер строки, а `+` — подтверждённый номер больше отображаемого диапазона; этот предел отображения не ограничивает 64-битные байтовые смещения.

Доступный для позиционирования источник позволяет подготовить холодный переход далеко по документу из ограниченного локального окна, без прохода всего предшествующего префикса. Решение о кодировке повторно используется только если оно подтверждено у начала источника; запрошенный исходный байтовый якорь сохраняется. Номера логических строк и их общее количество остаются неизвестными, пока не подтверждены; локальный EOF не доказывает число строк во всём документе. На известном EOF или за ним непустой источник показывает доступную последнюю строку или фрагмент, сохраняя запрошенное смещение на EOF либо на байт после него; завершающий перевод строки не добавляет ещё одну строку отображения, а пустые строки, присутствующие в источнике, сохраняются. Пустой источник остаётся пустым. Пустой ответ в произвольной удалённой позиции сам по себе не доказывает EOF. Во время подготовки остаётся последнее готовое окно. Если источник вернул пустой ответ без окончательного EOF, контрол переходит в ожидание; после появления данных вызовите `reload()` или нажмите F5. Автоматического опроса файла здесь нет; для следования за дописываемым журналом используйте [файловый LogView](log-view.md#log-view-file-ru).

## Источники и команды {#document-view-sources-ru}

Файл — один из вариантов источника. `ui::document(provider, budget)` принимает worker-safe `ByteDocumentProvider`, а `ui::document(sharedText)` показывает существующее неизменяемое хранилище без полной копии. Пользовательский provider объявляет возможности поиска позиции и неизменяемости; размер может быть неизвестен. Принятые чтения должны относиться к точной ревизии. Замена источника сбрасывает несовместимые подготовленные данные; отменённая или устаревшая работа не может подменить активную модель.

| Операция | С автоматическим сбором ошибок | Checked-вариант |
|---|---|---|
| Заменить источник | `reader.model(source)` | `reader.setModel(source)` |
| Запросить исходную байтовую позицию | `reader.byte(offset)` | `reader.seekByte(offset)` |
| Обновить данные у текущего якоря | `reader.reload()` | `reader.refresh()` |
| Показать или скрыть номера строк | `reader.lineNumbers(enabled)` | `reader.setLineNumbers(enabled)` |
| Переключить номера строк | `reader.toggleLineNumbers()` | — |
| Прочитать сохранённый статус без I/O | `reader.currentStatus()` | `reader.status()` |

Краткие команды передают ошибки в существующий коллектор сцены. Checked-команды возвращают `std::expected`, оставляя обработку вызывающему коду. Принятие команды не означает, что данные уже показаны: подготовка может продолжаться. Вызывайте команды в UI-потоке владельца, например из обработчика кнопки или клавиши. `runApp` управляет фоновой службой и восстановлением терминала.

Первая версия доступна только для чтения. Выделение текста, экспорт в clipboard, редактирование, поиск и автоматическое семантическое перебазирование при произвольной внешней перезаписи в неё не входят.

## Кодировки и свойства ресурса {#document-view-settings-ru}

Подсказка UTF-8 по умолчанию применяется после явно выбранной кодировки или распознанного BOM. Доступны UTF-8, UTF-16LE/BE, UTF-32LE/BE, Windows-1251 и Windows-1252. Пример выбора — `.encoding(DocumentEncoding::UTF16LE)`. `.wrap(false)` включает горизонтальное окно, `.lineNumbers()` — нумерацию. Изменение этих настроек сохраняет исходный байтовый якорь.

По умолчанию повреждённый ввод декодируется с заменой. Низкоуровневый `DocumentViewConfig::decoder` поддерживает строгую проверку с typed-ошибкой подготовки. Терминальные управляющие символы показываются видимыми escape-последовательностями. Обычные многоскалярные графемные кластеры сохраняются и при переходе через границы страниц. При локальном перезапуске используется до 4 КиБ контекста графем, отдельно от упреждающего чтения декодера. Слишком большой кластер или непроверяемый в ограниченном контексте кластер (например, цепочка региональных индикаторов длиннее 4 КиБ) отображается как продолжение с видимым кружком и устанавливает `fragmentedCluster`. Для начальной цепочки региональных индикаторов чётность остаётся неподтверждённой до символа, который сбрасывает это состояние; это относится и к повторному переходу рядом с кешированной позицией. Ограничение локального отображения не ограничивает длину логической строки.

Нативный тип ресурса — `DocumentView`. В CONFIGURATION его свойства: `file` — буквальный UTF-8-путь, `lineNumbers`, `wrap` и `encoding`. Общие размеры, рамка и полосы прокрутки имеют ту же семантику, что C++-модификаторы. Viewer-свойства не принимаются посторонними контролами.

## Стилизация {#document-view-styling-reference-ru}

Селектор типа — `DocumentView`. Текст, фон и нижняя строка используют обычное, `:focused` или `:disabled` оформление. Встроенные темы сохраняют поверхность документа при фокусе и выделяют его обрамление; явное правило `DocumentView:focused` может изменить поверхность. `foreground`, `background`, `bold`, `italic` и `underline` работают через обычный [каскад стилей](styling-guide.md).

Шаблоны рамки, оформление заголовка, стрелки, направляющие и отдельные части ползунка описаны в [справочнике рамок и прокрутки](scroll-controls.md#scrollbar-styling-reference-ru). `.framed("rounded", "Document")` задаёт заголовок; одноаргументный `.framed("rounded")` выбирает шаблон, как у остальных контролов.

DocumentView регистрирует три семантические части оформления: `body` для текста
документа, `gutter` для номеров строк и `position` для нижней строки. Поле
`gutter` отображается при включённом `.lineNumbers()`. Для каждой части доступны
пять свойств PSS: `role-<part>-foreground`, `role-<part>-background`,
`role-<part>-bold`, `role-<part>-italic` и `role-<part>-underline`. Значения и
правила каскада приведены в [справочнике свойств стилей](styles.md#styles-semantic-role-properties-ru).
Эти части используют существующий каскад темы и прикладных/пользовательских
слоёв. Пример перед своим слоем ролей устанавливает `nordTheme()`, поэтому
незаданные фоны наследуются от её тёмной поверхности. Для каждого состояния
незаданные свойства наследуют разрешённое оформление `DocumentView`. Изменение
оформления обновляет отображение без повторной загрузки источника документа.


| Часть | Текст | Фон | Жирность | Курсив | Подчёркивание |
| --- | --- | --- | --- | --- | --- |
| `body` | `role-body-foreground` | `role-body-background` | `role-body-bold` | `role-body-italic` | `role-body-underline` |
| `gutter` | `role-gutter-foreground` | `role-gutter-background` | `role-gutter-bold` | `role-gutter-italic` | `role-gutter-underline` |
| `position` | `role-position-foreground` | `role-position-background` | `role-position-bold` | `role-position-italic` | `role-position-underline` |

Запускайте пример из каталога исходников Portals, где доступен `README.md`. F2 показывает или скрывает поле номеров во время чтения. Источник и якорь чтения сохраняются, включая уже принятую прокрутку во время загрузки. Повторное назначение прежнего значения не запускает новую загрузку или перерисовку.

## Ограничения ресурсов {#document-view-limits-ru}

Лимиты ограничивают хранимую ёмкость и работу, а не размер документа. Стандартный корневой бюджет источника — 8 МиБ; приложение может настроить и совместно использовать `SourceBudget`. По умолчанию `DocumentViewConfig` допускает 16 384 реальные ячейки окна, 64 КиБ подготовленного содержимого и 256 КиБ исходных байтов на один фоновый шаг. Размер страницы источника по умолчанию — 64 КиБ. Слишком большое для настроенного лимита окно получает `PAGE_TOO_LARGE`, а не молчаливое усечение.

Удерживаемые страницы, неизменяемые снимки сканера, готовый вывод и отменённая работа сохраняют свои кредиты до завершения реального владельца. Доменное хранилище пользовательского provider не входит в SDK-учёт сохранённых страниц. Память процесса, кредиты источника, задержка холодного перехода и физическое появление кадра в терминале — разные измерения.

Контрол хранит до 16 позиций источников в пределах текущего запуска. Для дополнительных источников слоты используются по кругу; источник без сохранённой позиции открывается с байта ноль. Между запусками эти позиции не сохраняются.
