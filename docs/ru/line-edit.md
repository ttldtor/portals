# Однострочный редактор Unicode {#line-edit-ru}

[Подробная английская версия](../line-edit.md)

Создайте поле через [`ui::lineEdit`](../../include/portals/ui.hpp), чтобы ввод, модель и история подключились автоматически. В этом приложении F2 копирует текущий черновик в надпись и добавляет `!`; Enter подтверждает поле, Escape восстанавливает модель. F10 закрывает приложение.

```cpp
#include <portals/ui.hpp>

int main() {
  using namespace portals;

  ui::Ref<LineEdit> name;
  ui::Ref<Label> greeting;

  auto scene = ui::scene(
    ui::vbox(ui::lineEdit(name,
               "Ada",
               {.options = {.editMode = EditMode::EXPLICIT}}),
      ui::label(greeting, "Press F2 to read the draft")));

  return scene
    | ui::onKey("F2",
                [name, greeting] {
                  greeting.text() = name.text() + "!";
                })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Пример читает черновик через `name.text()`, поэтому F2 видит и ещё не подтверждённый текст. Для нескольких полей с общей моделью передайте им один `ManagedScene::state(...)`; см. [декларативный интерфейс](declarative-ui.md).

[Сборка самостоятельных примеров](examples.md).

## Подсказка, защищённое отображение и Clear

При создании поля задайте `LineEditOptions::displayMode` и необязательную владеющую
строку `placeholder`. Полная native-форма ниже использует внутреннюю модель и обычный
runner для сообщения ошибок подготовки и выполнения. Кнопка возвращает полный проверенный
результат Clear. F10 завершает приложение с восстановлением терминала; Ctrl+Z восстанавливает
очищенное значение, пока история включена.

```cpp
#include <portals/ui.hpp>

int main() {
  using namespace portals;

  ui::Ref<LineEdit> password;

  return ui::scene(ui::vbox(
    ui::lineEdit(password, "", {
      .options = {
        .displayMode = LineEditDisplayMode::PASSWORD,
        .placeholder = "Password"}}),
    ui::button("Clear", [password] {
      return password.clear();
    })))
    | ui::onKey(key::F10, ui::quit)
    | ui::runApp();
}
```

[Сборка через установленный пакет](package.md).
Эта же форма компилируется как потребитель установленного SDK. По умолчанию сервис буфера
обмена не подключён; приложение может передать его через `LineEditConfig::clipboard`.

| Режим отображения | Значение, выделение и курсор | Собственная ширина | Ctrl+C / Ctrl+X |
| --- | --- | --- | --- |
| `NORMAL` (по умолчанию) | Исходные графемы, обычное выделение и прокрутка | Отображаемый текст плюс ячейка курсора | Прежнее поведение буфера обмена |
| `PASSWORD` | Один ASCII `*` на расширенную графему, включая выделение и наложение курсора | Число звёздочек плюс ячейка курсора | Поглощаются без обращения к сервису и callback результата |
| `NO_ECHO` | Нет символов значения и выделения; активный курсор остаётся в крайней левой ячейке | Одна ячейка независимо от длины значения | Поглощаются без обращения к сервису и callback результата |

Выделенный прямоугольник по-прежнему задаётся ограничениями layout. PASSWORD раскрывает число
графем: комбинируемая последовательность или эмодзи с ZWJ получает одну звёздочку независимо
от настоящей ширины. Курсор и якорь остаются байтовыми смещениями исходного UTF-8 черновика.
Защищённые copy/cut также не меняют историю и invalidation. Входящие Ctrl+V и paste разрешены
для доступного на запись поля. Read-only блокирует paste, редактирование и пользовательский
Clear; disabled/hidden предки тоже блокируют команды. В NORMAL read-only по-прежнему разрешает
копирование. Явный программный `.text().set(...)` сохраняет прежнюю семантику, в том числе
для read-only редактора.

Отсутствующая или пустая подсказка ничего не показывает. Непустая видна только при пустом
черновике, с фокусом и без него, с существующим оформлением и отсечением по целым графемам.
Она не попадает в модель, валидацию, историю, callback или буфер обмена. NO_ECHO сохраняет
собственную ширину в одну ячейку и при показе подсказки. Проверяемый монтаж рецепта валидирует
и готовит её хранилище под политикой ширины сцены и лимитами редактора до публикации внутренней
модели. Неверный UTF-8, разделители строк и превышение лимитов отклоняют монтаж; ошибки текста
сохраняют типизированную причину, нехватка памяти даёт NO_MEMORY. Прямой низкоуровневый конструктор
`LineEdit` использует документированные исключения.

Обе настройки неизменяемы после монтажа. Для смены режима удалите редактор и создайте новую
привязку с новой историей. Уничтожение и повторное создание не обещают перезаписать старое хранилище.

PASSWORD/NO_ECHO управляют отображением и исходящим буфером обмена. Приложению по-прежнему доступны
открытые байты через модель, `TextProperty::get`, снимки текстовых источников, `LineEdit::text`,
результаты commit и Undo. История ограничена и включена по умолчанию: 128 общих операций, 1 МиБ
сохранённых снимков. `history.enabled = false` отключает Undo, включая Clear. Встроенные команды
рисования/кэша и экспорт диагностики не содержат фактическое защищённое значение; свои callback
и журналы контролирует приложение. Имена ссылок, scopes и подсказки должны быть несекретными.
Безопасное стирание и zeroization не предоставляются.

`Ref<LineEdit>::clear()` и низкоуровневый `LineEditBinding::clear()` создают одну отдельную
пользовательскую операцию с прежним черновиком и обоими концами выделения. Clear игнорирует
RESET_BASELINE программного setter и следует выбранному EditMode. Пустое доступное поле
остаётся строгим no-op. Read-only/disabled возвращают WOULD_BLOCK даже для пустого поля.
Clear не принимает и не перезаписывает более новую внешнюю модель как побочный эффект.

До принятия черновика ошибка памяти/истории/кэша/invalidation сохраняет прежний draft, выделение
и открытую группу набора. После принятия техническая ошибка публикации оставляет согласованные
пустой draft, историю и кэш с dirty=true, а модель — без этой публикации. Проверенный результат
команды возвращает точную техническую ошибку. VALIDATION_FAILED и CONFLICT — семантические
`LineEditResult`: результат команды успешен, принятый draft остаётся отменяемым. Непустой Clear
доставляет один outcome. Как в примере, возвращайте из managed-действия полный `EditorCommandResult`,
чтобы сохранить доказательство однократного сообщения; извлечение `.result()` его теряет.
Успешный commit модели и произвольные эффекты пользовательских callback не откатываются.

<summary>Справка: привязка, публикация и ввод</summary>

`LineEdit` владеет черновиком UTF-8, курсором и якорем выделения на границах [графем](glossary.md#glossary-text-units-ru) — текстовых кластеров, используемых как единицы перемещения курсора. Смещения задаются в байтах, горизонтальная прокрутка — в ячейках терминала. Поддерживаются комбинируемые символы, составные эмодзи с соединителем нулевой ширины (ZWJ), китайские, японские и корейские символы (CJK). Для декларативного создания используйте `ui::lineEdit(model)`. Низкоуровневую привязку `bindLineEdit` нужно хранить до отключения ввода и наблюдения.

Дерево, маршрутизатор и планировщик живут дольше привязки. Она удерживает модель и необязательный сервис буфера обмена. Перемещайте и уничтожайте её на UI между кадрами. Ссылки из `tree.read` действуют только внутри обработчика, команды текста — внутри внешнего `tree.frame`. Рисование не обращается к модели и сервисам. Маршрутизатор определяет доступность ввода; фокус для отображения передаёт приложение.

**Черновик и публикация**

`LineEditOptions::editMode` задаёт момент проверки и публикации технически принятого текста.

| Режим | Изменение текста | Потеря фокуса | Enter / подтверждение |
|---|---|---|---|
| `IMMEDIATE` (по умолчанию) | Проверить и опубликовать | Сохранить отклонённый черновик | Проверить и подтвердить |
| `ON_COMPLETION` | Сохранить черновик | Проверить и подтвердить один раз | Проверить и подтвердить |
| `EXPLICIT` | Сохранить черновик | Сохранить черновик | Проверить и подтвердить |

Пример настройки: `ui::lineEdit(model, {.options = {.editMode = EditMode::EXPLICIT}})`. Программный `router.invoke(field, {Action::ACTIVATE})` использует тот же обработчик и передаёт точный `LineEditResult` обработчику результата. Сам `invoke` возвращает `expected<DispatchResult, TreeError>`.

Техническое отклонение сохраняет прежний текст и выделение. Семантический отказ оставляет новый видимый черновик с `VALIDATION_FAILED`, без публикации: промежуточное пустое значение или минус можно продолжать редактировать. Исключение валидатора или публикации даёт типизированный `FAILED` и сохраняет принятый текст. Перед подтверждением и после валидатора проверяется исходная ревизия модели; `CONFLICT` не перезаписывает внешнее обновление.

Escape принимает последнюю корректную модель. В режиме IMMEDIATE ранее опубликованные изменения сохраняются. Успешная публикация делает черновик чистым и устанавливает точную ревизию квитанции; отклонённый или конфликтующий черновик остаётся изменённым до подтверждения либо Escape.

Потеря фокуса обрабатывается синхронно до следующего действия. Переход A→B→A между кадрами подтверждает A один раз. Уведомления модели и `sync` не создают событий потери фокуса. Равный текст не публикуется и не перерисовывается повторно; явное подтверждение может вернуть квитанцию неизменённого свойства.

Внешняя публикация обновляет чистое поле. Изменённое поле сохраняет черновик. Уведомление читает актуальный снимок. Перед каждым кадром выполняется синхронизация для восстановления отклонённых уведомлений. Успешный commit остаётся успешным при потере уведомления: `LineEditResult::commit` содержит точный `PropertyUpdate<std::string>`. Повторять публикацию ради уведомления нельзя.

`trigger` различает `INPUT`, `FLUENT` и `BLUR`. Управляемая ошибка по возможности сохраняет контекст `lineEdit.input`, `lineEdit.fluent` либо `lineEdit.blur`, исходную причину и узел. Ошибка потери фокуса при восстановлении в `prepare` записывается один раз.

Валидатор и буфер обмена могут повторно войти в UI. После их вызова проверяется жизнь узла, после проверки Enter — ревизия. Обработчик результата вызывается последним и может удалить узел, предка или привязку. Его исключение не отменяет принятых изменений. Синхронизация внутри кадра или действующей операции ввода возвращает `WOULD_BLOCK`; чужой поток отклоняется.

**Клавиши и буфер обмена**

- Left/Right, Home/End перемещают по графемам; Shift расширяет выделение.
- Backspace/Delete удаляют целые графемы или выделение.
- Ctrl+A выделяет всё; в NORMAL Ctrl+C копирует и Ctrl+X вырезает; Ctrl+V вставляет в доступное поле.
- Сервис `Clipboard` владеет возвращёнными байтами и заимствует копируемые на время записи. Он должен отвечать быстро. Отсутствие или ошибка даёт `CLIPBOARD_FAILED`; неудачное вырезание сохраняет выделение.
- Некорректный UTF-8, CR, LF, U+2028 и U+2029 отклоняют всю вставку с `INVALID_TEXT`. Другие управляющие символы хранятся логически и показываются как `?`; ESC/C0 не становятся терминальными командами.
- Лимиты ограничивают весь черновик в байтах, размере кластера, графемах и ячейках. Превышение возвращает `LIMIT_EXCEEDED` без обрезки. Неверный внешний снимок сохраняет отображение и возвращает `INVALID_ARGUMENT` при синхронизации.

По умолчанию ввод ограничен 4096 байтами. Буфер обмена получает этот лимит, результат проверяется повторно. Внутренняя ошибка памяти даёт `FAILED`/`NO_MEMORY`: до принятия сохраняется прежний черновик, ошибка публикации после принятия оставляет новый видимым. Создание аргументов может бросить до входа в API.

Курсор использует `LineEditOptions::cursor`, выделение — собственный стиль. Широкая графема не делится; в одноячеечной области вместо непомещающейся графемы отображается пустой курсор. Встроенные темы инвертируют цвета активного поля для курсора в true-color и ANSI16.

[Undo/Redo](editor-history.md) включены по умолчанию. Выделение мышью, композиция IME и системные реализации буфера обмена остаются отдельными возможностями. Тесты системных записей ConPTY не подтверждают все особенности конкретного терминального интерфейса.

См. [текст](text.md), [свойства](property.md), [фокус](focus.md), [терминал](terminal.md).
