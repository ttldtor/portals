# Сохранять позицию независимо от представления {#model-positions-ru}

[Английская версия](../model-positions.md) · [Данные модели](model.md)

Номер строки описывает порядок в одной ревизии модели. `RowId` определяет запись.
Вставка другой записи перед ней меняет номер строки, сохраняя её идентичность.
Закладка модели позволяет учитывать это различие при восстановлении позиции.

Здесь описана основа навигации для поставщиков данных из
`<portals/model_position.hpp>` и `<portals/model_position_finite.hpp>`.
Создание и разрешение закладки не меняет контрол, выделение, модель или область
просмотра. Автоматическое восстановление представлений и общие UI-курсоры
подключаются отдельными интеграциями.

## Что хранит закладка

`ModelResource` определяет логический ресурс и его совместимую историю — lineage.
Идентичность использует существующее пространство `SourceStamp`. Документ, заново
открытый по тому же пути, необязательно является прежним ресурсом. Поставщик
сохраняет lineage, только пока может сопоставлять старые и новые позиции.

`ModelPosition` различает запись, промежуток между записями и текстовую метку.
Позиция содержит ревизию данных и координату-подсказку. Самой координаты
недостаточно для определения текущего места записи. Для записи хранится полный
`RowId`, включая generation. Одинаковые ID строк разных ресурсов не связаны.

`ModelBookmark` владеет позицией и необязательными неизменяемыми метаданными
поставщика. Закладка не удерживает представление, снимок модели, строки или
страницы данных. Копии разделяют неизменяемые метаданные. Настраиваемый лимит
по умолчанию — 4096 байт; `storageBytes()` показывает учитываемый объём хранения,
а не резидентную память процесса.

Закладка в памяти не открывает файл заново и не сериализует его данные.
Для восстановления между процессами поставщику нужны переносимая идентичность
и кодек экспорта/импорта. `SourceCursor` остаётся токеном промежутка одной
неизменяемой сессии доставки и не заменяет закладку ресурса.

## Разрешение позиции

`PositionResolver` принимает `PositionRequest` и возвращает квалифицированный
`PositionReply` либо типизированную ошибку `SourceError`. Запрос содержит текущую
сессию источника, целевую ревизию, номер запроса и закладку. Перед применением
асинхронного ответа проверяйте `positionReplyMatches` для всё ещё актуального
запроса. Старый ответ не должен менять результат новой навигации.

| Результат | Значение |
|---|---|
| `EXACT` | Доступна та же запись или доказанно сопоставленная граница. |
| `NEAREST` | Запись удалена; разрешена позиция сохранившегося соседа. |
| `EMPTY` | В совместимом источнике нет текущей записи. |
| `PENDING` | Нужный ограниченный объём данных ещё не готов. |
| `UNSUPPORTED` | Поставщик не поддерживает этот вид позиции или поиск по ID. |
| `INCOMPATIBLE` | Ресурс, lineage или описание изменений не позволяют установить позицию. |
| `UNAVAILABLE` | Навигация поддерживается, но нужная история или хранилище недоступны. |

Интерфейс не требует общего числа строк. Потоковый поставщик может разрешать
свои ключи и границы без выдуманного конечного размера. Операции с вводом-выводом
выполняются через существующий механизм фоновой работы источника. Результат
`PENDING` не должен блокировать UI; полный просмотр источника в UI-потоке
для разрешения позиции недопустим.

## Адаптер конечного неизменяемого снимка

`FinitePositionResolver<T>` использует `ModelSnapshot<T>` и его ограниченный
по работе метод `locateRow`. Адаптер хранит слабую ссылку на снимок: закладка
и resolver не продлевают жизнь закрытого источника. Снимок должен соблюдать
требования модели к фоновому чтению и уничтожению.

Если полный ID записи сохранился, поиск удерживает её при вставках и перестановках.
Если запись отсутствует, для выбора соседа необходимо полное описание изменений
порядка. `PositionChangeMap` хранит заявленные поставщиком вставки, удаления
и перемещения между двумя ревизиями. Проверяются границы и арифметика; за полноту
описания отвечает поставщик. Настраиваемый лимит по умолчанию — 1024 операции.
Стоимость сопоставления зависит от числа операций, а не числа строк.

При направлении `FORWARD` удаление выбирает следующую сохранившуюся запись,
а в конце — предыдущую:

| До изменения | Изменение | Результат |
|---|---|---|
| A B **C** D | Удалить B | Текущей остаётся C. |
| A B **C** D | Удалить C | Ближайшей становится D. |
| A B C **D** | Удалить D | Ближайшей становится C. |
| A B **C** D | Удалить C и D | Ближайшей становится B. |
| A B **C** D | Удалить всё | Текущей записи нет. |

Направление `BACKWARD` предпочитает другую сторону. Промежутки учитывают сторону
вставки и сами не выбирают строку. Без совместимого описания изменений адаптер
не подгоняет старый номер строки под новую ревизию молча. Если поиск по ID
не поддерживается, результат сообщает об этом вместо полного перебора модели.

Адаптер строк не разрешает текстовые метки. Поставщик текста должен сохранять
границы графем и определять перемещение меток при правках. Эта основа не выполняет
редактирование, Undo/Redo, синхронизацию выделения или сохранение закладок на диск.

Общие текущая запись и место чтения описаны в разделе [навигация модели](model-navigation.md).
