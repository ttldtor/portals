# Инструменты проверки документов {#document-probe-reference-ru}

[Английская версия](../document-probe-reference.md) · [Инструменты измерения](developer-tools-measure.md#tool-document-probes-ru)

Эти инструменты разработки проверяют просмотр документов с ограниченной памятью
и правильность полученных окон источника. Сборка тестовых целей описана в
[руководстве по измерениям](developer-tools-measure.md#tool-document-probes-ru).
Генератору и драйверу проверок нужен Python 3.8+ со стандартной библиотекой;
SDK от Python не зависит. МиБ означает 1 048 576 байт; длительности `*_ns`
измеряются в наносекундах. Команды этой страницы сами по себе не подтверждают
результаты измерений или гарантии производительности при увеличении файла.

## Создать маленький вход с известным содержимым

[document_corpus.py](../../tests/probes/document_corpus.py) записывает
детерминированные UTF-8-байты SQL или Markdown через ограниченные буферы.
Повторяющиеся блоки по 256 байт содержат десятичный маркер каждого логического
МиБ. Перед ними можно добавить длинную первую строку. Manifest сохраняет
логический и физический размеры, SHA-256, шаблон и хеш генератора. Для gzip
используются уровень 1 и нулевой timestamp.

```powershell
New-Item -ItemType Directory -Path build/document-fixtures
python tests/probes/document_corpus.py --output build/document-fixtures/sample.sql --size-mib 1
./build/tools/portals_document_ui_probe.exe --file build/document-fixtures/sample.sql --language mysql --views 4
./build/tools/portals_document_oracle_probe.exe --file build/document-fixtures/sample.sql --pattern sql --size-mib 1 --evictions 3
```

Для каждой генерации выбирайте новое имя: существующие файлы отклоняются.
Для gzip добавьте генератору `--gzip`, обоим probe — `--kind gzip`, и используйте
сборку с включённым gzip. Для Markdown задайте генератору `--format markdown`,
UI-probe — `--language markdown`, oracle — `--pattern markdown`.

| Аргумент генератора | Назначение и ограничения | По умолчанию |
| --- | --- | --- |
| `--output PATH` | Новый файл данных; родитель существует, `PATH` и `PATH.manifest.json` отсутствуют | Обязателен |
| `--size-mib N` | Точный логический размер, 1–8192 МиБ | 16 |
| `--format sql\|markdown` | Известный шаблон содержимого | `sql` |
| `--long-line-mib N` | Длина первой строки вместе с переводом строки, 0–`size-mib`; ноль отключает | 0 |
| `--gzip` | Сжать данные без изменения логического размера | Выключен |
| `--help` | Показать справку без выходного пути и генерации | Выключен |

Нужно свободное место под логический размер плюс 64 МиБ, в том числе для gzip.
Генератор создаёт выбранный файл и соседний manifest, печатает JSON manifest
в stdout и при сообщённой ошибке генерации/I/O удаляет частичные файлы своего
запуска. Код 0 означает успех или справку, 2 — неверные аргументы либо отказ
предварительной проверки, 1 — ошибку генерации/I/O. Входные данные, кеши ОС
и настройки не изменяются.

## Probe всего Application

[document_ui.cpp](../../tests/probes/document_ui.cpp) запускает штатные
управляемую сцену, scheduler и background executor. Все видимые viewers
используют один cold descriptor, один байтовый источник и один корень
`SourceBudget`. Общая область — 120×40 ячеек: одно полное окно или четыре
квадранта по 60×20. Headless-приёмник считает и отбрасывает вывод; native-окно,
подтверждение физического показа и сохранение истории терминала не используются.

| Аргумент UI-probe | Назначение и ограничения | По умолчанию |
| --- | --- | --- |
| `--file PATH` | Существующий обычный файл; literal UTF-8-путь без раскрытия home и переменных окружения | Обязателен, кроме `--idle` |
| `--kind plain\|gzip` | Исходные или распакованные байты | `plain` |
| `--language plain\|mysql\|markdown` | Профиль текста/подсветки | `plain` |
| `--views N` | 1 или 4 видимых viewer | 1 |
| `--budget-mib N` | Общий лимит кредитов источника, 1–4096 МиБ; прочие аллокации процесса не входят | 128 |
| `--timeout-ms N` | Предел времени всей нагрузки, 1–3 600 000 мс | 60 000 |
| `--samples N` | Число сохраняемых первых samples каждой измеряемой фазы, 1–1 000 000 | 8192 |
| `--idle` | Тот же фасад Application без DocumentView, для отдельного измерения начального состояния | Выключен |
| `--help` | Справка без файлового I/O, создания Application и работы терминала | Выключен |

Конечный план включает начальную подготовку, прокрутку на строку и страницу,
Home, байт 4096, End, позиции непосредственно до/на/после 4 ГиБ и повторный Home.
Пропускаются позиции за известным размером, а также позиции, для которых размер
остаётся неизвестным. Отчёт различает запланированные, начатые, наблюдавшиеся,
завершённые и пропущенные этапы. Для ненаблюдавшихся этапов массив `views` пуст.
Запросы проходят через проверяемые ссылки viewer между подготовленными кадрами.
End для gzip может читать архив, чтобы установить логический размер; первый
переход по сжатому источнику может потребовать повторного чтения длинного префикса.

`first_accepted_output_frame_ns` может относиться к кадру загрузки.
`initial_text_ready_observed_ns` — наблюдение таймера scheduler после начальной
готовности текста, а не время первого отрисованного кадра с содержимым.
`initial_text_ready_observation_uncertainty_ns` хранит интервал наблюдения.
Поэтапные `first_output_frame_observed_ns` и `settled_ns` также получены таймером.
Неизмеренные времена равны `null`. Observer сообщает реальные фазы Application;
отдельной фазы `UI_TASK` в API нет.

Распределения фаз и опозданий таймера содержат общее число samples, сохранённый
префикс и переполнение. `p50_ns` и `p95_ns` вычисляются методом ближайшего ранга
только для непустого набора без отброшенных samples. Иначе `valid` равен false,
а процентили — `null`. Опоздание таймера характеризует отзывчивость scheduler;
такты независимого сборщика памяти не подтверждают отзывчивость UI.

Счётчики provider разделяют принятые логические байты и физические байты
источника, показывают нарушения запрета I/O на UI-потоке. Снимки памяти разделяют
текущую память процесса, системные пики за жизнь процесса и максимум выборки.
В Windows private memory — commit процесса, resident memory — рабочий набор.
В Linux resident-значения берутся из RSS и HWM; private commit недоступен
и остаётся `null`. Пик бюджета источника выбирается из samples и не является
инструментированным максимумом каждой аллокации. Метаданные самого корня остаются
учтены, пока он жив: cleanup отдельно сообщает возврат кредитов, число
page/work/consumer и фактическое уничтожение корня.

Probe печатает ограниченный JSON в stdout и диагностику в stderr. Вход не
изменяется, файлы результата не создаются. Код 0 означает завершение или справку,
2 — неверный CLI/вход либо недоступную запрошенную поддержку gzip, 1 — неполное
выполнение, timeout или ошибку runtime. Проверяйте `complete`, `workload_failed`,
наблюдения этапов и ошибки вместе с кодом завершения.

## Worker-oracle окон источника и подсветки

[document_oracle.cpp](../../tests/probes/document_oracle.cpp) использует
внутреннюю подготовку на worker и сравнивает полученный текст с зависящими от
позиции байтами генератора, а source maps — с последовательным лексическим
oracle. Проверяются покрытие целевого окна и EOF; явный EXACT-запрос должен
получить точные роли, доказанные по исходным байтам. Этот executable не запускает
event loop Application и не рисует пиксели терминала. Четыре состояния view
удерживают отдельные окна общего источника/корня; их подготовка последовательна
на одном worker.

| Аргумент oracle | Назначение и ограничения | По умолчанию |
| --- | --- | --- |
| `--file PATH` | Файл генератора с соответствующими шаблоном, логическим размером и первой строкой | Обязателен, кроме `--check` |
| `--kind plain\|gzip` | Обычный или gzip-вход | `plain` |
| `--pattern sql\|markdown` | Шаблон генератора для проверки байтов и ролей | `sql` |
| `--size-mib N` | Ожидаемый логический размер, 1–8192 МиБ | 1 |
| `--long-line-mib N` | Размер первой строки генератора, 0–`size-mib` МиБ | 0 |
| `--views N` | 1 или 4 удерживаемых состояния worker-view | 1 |
| `--evictions N` | Дополнительные различные позиции для циклов retained checkpoints, 0–64; не доказанное число вытеснений | 40 |
| `--timeout-ms N` | Предел всей worker-операции, 1–1 800 000 мс | 60 000 |
| `--exact` | Добавить явное восстановление EXACT в средней позиции после предыдущих этапов | Выключен |
| `--check` | Выполнить четыре отрицательные проверки контрактов навигации/EXACT без файлов | Выключен |
| `--help` | Показать справку без входов | Выключен |

Общий лимит кредитов фиксирован: 128 МиБ. После исчерпания ограниченного бюджета
уточнения AUTO может закончить с читаемой preview-подсветкой. Такой кадр не
доказывает глобальную точность синтаксиса. Отчёт разделяет итоговое состояние
подсветки и состояние удержанного кадра, если AUTO завершился без нового кадра.
Точные source maps проверяются там, где заявлена точность; `--exact` — отдельный
запрос, который может прочитать весь префикс или использовать checkpoints предыдущих этапов. Это не гарантированно холодный проход по префиксу и не проверка каждого байта документа. Для файла 1024 МиБ из одной строки длиной 1024 МиБ эта позиция находится внутри строки на 512 МиБ. UI-probe использует AUTO и не
требует такого восстановления для обычного перехода.

JSON содержит worker-времена первого кадра и завершения, число шагов, проверенных
байтов текста, source maps и exact maps, расхождений цвета, счётчики чтения,
выборку бюджета, память процесса и cleanup. Его `first_frame_ns` измеряет
подготовку worker; граница измерения отличается от времени вывода UI.
Код 0 означает завершение/справку/check, 2 — неверный CLI либо недоступный gzip,
1 — timeout, runtime-ошибку или нарушение oracle. Отсутствующий файл приводит
к ошибке при обращении provider во время выполнения. Вход не меняется, файлы
результата не создаются, кеши не сбрасываются.

## Маленький регрессионный драйвер и практика измерений

```powershell
python tests/probes/test_document_probes.py --ui-exe build/tools/portals_document_ui_probe.exe --oracle-exe build/tools/portals_document_oracle_probe.exe
./build/tools/portals_document_oracle_probe.exe --check
```

[test_document_probes.py](../../tests/probes/test_document_probes.py) требует
`--ui-exe PATH` и `--oracle-exe PATH`; `--gzip` дополнительно включает контракты
gzip-сборки и по умолчанию выключен. `--help` не требует executables и не
запускает тесты. Драйвер создаёт маленькие временные fixtures, ограничивает
время дочерних процессов, проверяет справку, неверный CLI, Unicode-пути,
одно/четыре окна, cleanup, переполнение samples, deadline, AUTO preview и отказы
oracle, затем убирает свои временные файлы и процессы. Код 0 означает успешные
проверки, 1 — ошибку проверки, 2 — неверный CLI или отсутствие executables.
Постоянные файлы доказательств драйвер не создаёт.

Большие квалификационные матрицы запускайте отдельно от регрессий каждого
коммита. Для повторов используйте отдельные процессы probe, сохраняйте stdout,
stderr и manifest входа, записывайте ревизию, compiler, configuration, платформу,
тип источника, язык, число окон, бюджет и deadline. Сравнивайте idle и нагрузку
при одинаковых настройках измерения. Новый процесс не доказывает холодное
состояние файлового кеша ОС: инструменты не сбрасывают кеши и не меняют глобальные
настройки. Кредиты источника, память процесса, принятый вывод и физический показ
остаются разными величинами.
