# Передать представлениям неизменяемые данные {#model-ru}

[Английская версия](../model.md)

Для отображения загрузки и результата подготовленного диапазона оберните управляемый
контрол в [представление данных](data-presentation.md); владение моделью и поставщиком сохраняется.

Используйте [ModelSnapshot<T>](../../include/portals/model.hpp). Этот фрагмент передаёт три имени списку. Сцена владеет моделью и автоматически подготавливает видимые строки. F10 закрывает приложение.

Фрагмент предполагает подключение `<portals/ui.hpp>` и `using namespace portals`; он использует адаптер Names — неизменяемый `ModelSnapshot<std::string>` с тремя записями — и функцию displayText для создания GraphemeText. Адаптер, функция, заголовки и вся программа приведены ниже и в [guide_model.cpp](../examples/guide_model.cpp).

```cpp
int main() {
  auto scene = ui::scene([](ManagedScene &owner) {
    return owner.model<std::string>(std::make_shared<Names>()).transform([](auto model) {
      return ui::virtualList(model, [](const ModelRow<std::string> &row) {
        return displayText(row.value);
      });
    });
  });

  return scene
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

<summary>Полная программа</summary>

```cpp
#include <portals/ui.hpp>
#include <array>
#include <stdexcept>

using namespace portals;

class Names final : public ModelSnapshot<std::string> {
public:
  Names() : ModelSnapshot(1, 3) {
  }

  ModelRows<std::string> read(RowRange range) const override {
    return {RangeState::READY,
            std::span(rows_).subspan(static_cast<std::size_t>(range.first), range.count), {}};
  }

private:
  const std::array<ModelRow<std::string>, 3> rows_{{
    {{1, 1}, "Ada"}, {{2, 1}, "Grace"}, {{3, 1}, "Margaret"}
  }};
};

GraphemeText displayText(std::string_view value) {
  auto result = GraphemeText::from(value);

  if (!result) {
    throw std::runtime_error("Invalid display text");
  }

  return std::move(*result);
}

int main() {
  auto scene = ui::scene([](ManagedScene &owner) {
    return owner.model<std::string>(std::make_shared<Names>()).transform([](auto model) {
      return ui::virtualList(model, [](const ModelRow<std::string> &row) {
        return displayText(row.value);
      });
    });
  });

  return scene
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

</details>

[Исходник примера](../examples/guide_model.cpp). Добавьте исходник в C++23-проект и свяжите его с целью portals::core ([инструкция сборки](getting-started.md)). Запустите программу в терминале.

Поставщик возвращает заимствованный диапазон своего неизменяемого массива. Модель удерживает снимок, пока представления используют его. RowId идентифицирует запись независимо от позиции. Публикуйте новый снимок со строго большей ревизией через ManagedModel::publisher(); обработайте отказ очереди и сохраните снимок для повтора.

Термины: [рецепт](glossary.md#glossary-recipe-ru), [кадр](glossary.md#glossary-frame-ru), [владение](glossary.md#glossary-ownership-ru).

<details>
<summary>Справка API и ограничения</summary>

`Model<T>` отделяет типизированный источник предметных данных от списка, таблицы или графика. Для списка `T` может быть скаляром, для таблицы и графика — записью приложения. `ModelRow<T>` содержит стабильный `RowId`, независимый от позиции строки. Приложение связывает типизированный доступ к полям с `ColumnId`; преобразование ячеек в строки и форматирование задаются отдельно. Перестановка и вставка сохраняют идентификаторы. Повторное использование номера строки или столбца требует нового поколения; исчерпанную пару переиспользовать запрещено.

Поставщик данных наследует `ModelSnapshot<T>` и предоставляет неизменяемую ревизию данных, логическое число строк и ограниченный `read(RowRange)`. Чтение обращается только к уже доступной памяти. Оно не выполняет ввод-вывод, не ожидает мьютекс провайдера, не запускает работу, не изменяет предметные данные и не форматирует невидимые строки. Готовый результат содержит ровно запрошенные строки; неготовый результат и ошибка не содержат строк. Текст ошибки принадлежит снимку.

Библиотека проверяет арифметику диапазонов и форму результата, переводит исключения провайдера в ошибки и сохраняет снимок за каждым возвращённым `ModelRange`. Провайдер обеспечивает уникальные стабильные идентификаторы и согласованность всех готовых диапазонов одной ревизии, включая пересекающиеся диапазоны из разных объектов снимка. Метаданные провайдера неизменяемы после создания.

**Владение и согласованный кадр**

Модель создаётся в UI-потоке владельца с существующим `WidgetTree` и узлом контекста. Дерево должно жить дольше источника. Корень или долгоживущий контекст приложения позволяет модели пережить отдельные представления. Удаление контекста и уничтожение источника закрывают оба канала `Scheduler`. Копия отправителя может пережить источник, дерево и планировщик; дальнейшая публикация возвращает `CLOSED`.

Перед каждым `WidgetTree::frame` вызовите `model.pin()` один раз и передайте один `ModelFrame<T>` всем представлениям этой модели. [Фиксированный снимок](glossary.md#glossary-model-pin-ru) `ModelFrame<T>` удерживает базовый снимок провайдера и неизменяемую таблицу результатов потребителей. `revision()` обозначает ревизию UI-кадра, включая запросы и готовность диапазонов; `dataRevision()` — ревизию предметных данных. Разные модели не образуют общей неявной транзакции. Обслуживайте планировщик между кадрами. Изменение источника и создание запросов внутри кадра дерева отклоняются. Рабочий поток может одновременно поставить результат в очередь, сохраняя текущий снимок кадра.

`frame.read(rows)` читает базовый снимок. `frame.range(consumer.id())` читает результат конкретного потребителя без объединения пересекающихся диапазонов. Оба возвращают независимые владельцы `ModelRange<T>`. Строки и текст ошибки остаются доступны, пока сохраняется диапазон или его базовый снимок, даже после уничтожения представления и источника.

`shared_ptr<const T>` требует неизменяемости всей достижимой памяти через другие ссылки. Деструкторы снимков, строк и объектов работы могут выполняться в потоке, освободившем последнего владельца. Деструктору, который повторно входит в UI, нужен живой UI-контекст и выполнение в UI-потоке владельца.

**Асинхронные диапазоны**

`model.openRange()` возвращает перемещаемый `ModelConsumer<T>` во владении UI-потока. Его `ModelRangeId` никогда не переиспользуется, даже если другой потребитель запрашивает те же строки. `consumer.request(rows, work_owner)` переводит результат потребителя в состояние ожидания и возвращает копируемый `ModelRequest<T>` для рабочего потока. Приложение планирует работу провайдера с этим токеном. Необязательный `work_owner` удерживает память работы; без него удерживается базовый снимок. Библиотека не создаёт поток и не запускает ввод-вывод.

Рабочий поток создаёт неизменяемый снимок готового диапазона либо ошибки и вызывает `request.complete(snapshot)`. Снимок должен сохранять исходную ревизию данных и логическое число строк. Доставка через ограниченный `Scheduler` проверяет потребителя, поколение запроса, ревизию, отмену и время жизни источника и контекста. Обновляется только слот этого потребителя. Новый запрос отменяет только его предыдущее поколение. Независимые завершения могут поступать в любом порядке; закрытие одного потребителя не отменяет другого с тем же диапазоном.

`request.cancel()` кооперативно отменяет поколение. Он не останавливает поток, не ожидает его и не освобождает резерв работы. Закрытие потребителя без выделения памяти отменяет текущее поколение и выводит слот из обращения. Сохранённые неизменяемые таблицы могут удерживать прежний результат до переиспользования слота или уничтожения источника, сохраняя ревизию и данные. Старый снимок кадра ещё может читать этот результат; удалённый дескриптор для новых кадров не используется. Уничтожение источника устанавливает `stopRequested` у живых токенов. Удаление контекста закрывает доставку, что завершение может обнаружить через `CLOSED`.

`model.publisher().publish(snapshot)` ставит полную замену провайдера в очередь. Применяются только строго новые ревизии данных. Новая ревизия переводит результаты потребителей в ожидание и отменяет прежнюю работу. Каждый потребитель запрашивает новый интервал после чтения числа строк из следующего снимка кадра. Старые завершения не перезаписывают новую ревизию. Провайдер агрегирует предметные события до публикации: отображаемый снимок должен сохранять влияние каждого принятого тика на OHLC и объём. Модель не объединяет предметные события.

Присваивание заменяет все поля до освобождения старой памяти. Деструктор последнего владельца может повторно войти в живой UI-контекст и освободить присваиваемый объект. После такого освобождения возвращённую ссылку использовать нельзя. Одновременное изменение одного объекта-владельца не поддерживается.

**Лимиты и ошибки**

Положительные `ModelOptions` независимо ограничивают строки на чтение и запрос, живые слоты потребителей и владельцев незавершённых запросов. Логическое число строк не выделяет строки или виджеты. Получение снимка кадра и чтение готового диапазона копируют небольшие объекты владения без копирования предметных строк. Публикация копирует только ограниченную таблицу потребителей.

- Неверные или слишком большие диапазоны и неправильная форма ответа возвращают `TreeError::INVALID_ARGUMENT`; завершение использует `SchedulerError::INVALID_ARGUMENT`.
- Лимит потребителей возвращает `NODE_LIMIT`, лимит работы или очереди — `WOULD_BLOCK`. Неудачный запрос сохраняет прежнее состояние.
- Резерв работы сохраняется после отмены, постановки завершения в очередь и уничтожения потребителя до освобождения последнего токена в рабочем потоке или очереди. Память провайдера уничтожается раньше освобождения резерва, включая повторный вход из деструктора.
- На поколение принимается одна успешная отправка завершения. При заполненной очереди можно повторить попытку. Дубликат и отменённый токен возвращают `CLOSED`.
- Принятие очередью не подтверждает применение. Нехватка памяти на UI сохраняет старую таблицу и фиксируется в `lastError()`. Эта диагностика сохраняется; для повтора нужного диапазона начните новый запрос.
- UI-операции проверяют поток. Уничтожение потребителя или источника в другом потоке завершает процесс. Читать провайдера и использовать переданных неизменяемых владельцев можно в потоках, разрешённых его контрактом уничтожения.

Успешное применение диапазона или полного снимка запрашивает компоновку и рисование контекстного узла. Запуск рабочих потоков, их автоматическая отмена, скрытое кэширование, вытеснение и объединение диапазонов не выполняются.

См. [`Scheduler`](scheduler.md), [дерево](widget-tree.md), [свойства](property.md).
