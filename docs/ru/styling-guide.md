# Стили сцены {#styling-guide-ru}

[Английская версия](../styling-guide.md)

[PSS](glossary.md) — язык таблиц стилей Portals. Он задаёт цвета, начертание текста и минимальную ширину контролов.
Контролы, компоновку и действия объявляют через C++ API `ui`.

## Запустите сцену со стилем

```cpp
#include <portals/ui.hpp>
#include <portals/ui_style.hpp>

int main() {
  using namespace portals;

  return ui::scene(ui::vbox(
    ui::label("F10: quit"),
    ui::button("Save").id("save")))
    | ui::theme(nordTheme())
    | ui::style(R"(
        Button#save { min-width: 12; bold: true; }
        Button#save:focused { background: #4bb4dc; foreground: #181c24; }
      )")
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Правила применяются к кнопке с `.id("save")`. F10 завершает приложение.
Требования к сборке описаны в [кратком руководстве](index.md), подключение
библиотеки — в [настройке пакета](package.md). `runApp` сообщает об ошибках
и пытается восстановить терминал. Для обработки ошибок при создании описания
сцены используйте фабричную перегрузку из [декларативного API](declarative-ui.md).

Далее фрагменты предполагают открытую [сцену](glossary.md#glossary-scene-ru) `ui::Scene scene` между кадрами,
`using namespace portals;` и заголовок `<portals/ui_style.hpp>`.

## Напишите правило

```cpp
scene
  | ui::style("Button { bold: true; }");
```

`Button` — [селектор](glossary.md), выбирающий тип контрола.
`bold: true;` задаёт полужирное начертание.

Вызов `ui::style(...)` возвращает объект настройки типа `ui::StyleStage`.
Такой объект называется [стадией UI](glossary.md#glossary-ui-stage-ru).
Он [владеет](glossary.md#glossary-ownership-ru) разобранной таблицей стилей.
Исходную строку можно освободить после завершения вызова `ui::style(...)`. Стандартные контролы получают метаданные стилей автоматически.
Собственный контрол должен зарегистрировать метаданные и рисовать с учётом
вычисленных стилей; подробности — в [справке по стилям](styles.md).

Ниже показана структура PSS v0. Квадратные скобки обозначают необязательные части:

```text
stylesheet  := rule ...
rule        := selector { property: value; ... }
selector    := [Type or *] [.class ...] [#id] [:state]
```

Условия ID, класса и состояния могут идти в любом порядке. В селекторе
допустимы один ID и одно состояние; все условия должны совпасть.
Селектор без типа начинается с `.`, `#` или `:`. Идентификатор начинается
с латинской буквы ASCII или подчёркивания; далее допустимы буквы, цифры,
подчёркивания и дефисы. Комментарии записывают как `/* ... */`.
ID чувствительны к регистру. Каждое объявление завершается точкой с запятой.

| Свойство | Значение | Результат |
|---|---|---|
| `foreground`, `background` | `#RRGGBB` | Перерисовка |
| `bold`, `italic`, `underline` | `true` или `false` | Перерисовка |
| `min-width` | Целое от 0 до `INT32_MAX`, в ячейках терминала | Компоновка и перерисовка |

Для `min-width` нужен селектор без условия состояния. Ноль сохраняет
размер, полученный при измерении содержимого контрола. Политики размеров и обрезка продолжают действовать.

Состояния: `normal`, `focused`, `disabled`, `selected`, `header` и `caret`.
Правило без состояния применяется ко всем вариантам оформления;
`:normal` — только к обычному варианту. Состояния `:hover` в PSS v0 нет.

## Разделите правила на заменяемые группы

Установка `ui::style` создаёт или обновляет [слой стилей](glossary.md).
[Уровень приоритета](glossary.md) по умолчанию — `APPLICATION`. Имя обозначает слой в пределах уровня:

```cpp
scene
  | ui::style("Button { min-width: 12; }", {.name = "layout"});
scene
  | ui::style("LineEdit { foreground: #ff5555; }", {.name = "validation"});
scene
  | ui::style("Button { background: #181c24; }", {.name = "branding"});

scene
  | ui::style("LineEdit { foreground: #55ff55; }", {.name = "validation"});
```

Последняя стадия заменяет всю таблицу `validation`. Слои `layout` и `branding`
сохраняются. Правила начинают действовать при установке.
Проверку данных выполняет код приложения.

**Имя необязательно.** Задайте его, если позже нужно заменить отдельную группу
правил новой стадией. Независимо созданные безымянные стадии создают независимые
слои. Повторное использование той же стадии проверяет идентичность её слоя.

Ключ слоя — `(уровень, имя)`. `APPLICATION/validation` и `USER/validation`
независимы. Замена сохраняет позицию слоя; при отказе сохраняется прежняя таблица.
`.id("save")` обозначает контрол для селекторов. Удаление и дескрипторы слоёв
описаны в [справке по слоям](style-layers.md).

## Определите приоритет правил

Каждое свойство вычисляется отдельно по уровням:

```text
значения контрола по умолчанию < DEFAULTS < THEME < APPLICATION < USER
```

Более высокий уровень имеет приоритет. Внутри уровня специфичность сравнивается
по `(наличие ID, число классов + число состояний, наличие типа)`.
При равной специфичности учитывается порядок установки слоёв, затем порядок
правил: более позднее объявление побеждает. Замена именованного слоя сохраняет порядок.

Пропущенное свойство сохраняет значение нижнего приоритета. Явное `false`
может переопределить `true`. В PSS v0 свойства не наследуются от родителя.
Устанавливайте прикладные и пользовательские слои до подключения контроллера
динамической темы.

## Загрузите стили из файла

```cpp
scene
  | ui::style(ui::file("themes/modern.pss"), {.name = "palette-file"});
```

`ui::style(ui::file(...))` возвращает объект с собственной копией пути.
Файл читается при применении этого объекта к сцене.
Обычная строка содержит текст PSS. Включение других файлов, автоматическая
перезагрузка и наблюдение за файлом пока отсутствуют.
`parsePssDocument(bytes, sourceName)` выполняет только разбор байтов.

Стадии источников стилей принимают `APPLICATION` и `USER`; по умолчанию
используется `APPLICATION`. Для замены темы вызовите `ui::theme(StyleSheet)`;
см. [темы](themes-guide.md).

## Отличия от CSS и QSS

PSS v0 поддерживает перечисленные выше селекторы, состояния и свойства.
[QSS](https://doc.qt.io/qt-6/stylesheet-syntax.html) также поддерживает селекторы
потомков, дочерних элементов, свойств и частей контролов. В PSS v0 эти возможности,
списки селекторов, цепочки состояний, наследование и единицы длины отсутствуют.
Для цвета текста используется `foreground`, для ширины — ячейки терминала.

[Пользовательские свойства CSS](https://www.w3.org/TR/css-variables/)
записывают через `--name` и `var(...)`. В PSS v0 переменных и функций пока нет.
Существующие типизированные параметры C++ описаны отдельно в
[стилях времени компиляции](compile-time-styles.md).

## Обработайте ошибку стиля

Ошибки настройки доступны через `scene.checked()` и политику сообщений `runApp`.
Диагностика источника содержит смещения в байтах, номер строки и байтовый столбец
с отсчётом от единицы. Отклонённое обновление сохраняет прежнюю таблицу
и вычисленные стили. Обновляйте стили между кадрами в UI-потоке.
Создание стадии может выбросить исключение; границы фабричного запуска описаны
в [декларативном API](declarative-ui.md).

Например, правило `Button { color: #ff5555; }` даёт `UNKNOWN_PROPERTY`.
Замените `color` на `foreground` и примените исправленную таблицу.
Отклонённое обновление сохраняет прежнее оформление.

Для стиля одного контрола используйте `ui::style(ref, source)` или
`ui::styleFile(ref, path)`. Область действия и время жизни описаны в
[применении стилей через ссылку](declarative-ui.md).
