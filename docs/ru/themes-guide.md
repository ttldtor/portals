# Выбор и обновление темы {#themes-guide-ru}

Примеры существующего API ниже относятся к базовой версии `84b865e`; разделы **TBD** описывают будущую работу.

[English original](../themes-guide.md)

Тема — обычная таблица стилей, задающая палитру. Она меняет оформление;
поведение ввода не меняет и отдельную среду исполнения не вводит.
Прикладные переопределения описаны в [гайде по стилям](styling-guide.md).

## Выберите встроенную палитру

Фрагмент предполагает подключённый `<portals/ui.hpp>` и бездействующую `ui::Scene`:

```cpp
scene | ui::theme(nordTheme());
```

| Фабрика | Оформление |
| --- | --- |
| `modernTheme()` | Современная тёмная палитра |
| `turboTheme()` | Палитра в духе Turbo |
| `nordTheme()` | Тёмная палитра Nord |
| `gruvboxTheme()` | Тёмная палитра Gruvbox |
| `tokyoNightTheme()` | Тёмная палитра Tokyo Night |
| `catppuccinLatteTheme()` | Светлая палитра Catppuccin Latte |

Фабрики возвращают владеющие значениями `StyleSheet` и могут выделять память
до установки. Для подготовленной управляемой сцены `ManagedScene::theme(sheet)`
возвращает проверяемый результат установки. UI-фасад собирает ошибки настройки
для `checked()` или runner. Заменяйте тему между кадрами в UI-потоке сцены.

## Задайте свои шесть цветов

`ThemeTokens` — палитра C++, а не объявление переменных PSS. Этот фрагмент настройки
заменяет тему шестью явно заданными RGB-цветами:

```cpp
scene | ui::theme(themeFromTokens(ThemeTokens{
  .foreground = RgbColor{220, 225, 232},
  .background = RgbColor{24, 28, 36},
  .accent = RgbColor{75, 180, 220},
  .muted = RgbColor{125, 135, 150},
  .selection = RgbColor{45, 75, 110},
  .heading = RgbColor{255, 200, 85}
}));
```

| Токен | Роль в оформлении |
| --- | --- |
| `foreground` | Обычный и выделенный текст |
| `background` | Обычная заливка, текст в фокусе и заливка каретки |
| `accent` | Заливка в фокусе и текст каретки |
| `muted` | Текст отключённого контрола |
| `selection` | Заливка выделенной строки/диапазона редактора |
| `heading` | Текст заголовка |

Стандартные правила запрашивают полужирное начертание для фокуса, выделения
и заголовков. Каретка инвертирует цвета поля в фокусе. Эти токены не покрывают
все возможные поверхности виджетов; для дополнительных вариантов добавьте
обычные правила.

## Сохраните прикладные переопределения при смене темы

Перед установкой независимо заменяемых стилей включите слои:

```cpp
scene.styleLayers()
     .styleLayer(StyleTier::APPLICATION, "application", applicationStyles)
     .styleLayer(StyleTier::USER, "contrast", userStyles);
scene | ui::theme(gruvboxTheme());
```

Фрагмент предполагает владеющие значениями `StyleSheet` с именами
`applicationStyles` и `userStyles`. Замена темы меняет слот `THEME`. Прикладные
и пользовательские слои остаются выше него, в том числе при изменении параметров
живой темы. Поэтому прикладное переопределение foreground может скрыть обновление
акцента: обновление прошло успешно, но декларация более высокого уровня всё ещё
побеждает. См. [приоритет слоёв](style-layers.md).

## Обновите типизированный параметр во время работы

Подключите `<portals/ui_style.hpp>`. Существующий экспериментальный дескриптор
C++23 поддерживает именованные параметры `RgbColor`, `bool` и `std::int32_t`.
Фрагмент объявляет изменяемый акцент и производный цвет для состояния фокуса:

```cpp
namespace sc = portals::style::ct;
constexpr auto THEME = sc::sheet(
  sc::parameters(sc::parameter<"accent">(sc::rgb(75, 180, 220))),
  sc::rule(sc::selector<"Button">(),
           sc::foreground(sc::token<"accent">())),
  sc::rule(sc::selector<"Button">(StyleState::FOCUSED),
           sc::background(sc::mix(sc::token<"accent">(),
                                  sc::rgb(24, 28, 36), 50))));

auto stage = ui::liveTheme(THEME);
auto colors = stage.ref();
scene | stage;
```

После успешного подключения разрешённый UI callback может изменить акцент:

```cpp
auto changed = colors.set<"accent">(sc::rgb(255, 200, 85));
```

Проверяйте результат: `true` означает изменение, `false` — равное значение;
отказ сохраняет прежние значения и таблицу стилей.
`apply(sc::change<"name">(value), ...)` меняет пакет атомарно. Имена и точные
скалярные типы проверяются во время компиляции. `mix` — существующее ограниченное
выражение с процентом от 0 до 100; это не вычислитель произвольных выражений
и не граф производных токенов.

Сцена владеет подключённым контроллером. `colors` — слабый наблюдатель: он не
удерживает сцену живой, чтение и обновление разрешены только в UI-потоке.
Закрытие или утрата актуальных полномочий управления темой дают типизированную
ошибку. После смены владельца темы подключите новую стадию; старая не
переустанавливает себя молча.

## Файлы и ограничения

`themes/modern.pss` и `themes/turbo.pss` соответствуют своим типизированным
фабрикам. Синтаксис файлового источника: `ui::style(ui::file(path), options)`;
см. [гайд по стилям](styling-guide.md). По умолчанию уровень — `APPLICATION`,
поэтому выбирайте слои осознанно: загруженный туда файл не становится
заменяемым слотом `THEME` автоматически.
В PSS v0 нет неявного наблюдения за файлом или подстановки переменных темы.

## Направление: один PSS-источник тем

**TBD — M5, U65:** PSS станет единственным редактируемым источником встроенных тем.
Из него будут генерироваться C++-представление и встроенные ресурсы; приложению
не потребуются файлы тем в рабочем каталоге. Так не придётся вручную поддерживать
вторую таблицу палитры. Существующие фабрики остаются реализованным путём;
в описываемой базовой версии это изменение ещё не выполнено.

Принятое направление: валидировать и загружать тему средствами стилей, затем
атомарно заменять слой `THEME`. Прикладные и пользовательские слои сохраняются.
Смена темы заменяет таблицу стилей, а не накапливает патчи вычисленных свойств.
Сегодня `ui::style(ui::file(path))` по умолчанию устанавливает `APPLICATION`;
это не будущий загрузчик темы в `THEME`.

**TBD — M5, U65:** общие правила классов/состояний контролов будут использовать
типизированные семантические параметры с полными светлыми/тёмными defaults.
Тема сможет переопределять параметры и правила. Автоматическое определение
системного светлого/тёмного варианта — отдельный незавершённый контракт,
а не существующая функция или обещание отдельно назначенного пакета.

**TBD — M5, U65; целевой путь данных (один resolver):**

```text
редактируемый PSS -> встроенный PSS / файл PSS -> проверка -> замена THEME
внешняя тема -> импортёр -> нормализованный PSS ---^           |
                                             существующий style resolver
                                             APPLICATION / USER сохраняются
```

Ветка импортёров отдельно не назначена в очередь. Схема не вводит отдельный
runtime для тем.

### Импорт внешних тем в PSS

**TBD — направление U65, M5; milestone импортёров отдельно не назначен:**
импортёр будет нормализовать поддержанные поля внешнего формата в параметры/правила
и выдавать PSS. Парсеры внешних форматов не станут обязательными зависимостями
retained core; импорт кодовой темы не будет исполнять её код.

Цветовые схемы Windows Terminal JSON и Base16/Tinted YAML — первые кандидаты,
а не утверждённые цели совместимости. Для каждого импортёра нужны версия формата,
соответствие полей, синтезированные defaults, неподдержанные свойства и notices
источника. ANSI-палитра сама по себе не задаёт роли Button, selection, error
или предметные роли bid/ask: их отображение должно быть явным и настраиваемым.
Пакет импортёров требует отдельной декомпозиции; дополнительный бюджет пока
не оценён.

### Runtime-параметры пока запланированы

**TBD — M5, U65/U128:** параметры и выражения runtime PSS описаны через
[раздельные пространства имён и checked-обновления](styling-guide.md#future-style-parameters-ru).
Экспериментальный типизированный C++-путь `token`/`mix` и `LiveTheme` выше уже
существует; это не делает такие выражения допустимыми внутри строки PSS.
`LiveThemeRef` не связывает произвольное свойство предметной области автоматически;
обновляйте его явно в UI-потоке. Compile-time стили остаются
[отдельным документом для пересмотра](compile-time-styles.md).

## Изучите полную программу

[PSS consumer со строковыми источниками](../../tests/package_consumer/style_pss_after.cpp)
и [его общая настройка](../../tests/package_consumer/style_pss_support.hpp) показывают
слои, живые обновления, отказы обновления и очистку. Отдельный типизированный
дескриптор рассмотрен в [compile-time стилях](compile-time-styles.md) и полных
consumer-примерах к ним. Сохраняйте этот документ отдельным предметом пересмотра,
не смешивая его C++-синтаксис с будущей строковой грамматикой.

Режим цвета терминала всё ещё влияет на результат. True color сохраняет
RGB-палитру; ANSI16 квантует цвета и может свести близкие варианты к одному.
Полужирное, курсивное и подчёркнутое начертания — запросы терминалу, а не гарантия
одинакового внешнего вида.
