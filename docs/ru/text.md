# UTF-8, графемы и ширина текста {#text-ru}

[Подробная английская версия](../text.md)

`<portals/text.hpp>` предоставляет `GraphemeText`: значение с собственным хранением UTF-8 с неизменяемыми расширенными графемными кластерами и измерениями в ячейках. Байты, графемы и ячейки учитываются раздельно. Сегментация использует utf8proc 2.12.0, Unicode 18.0.0 и [UAX #29](https://www.unicode.org/reports/tr29/). Нормализация и исправление входа не выполняются. Некорректный UTF-8 возвращает байтовое смещение ошибочной последовательности, включая усечённый конец, избыточную кодировку и закодированные суррогаты. Встроенный NUL сохраняется.

## Владение и курсор

При создании вход копируется. `bytes()` и `graphemes()` заимствуют память до уничтожения, присваивания или перемещения объекта. Копии независимы. После перемещения в другой объект источник пуст; самоперемещение сохраняет значение. Чтение допускает несколько потоков, изменения требуют внешней синхронизации.

Создание и копирование могут бросить `std::bad_alloc` или `std::length_error`. Семантические ошибки и превышение лимитов возвращаются через `std::expected`; частичный текст не возвращается. Конструктор перемещения может выделять служебную память отладочных итераторов: при сбое источник сохраняется. Перемещающее присваивание — `noexcept`, без выделений.

Перемещение курсора и обрезка не выделяют память и не бросают исключений. Курсор использует двоичный поиск; обрезка последовательно проверяет префикс. Смещения должны попадать на границы графем, включая начало и конец, иначе возвращается `NOT_BOUNDARY`. Движение за соответствующий край сохраняет позицию. Отрицательный лимит обрезки считается нулём. Кластер шириной две ячейки завершает префикс, если целиком не помещается.

## Политика ширины

`WidthPolicy` задаёт детерминированный профиль измерения. Фактическое формирование глифа шрифтом и совместимость с конкретным терминалом требуют отдельной проверки. По умолчанию символы неоднозначной восточноазиатской ширины (`Ambiguous`) занимают одну ячейку, эмодзи — две. В широком режиме печатные символы этой категории с шириной один расширяются до двух ячеек. У обычного кластера суммируются положительные ширины скаляров; комбинируемые и нулевые символы ширину не добавляют. [UAX #11](https://www.unicode.org/reports/tr11/) сам по себе не определяет фактическую ширину терминального глифа.

Распознаются последовательности клавишных символов (`keycap`: `[0-9#*]`, необязательный VS16 и знак клавиши), кластеры региональных индикаторов, включая одиночный индикатор, и `Extended_Pictographic` с шириной два либо VS16, ZWJ, модификатором или последовательностью тегов. VS15 подавляет расширение пиктографического символа. Выбор одной или двух ячеек применяется к одиночным и составным эмодзи. Дополнительные комбинируемые знаки остаются в своём логическом кластере. Используются свойства utf8proc без отдельной таблицы Unicode. Это ограниченный профиль распознавания; полного валидатора RGI здесь нет.

Кластеры шириной ноль или обычные кластеры шириной больше двух помечаются `unsupported` и измеряются одной ячейкой. Управляющие символы, CRLF, табуляция, ESC, NUL, C1, неназначенные скаляры, разделители строк/абзацев и неподдерживаемое форматирование также `unsupported`. При выводе обязательно используется ASCII `?`; исходные управляющие байты выводить запрещено. Логические байты и границы сохраняются. Раскрытия табуляции и многострочной разметки здесь нет.

## Лимиты и пересчёт

Значения по умолчанию: 1 МиБ входа, 64 КиБ на кластер, 1 048 576 кластеров, 2 097 152 ячейки. Настройки изменяемы при создании; длина ограничена также `PTRDIFF_MAX`, сумма ячеек — `INT32_MAX`. Пустой текст допустим при нулевых лимитах. Превышение лимита отклоняет вход целиком. Ошибка ресурса указывает начало отклонённого кластера; ошибки длины входа и политики — смещение ноль.

Полная `WidthPolicy`, включая `revision`, должна входить в ключи кэшей измерений, размещения и кадрового буфера. При смене политики создайте новые измерения и запросите перерасчёт геометрии и отрисовки. `GraphemeText` не меняет политику после создания и не инициирует обновление UI.

## Секретные байты в SecureString {#text-secure-string-ru}

[`SecureString` и `SecretView`](../../include/portals/secure_string.hpp) предоставляют
перемещаемое владение байтами и синхронный доступ к открытому содержимому через
`<portals/secure_string.hpp>`. Подключите target `portals::core` из
[установленного пакета](package.md). `SecureString` сохраняет байты приложения,
включая встроенный NUL, без проверки Unicode, нормализации, SSO и неявного
преобразования в обычный текст.

`create`, `assign` и `append` копируют заимствованный `std::string_view` во время
вызова; входной буфер должен оставаться действительным до его возврата. Для байтов
с NUL можно передать `std::string_view(data, size)`. Исходный буфер вызывающего кода
и копии внешних API находятся вне гарантий этого хранилища. Лимит `maxBytes` по
умолчанию равен 4096 байтам; допустимы значения от 0 до 1048576. Ноль разрешает
только пустые значения. Если требуется новое хранение, изменение подготавливает
выделение под конечную логическую длину, с округлением до страниц рабочей области
для native-хранения.

Этот полный пример использует условное ASCII-значение, читает только его длину
и явно закрывает хранилище. Он ничего не выводит и не открывает терминал:

```cpp
#include <portals/secure_string.hpp>

#include <cstddef>

int main() {
  auto secret = portals::SecureString::create("sample");

  if (!secret || !secret->append("-bytes")) {
    return 1;
  }

  std::size_t byteCount{};
  auto accessed = secret->withPlaintext([&](portals::SecretView view) {
    byteCount = view.size();
  });

  if (!accessed || byteCount != 12 || !secret->clear()) {
    return 2;
  }

  return secret->close() ? 0 : 3;
}
```

По умолчанию Windows и Linux выделяют отдельные страницы: рабочая область (payload)
всегда доступна для записи, снаружи её окружают две недоступные защитные страницы
(guard pages). Если Windows-шифрование покоя не запрошено, живая рабочая область
содержит открытые байты между callback. Стирание охватывает весь выделенный доступный
объём (capacity), включая выравнивание и неиспользованный хвост.
Независимые запрошенные опции обязательны: недоступная гарантия возвращает
`UNSUPPORTED`, а сбой native-подготовки — типизированную ошибку без молчаливого
ослабления политики.

| Гарантия | По умолчанию | Windows | Linux | WASM / другие неподдерживаемые платформы |
| --- | --- | --- | --- | --- |
| Стирание capacity | Обязательно | Применяется | Применяется | Применяется при явном `WIPE_ONLY` |
| Внешние guard pages | Обязательны при `NATIVE_GUARDED` | Применяются | Применяются | Не поддерживаются |
| `lockPages` | `false` | Native-блокировка страниц | Native-блокировка страниц | Не поддерживается |
| `excludeFromDumps` | `false` | Не поддерживается | Исключение из Linux core dump | Не поддерживается |
| `encryptWhileIdle` | `false` | `CryptProtectMemory`, `SAME_PROCESS` | Не поддерживается | Не поддерживается |

На WASM создание с политикой по умолчанию возвращает `UNSUPPORTED`, в том числе
для пустого входа. Чтобы явно принять только стирание, можно передать в `create`
`SecureStringOptions` со `storage = SecureStringStorage::WIPE_ONLY`. Эта политика
использует heap или линейную память и отклоняет запросы блокировки, исключения из
дампов и шифрования на всех платформах. `capabilities()` сообщает фактически
применённые гарантии. Эти механизмы не защищают от отладчика или ArtMoney с доступом
к процессу, враждебного кода внутри процесса, терминального хоста, keylogger,
доступа к открытому содержимому во время callback и внешних копий. Длина видна.

`withPlaintext` владеет копией или перемещённым callable и удерживает хранилище
до конца callback. `SecretView` даёт явные `data()` и `size()`; время его жизни
заканчивается при возврате callback. Указатель и созданные из него представления
нельзя сохранять для дальнейшего использования. C++ не может запретить callback
сохранить указатель или скопировать байты; ответственность за такие значения
остаётся у вызывающего кода. Callback возвращает `void` либо
`std::expected<void, E>` с владеющей ошибкой, перемещение которой не бросает исключений;
прямые borrowed-ошибки и coroutine/task results отклоняются. Пользовательские обёртки
ошибок и ссылочные captures callable сохраняют свои обязательства по времени жизни.

Перемещение или уничтожение внешнего владельца внутри callback сохраняет активный
view. Перемещённый handle сохраняет состояние занятости: вложенный доступ и
проверяемые изменения, включая пустой append, clear и close, возвращают `BUSY`.
Операции, перемещения и уничтожение требуют внешней синхронизации; одновременное
изменение из разных потоков не поддерживается.

Сбой выделения или подготовки capabilities сохраняет прежнее значение. Неоднозначный
сбой crypto стирает затронутый payload и делает значение недоступным; замена после
удаления старого хранения не восстанавливает старые байты. Собственная диагностика
библиотеки содержит только операцию, категорию и native code. Ошибки или исключения
callback учитываются отдельно от ошибок cleanup; непрозрачная `callbackError`
библиотекой не логируется. `cleanup` сохраняет первые четыре ошибки по порядку,
а число остальных записывает в `omittedCleanupCount`.

`clear()` оставляет действительное пустое значение с той же политикой. `close()`
стирает и освобождает память; после успеха повторный вызов безопасен. Сбой освобождения
оставляет значение недоступным, а метаданные обнулённого выделения сохраняются для
повторного проверяемого `close()`. Деструктор без исключений делает не более двух
попыток освобождения; постоянный отказ ОС может оставить утечку обнулённого хранения.
