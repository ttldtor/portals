# Ввод с клавиатуры {#input-ru}

[Английская версия](../input.md)

Привяжите клавишу к действию через [`ui::onKey`](../../include/portals/ui.hpp). Пример показывает подсказку по F1; F10 закрывает приложение. Runner читает и декодирует терминальный ввод автоматически.

```cpp
#include <portals/ui.hpp>

int main() {
  using namespace portals;

  ui::Ref<Label> help;

  auto scene = ui::scene(
    ui::label(help, "F1: Help; F10: Exit"));

  return scene
    | ui::onKey("F1", [help] {
        help.text() = "Use Tab to move focus and Enter "
                      "to activate a control";
      })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Сочетания: `"Ctrl+S"`, альтернативы: `{key::F10, key::ALT + key::Q}`. По умолчанию callback получает PRESS. Обычный VT-ввод сообщает только PRESS, в том числе при удержании клавиши; RELEASE и отдельный REPEAT требуют адаптера, который действительно их предоставляет. См. [маршрутизацию и фокус](focus.md).

<details>
<summary>Справка: фазы и последовательности клавиш</summary>

**Нажатие, повтор и отпускание**

Обычная строка, аккорд и список альтернатив принимают PRESS:

```cpp
scene.onKey("W", move);
scene.onKey(ui::repeat("W"), move);       // Native REPEAT only.
scene.onKey(ui::release("W"), stop);      // Native RELEASE only.
scene.onKey(ui::pressRepeat("W"), move);  // PRESS or native REPEAT.
scene.onKey(ui::release({key::F10, key::ALT + key::Q}), stop);
scene.onKey(ui::repeat({key::UP, key::DOWN, key::LEFT,
  key::RIGHT}), move);
scene
  | ui::onKey(ui::keyActions("W", {KeyAction::PRESS,
    KeyAction::RELEASE}), action);
```

`ui::press(source)` выбирает PRESS. Все помощники принимают строку, типизированный
аккорд, владеющий Shortcut или список альтернатив. `keyActions` принимает
непустое подмножество PRESS/REPEAT/RELEASE. Повторы альтернатив и фаз вызывают
обработчик один раз. Пустой или неверный набор даёт `INVALID_ACTION_SET`
с индексом ошибочной фазы; для пустого индекс равен нулю.

Нормализация выполняется при настройке. Выбор владеет неизменяемыми альтернативами;
временные строки могут исчезнуть. Регистрация владеет обработчиком. Место
диагностики относится к `onKey`, смещение — к ошибочному входу. Новейшая
подходящая регистрация выигрывает; модификаторы совпадают точно, ASCII-буквы
сопоставляются по существующей политике регистра. Обработчик принимает
`void`-аргументы либо `const KeyEvent&` и поддерживаемые проверяемые результаты.

`ShortcutBehavior{.repeat = true}` выбирает PRESS+REPEAT для обычного источника.
Явный KeySelection уже содержит полный набор фаз. Сырой KeyEvent принимает
PRESS и REPEAT. Текстовый ввод представляет только PRESS.
VT-декодер выдаёт PRESS для повторных байтов и не создаёт отпускания.
Для REPEAT/RELEASE требуются настоящие события платформенного адаптера.
Удержание и синтетическое отпускание при потере фокуса не добавляются.
Поддержка Kitty запланирована как **TBD, M7**.

**Последовательности**

`Ctrl+K+K` означает Ctrl+K, затем Ctrl+K. `Ctrl+K,K` означает Ctrl+K, затем K
без модификаторов. Все модификаторы сегмента с `+` относятся ко всем его клавишам;
запятая начинает независимый сегмент. Shortcut владеет `sequences` и одиночными
`alternatives`; они делят общий бюджет. `matchShortcut` проверяет одиночные аккорды.

Выбранная фаза применяется к каждому шагу. Например, `release("A,B")` ждёт два
настоящих RELEASE; промежуточный PRESS проходит обычным путём. Неподходящий PRESS
сбрасывает ожидание, если кандидат принимает PRESS. Неподходящие REPEAT/RELEASE
его сохраняют. Новый начальный префикс заменяет ожидающую группу.

Новейшая регистрация на каждой глубине определяет завершение или продолжение.
Подавленные команды не вызываются при таймауте или несовпадении.
Альтернатива-префикс другой альтернативы той же регистрации даёт
`AMBIGUOUS_PREFIX`. Немодифицированный Escape PRESS отменяет ожидание и поглощается;
в продолжении он запрещён с `RESERVED_CANCEL` и смещением байта.

`ManagedOptions::keySequenceTimeout` положителен, по умолчанию 1000 мс.
Один слабый таймер Scheduler перезапускается после принятого промежуточного шага.
При `now >= deadline` ожидание очищается до обработки продолжения.
Смена фокуса, видимости, доступности, удаление и замена ввода отменяют префикс,
включая изменение туда и обратно. Обычная PAINT/LAYOUT-инвалидация его сохраняет.
Подробнее — в [декларативном API](declarative-ui.md#short-key-bindings-ru).

<details>
<summary>Справка: интеграция потокового VT-декодера</summary>

[`InputDecoder`](../../include/portals/input.hpp) нужен для собственного адаптера терминала. Он синхронно преобразует байты в события; вызывающий код задаёт время, включает режимы терминала, ограничивает очередь событий и обслуживает таймауты. Приложению с `ui::runApp()` этот цикл не нужен.

**Чтение декодера**

`InputDecoder::create(options)` возвращает владельца или `INVALID_OPTIONS`.
Одним экземпляром пользуется один исполнитель без конкурентных вызовов.
Перемещённый источник перед повторным использованием сбрасывается.
Полученные события владеют данными и переживают сброс или уничтожение декодера.

`next(bytes, now)` возвращает не более одного события и точный `consumed`.
Передайте остаток снова с первоначальной отметкой поступления. Событие может
потребить ноль байтов при таймауте и восстановлении. NEED_INPUT означает
исчерпание текущего входа; WORK_LIMIT требует следующего чтения.
Собственную очередь событий ограничивает вызывающий код.

Пустой `next` продвигает время. Перед ожиданием вычитайте события; после NEED_INPUT
ждите байты или `deadline()`. `finish(now)` начинает EOF и вызывается до finished
или failed. Последний finished может содержать событие. Дальнейший finish пуст
и идемпотентен; next даёт CLOSED. `reset()` освобождает вставку, очищает часы,
смещения и окно ответов, сохраняя параметры. Сброс объявляет новую сессию:
остаток незакрытой вставки нельзя безопасно продолжать как клавиши.

Ошибочный вызов отклоняет всё переданное представление. Время назад отклоняется
до изменений. Переполнение смещения проверяется для максимального потребляемого
префикса. Исключение памяти оставляет декодер failed; сессию нужно прекратить,
поскольку точное число потреблённых байтов уже невозможно вернуть.

**Поддерживаемый профиль VT**

Текстовое событие содержит одну корректную скалярную величину Unicode.
Графемы объединяет текстовая подсистема после вставки. Alt хранится как
наблюдаемый модификатор. Декодер не нормализует текст и не считает его ширину.
UTF-8 управляющих скаляров сохраняется как данные.
После ESC символы `[ O ] P X ^ _` зарезервированы под ввод последовательности.

| Кодирование | Событие |
| --- | --- |
| ASCII 0x20–0x7e, корректный UTF-8 | Скаляр текста |
| ESC и скаляр до срока | Текст с Alt |
| 0x09, 0x0d, 0x08/0x7f | Tab, Enter, Backspace |
| Остальные C0 кроме ESC | Ctrl + скаляр byte+0x40; NUL → Ctrl+@, LF → Ctrl+J |
| ESC и C0/DEL | Соответствующая клавиша с Alt |
| Один ESC; два ESC | Escape по сроку/EOF; первый Escape сразу |
| CSI/SS3 A B C D H F | Up, Down, Right, Left, Home, End |
| CSI/SS3 P Q R S | F1–F4 |
| CSI n~, n=1/7,2,3,4/8,5,6 | Home, Insert, Delete, End, PageUp, PageDown |
| CSI n~, n=11,12,13,14,15,17,18,19,20,21,23,24 | F1–F12 |
| CSI Z | Shift+Tab |

CSI/SS3 с буквой принимает отсутствие параметров, `1` или `1;m`.
Тильда принимает `n` или `n;m`. Для m=1..8 биты m−1: 1 Shift, 2 Alt, 4 Control.
Пустые числовые поля отклоняются. Традиционные Ctrl-I/Tab, Ctrl-M/Enter,
Ctrl-H/Backspace, Ctrl-[/Escape и ESC+символ/Alt+символ неразличимы.
Физические левый/правый модификаторы и AltGr не выводятся из этих байтов.

При `sgr_mouse=true` поддерживается `CSI <b;x;y M/m`: координаты 1..2147483648
преобразуются в `int32` с отсчётом от нуля путём вычитания единицы. Биты кнопки 0..1: левая/средняя/правая/нет;
4/8/16 — модификаторы, 32 — движение, 64 — колесо. Направления 64..67:
вверх/вниз/влево/вправо. Неизвестные биты, wheel+motion, отпускание wheel/motion
и переход без кнопки кроме движения отклоняются. Расширенные кнопки, пиксели,
8-битный CSI, X10/1005/1015 и ответы OSC/DCS не поддерживаются.

**Время, границы и восстановление**

Время — unsigned 64-битные монотонные миллисекунды вызывающего кода.
По умолчанию ESC/Alt ждёт 30 мс, CSI/SS3/строка или обычный скаляр — 1000 мс,
вставка — 30000 мс от полного начала. Поступление байтов срок не продлевает.
Сложение насыщается UINT64_MAX; `now >= deadline` истекает до обработки байтов.
Неполный Alt даёт Escape и сообщение о хвосте; обычный неполный UTF-8 — сообщение
и возврат к началу. Незакрытые последовательности, строки и вставка при таймауте
завершают поток ошибкой, предотвращая интерпретацию хвоста как команд.

По умолчанию CSI/SS3 ограничены 64 байтами, 16 параметрами и 10 цифрами на
параметр; пределы можно уменьшать. Вставка — 1 MiB; ноль допускает пустую.
Один next принимает до 4096 байтов. Хранение ограничено вставкой, пятью
предполагаемыми байтами конца и фиксированным буфером 64 байта, плюс ёмкость
аллокатора и возвращённое событие. Сложность памяти O(лимит вставки).

Ошибочный UTF-8 оставляет первый неподходящий продолжающий байт для повторного
разбора; неверный начальный байт потребляется. Ошибка грамматики потребляет
ошибочный байт. Переполнение выдаёт одно сообщение и пропускает остаток до
финала. Неизвестные завершённые последовательности не возвращаются как клавиши.
OSC/DCS/SOS/PM/APC пропускаются до ST (`ESC \`), OSC также до BEL.
Сообщения хранят тип и полуоткрытый диапазон байтов сессии без ANSI-фрагмента.
EOF закрывает неполное состояние с сообщением.

**Ответы терминала и вставка**

`expectReplies` задаёт окно [начало, срок), поколение и по одному ответу каждого
разрешённого вида; допускается только в начальном состоянии без события.
Декодер запросов не посылает. Поддерживаются DA `CSI ?p[;p...]c` и CPR
`CSI row;column R` с положительными параметрами и проверкой int32.
Начальный ESC и финал должны попасть в окно. Совпавший вид расходуется один раз.
В окне CPR имеет приоритет над modified F3; вне окна `CSI 1;2R` — Shift+F3.
Поколение связывает запрос с ответом, но байты не подтверждают подлинность.

При `bracketed_paste=true` начало — CSI 200~, конец — точный CSI 201~.
Внутри значим только конец; остальные байты, включая неверный UTF-8 и NUL,
сохраняются как данные. Первый подтверждённый байт сверх лимита удаляет весь
текст и выдаёт одно сообщение; хвост пропускается до конца под исходным сроком.
Предполагаемый префикс конца считается данными после несовпадения.
Поддельный CSI 201~ неотличим от настоящего конца. Получатель обязан проверять
текст и не пересылать сырой ввод вставки в терминал, shell или диспетчер команд.

Источники: [xterm](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html),
[Windows VT input](https://learn.microsoft.com/en-us/windows/console/console-virtual-terminal-sequences#input-sequences),
[UTF-8 Unicode](https://www.unicode.org/versions/latest/core-spec/chapter-3/#G7404).

</details>
