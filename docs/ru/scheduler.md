# Планировщик UI и ограниченные очереди {#scheduler-ru}

[Подробная английская версия](../scheduler.md)

[`Scheduler`](../../include/portals/scheduler.hpp) позволяет выполнить действие позже на потоке UI и доставить данные рабочего потока. Например, через секунду можно убрать уведомление, а результат расчёта передать обработчику, обновляющему модель. Он не создаёт рабочий поток: долгий расчёт внутри callback задержит интерфейс.

Этот самостоятельный пример планирует действие через одну секунду, обслуживает планировщик и печатает сообщение. `at` принимает абсолютное время в миллисекундах; стандартные часы — `steady_clock`. Токен `timer` и [область отмены](glossary.md#glossary-cancellation-ru) `scope` должны жить до выполнения.

```cpp
#include <portals/scheduler.hpp>
#include <chrono>
#include <iostream>

int main() {
  using namespace portals;
  using namespace std::chrono;

  auto scheduler = Scheduler::create();

  if (!scheduler) {
    return 1;
  }

  auto scope = (*scheduler)->makeScope();

  if (!scope) {
    return 1;
  }

  constexpr auto DELAY = seconds(1);
  const auto deadline = duration_cast<milliseconds>(steady_clock::now().time_since_epoch() + DELAY);
  bool ready = false;
  auto timer = (*scheduler)->at(*scope, static_cast<SchedulerTime>(deadline.count()),
                               [&ready] {
                                 ready = true;
                               });

  if (!timer) {
    return 1;
  }

  while (!ready) {
    if (!(*scheduler)->waitFor(duration_cast<milliseconds>(DELAY)) || !(*scheduler)->dispatch()) {
      return 1;
    }
  }

  std::cout << "Ready after one second\n";
}
```

В приложении Portals цикл уже обслуживает `Application::scheduler()` между кадрами: свой цикл `waitFor`/`dispatch` не добавляйте. Планируйте через существующий scheduler на UI-потоке, храните токен и область до выполнения или отмены. Для callback виджета есть `WidgetTree::at(node, deadline, callback)`: удаление узла отменяет вызов. Callback, меняющий модель или текст, использует обычный проверяемый API и его инвалидацию. Fluent-оператора таймера у `ui::Scene` пока нет.

<details>
<summary>Справка: очереди, отмена и часы</summary>

`Scheduler` привязан к потоку, вызвавшему `create`. Приложение вызывает `dispatch()` между кадрами. Обработчики применяют изменения и запрашивают перерасчёт компоновки или отрисовку. Планировщик не создаёт фоновый исполнитель, не изменяет виджеты и не выводит данные в терминал. Во время компоновки и рисования вызывать `dispatch` и `waitFor` запрещено. Повторный вызов диспетчеризации или ожидание из обработчика возвращает `REENTRANT_DISPATCH`.

**Очереди и перегрузка**

`SchedulerOptions` задаёт независимые положительные вместимости очередей `CONTROL` и `DATA`: по умолчанию 32 и 256 записей. За один вызов допускается до 32 обработчиков каждой очереди и 32 таймеров. Общий лимит живых подписок и таймеров — 256. Хранилища очередей и индекс регистраций резервируются при создании. Публикация не выделяет память планировщика. Лимиты учитывают число владельцев объектов; объём снимков и данных, удерживаемых приложением, ограничивает само приложение.

Каждый `dispatch` обслуживает очередь управления, наступившие таймеры, затем очередь данных. У каждой категории свой лимит, поэтому поток данных и таймеров сохраняет долю обслуживания управления. Принятая запись `CONTROL` обслуживается максимум за `ceil(control_capacity / control_budget)` вызовов, если её не отменили и планировщик не остановили. При настройках по умолчанию вся очередь управления обслуживается за один вызов. Новые записи могут исполниться в текущем вызове, пока остаётся лимит. Обработчики должны быстро завершаться: число вызовов ограничено, длительность пользовательского кода зависит от приложения.

Клавиши, изменение размера и обычные команды выхода используют `CONTROL`. Заполнение любой очереди возвращает `WOULD_BLOCK`. Повторите отправку после обслуживания очереди или сообщите о перегрузке. `requestStop()` использует отдельный флаг и сигнал пробуждения, не занимает запись и работает при заполненных очередях. Он сразу запрещает новые публикации. Уже выбранный обработчик завершится; следующие вызовы из очереди не начнутся.

Политика переполнения по умолчанию — `REJECT`. Для соединений `DATA` можно выбрать `REPLACE_LATEST`: очередной снимок заменяет единственный ожидающий снимок этого отправителя, сохраняя его позицию в очереди. Другие отправители не затрагиваются. Замена возможна при заполненной очереди; отправитель без ожидающей записи получит `WOULD_BLOCK`. Для `CONTROL` эта политика запрещена.

Замену применяют к полному снимку отображаемого состояния после обработки всех исходных событий. Исходные тики, последовательные изменения и необработанные ошибки провайдера терять нельзя. Включите статус в полный снимок либо используйте отказ с повторной отправкой.

**Владение и отмена**

`connect<T>` создаёт `SchedulerConnection<T>`. Контроллер сохраняет перемещаемую `Subscription`, рабочий поток получает копию `Publisher<T>`. Публикация передаёт `shared_ptr<const T>`. Производитель должен предоставить снимок с собственным хранением данных и неизменяемой достижимой памятью, включая доступ через другие ссылки. Обработчик получает ещё одного владельца и может сохранить его. Последний владелец снимка может уничтожиться в потоке производителя или UI, поэтому снимок не должен владеть ресурсами, требующими уничтожения в UI-потоке. Захваты обработчика освобождаются в UI-потоке.

Уничтожение или отключение подписки и закрытие её `UiScope` запрещают новые вызовы, включая уже поставленные в очередь. Закрытие области сначала логически отключает все регистрации и только затем освобождает захваты; правило сохраняется при повторном входе из их деструкторов. Исполняющийся обработчик удерживает захваты до возврата. Самозакрытие не ожидает завершения рабочего потока. Ссылочные захваты требуют внешнего владельца, живущего достаточно долго. Деструкторы снимков и захватов выполняются вне мьютекса очереди.

Области и подписки освобождаются в UI-потоке до уничтожения `Scheduler`. Их уничтожение или перемещающее присваивание в другом потоке завершает процесс. Явные `close` и `disconnect` возвращают `WRONG_THREAD` без изменений. Закрытие идемпотентно; область и её подписки можно освобождать в любом порядке. Идентификаторы не переиспользуются, их исчерпание сообщается как ошибка.

`Publisher` может пережить планировщик: он удерживает закрытое состояние канала без захватов обработчиков, а поздняя публикация возвращает `CLOSED`. Запрос остановки не подтверждает завершение рабочих потоков. Приложение останавливает их и ожидает завершения вне компоновки и рисования, сохраняя память провайдера до конца работы. UI-вызов `stop`, следующий `dispatch` после запроса остановки из рабочего потока или уничтожение планировщика освобождает обработчики. `waitFor` только наблюдает остановку. Уничтожайте планировщик в потоке владельца вне обработчиков; он сам не ожидает чужую работу.

**Таймеры и часы**

`at(scope, absolute_milliseconds, callback)` регистрирует одноразовый таймер с теми же правилами отмены через область действия. Таймеры исполняются по сроку, при равных сроках — по порядку регистрации. Готовые таймеры сверх лимита остаются ожидающими. Приложение явно назначает следующий абсолютный срок периодической работы и выбирает политику перегрузки. Периодическая симуляция с фиксированным шагом и проверка ревизий модели относятся к последующим слоям.

Необязательный `SchedulerClock` предоставляет заимствованные монотонные часы в миллисекундах. Функция чтения должна быть потокобезопасной, неблокирующей, без повторного входа и `noexcept`; контекст должен жить дольше планировщика. По умолчанию используется `steady_clock`. Часы читаются под мьютексом очереди для временных меток и таймеров; закрытые отправители к ним не обращаются. Тесты могут изменять искусственное время и вызывать `dispatch` без сна. Изменение часов из другого потока требует синхронизации и `Publisher::wake()` для пробуждения уже начатого ожидания.

`waitFor` выполняет ограниченное ожидание на условной переменной в UI-потоке. Оно завершается при поступлении работы, сроке таймера, явном пробуждении, остановке или реальном тайм-ауте. Максимальная реальная длительность независима от искусственных часов. Сигналы пробуждения объединяются в один одноразовый сигнал: уведомление непосредственно перед ожиданием сохраняется. Приложение согласует терминальный ввод через свой адаптер; системного объединённого ожидания терминала этот API не предоставляет.

**Ошибки и метрики**

Создание отклоняет нулевые и непредставимые вместимости и преобразует ошибки выделения памяти в `NO_MEMORY`. Регистрация также обрабатывает нехватку памяти при принятии обработчика. Выделение памяти при вычислении аргументов до входа в функцию остаётся вне этой границы. Другие исключения пользовательского копирования или перемещения обработчика распространяются без установки регистрации. Исчерпание лимита регистраций возвращает `WOULD_BLOCK`; чужая область и неверный поток сообщаются отдельно.

Исключение обработчика отключает его подписку и удаляет её ожидающие записи. Планировщик перехватывает исключение, увеличивает счётчик ошибок и вызывает необязательный заимствованный обработчик ошибок `noexcept` в UI-потоке. Результат `dispatch` сообщает число ошибок и без такого обработчика. Уже выполненные побочные эффекты приложения сохраняются.

`metrics()` возвращает потокобезопасную копию показателей. Для каждой очереди доступны текущая и пиковая занятость, число принятых, отклонённых, заменённых, доставленных и отменённых записей, а также последняя, максимальная и суммарная задержка. Отдельно учитываются циклы, таймеры и ошибки обработчиков. Задержка отсчитывается от последней замены в миллисекундах заданных часов. Счётчики насыщаются на `UINT64_MAX`; история отдельных измерений внутри планировщика не накапливается. Процентили и длительность обработчиков приложение измеряет отдельно.

См. правила [condition_variable](https://eel.is/c++draft/thread.condition.condvar) и [shared_ptr](https://eel.is/c++draft/util.smartptr.shared). Системные сбои стандартных средств синхронизации обрабатываются по стандартным правилам исключений или завершения процесса. Portals не эмулирует работу неисправного системного мьютекса.
