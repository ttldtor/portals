# Undo и Redo в редакторе {#editor-history-ru}

[Подробная английская версия](../editor-history.md)

Undo/Redo отменяет и повторяет изменения **текста и выделения одного редактора**. Подтверждение (`EditMode::ON_COMPLETION`) определяет, когда черновик попадает в модель; оно не хранит список прошлых значений. История автодополнения или введённых команд этим API не предоставляется. `ui::lineEdit` создаёт привязку и историю автоматически — отдельный `TextHistory` для обычного поля не нужен. Введите текст и нажмите Ctrl+Z или кнопку Undo; F10 закрывает пример.

Каждый связанный [`LineEdit`](../../include/portals/line_edit.hpp) имеет собственную историю. По умолчанию включены 128 общих групп Undo/Redo и 1 МиБ хранимых снимков. `LineEditOptions::history` задаёт лимиты и группировку. Общие транзакции сцены этим механизмом не предоставляются.

```cpp
#include <portals/ui.hpp>

int main() {
  using namespace portals;

  ui::Ref<LineEdit> name;

  auto scene = ui::scene(ui::vbox(
    ui::lineEdit(name, "Ada"),
    ui::button("Undo",
               [name] {
                 return name.undo();
               }),
    ui::button("Redo",
               [name] {
                 return name.redo();
               })));

  return scene
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Undo восстанавливает владеющий текст, курсор и выделение на полных границах графем с политикой ширины и лимитами редактора.

По умолчанию Undo сразу публикует восстановленное значение. В отложенных режимах восстановленный черновик ждёт того же подтверждения, что и обычный ввод; см. [режимы подтверждения](line-edit.md).

**Группы и публикация**

Последовательный ввод, Backspace и Delete образуют отдельные группы своих типов. Замена выделения, вставка, вырезание и программная запись — отдельные операции. Навигация, выделение, потеря фокуса, Enter, Escape и `stopGrouping()` закрывают группу. Подтверждение сохраняет историю. Равное обычное изменение сохраняет Redo. Пустой Undo/Redo закрывает группу без обработчика, уведомления и перерисовки.

По умолчанию действует `ProgrammaticChange::RECORD`; `LineEditOptions::programmaticChange` меняет его для программных изменений. Объект `field.text(RESET_BASELINE)` сохраняет политику по значению, включая `+=`, `append` и присваивание результата `+`. RESET очищает оба стека после принятия базового значения даже при равных байтах. При равном тексте модель не публикуется и кадр не запрашивается.

Текст, выделение и история принимаются согласованно до валидатора и наблюдателей модели. Ошибка памяти, текста, лимита или дерева до принятия сохраняет все три и Redo. Слишком большая целая группа отклоняется: ввод возвращает `LIMIT_EXCEEDED`, программная запись — `WOULD_BLOCK`. При необходимости удаляются целые старые группы. См. [учёт памяти истории](text-history.md).

В IMMEDIATE восстановленный текст сразу проверяется и публикуется; ON_COMPLETION публикует при потере фокуса, Enter или активации; EXPLICIT — при Enter или активации. Семантический отказ оставляет обратимый видимый черновик с `VALIDATION_FAILED`. Исключение валидатора или ошибка публикации сохраняет принятую историю и текст, возвращает техническую ошибку и подробный `LineEditResult`. Потеря уведомления не требует повторять Undo.

**Ревизии и доступность**

Собственная публикация продвигает исходную ревизию без очистки истории. Внешняя новая ревизия чистого поля принимает последнее значение и очищает историю даже при тех же байтах. Обнаружив её, Undo/Redo принимает новое состояние и завершается без старой операции.

Внешний конфликт изменённого поля сохраняет черновик и историю. Редактирование возможно, Undo/Redo возвращает `WOULD_BLOCK` с `CONFLICT` до изменения. Escape принимает модель и очищает историю; явный RESET выбирает новое базовое значение. Автоматического переноса истории нет. В IMMEDIATE Escape сохраняет ранее опубликованные изменения.

Привязка и `ui::Ref<LineEdit>` предоставляют `undo`, `redo`, `stopGrouping`, `canUndo`, `canRedo` и `historyAvailability`. Логические запросы при ошибках возвращают false без сообщения и изменения. Проверенный запрос возвращает `HistoryAvailability` либо исходную ошибку. Скрытый или отключённый предок, режим чтения, пустая или отключённая история и несовпадение ревизии делают команды недоступными. Отключение и режим чтения дают `WOULD_BLOCK` до принятия.

`readOnly` по умолчанию false. Он блокирует ввод, удаление, вырезание и вставку без вызова буфера обмена и валидатора. Навигация, выделение и копирование сохраняются. Явные программные изменения разрешены с настроенными RECORD/RESET и режимом публикации.

**Сочетания клавиш**

Ctrl+Z вызывает Undo, Ctrl+Y и Ctrl+Shift+Z — Redo. `historyShortcuts` задаёт другие сочетания, nullopt отключает отдельное. Модификаторы совпадают точно, регистр ASCII нормализуется, PRESS/REPEAT принимаются, RELEASE игнорируется. История приоритетнее пересекающихся Ctrl+A/C/X/V. Пустая совпавшая команда обрабатывается локально без передачи выше и обработчика результата.

Допустимы CHARACTER с корректным ненулевым скаляром, INSERT, PAGE_UP/DOWN и F1–F12; несимвольные клавиши требуют нулевого скаляра. Enter, Escape, Tab, стрелки, Home/End, Backspace/Delete и неверные значения отклоняются при привязке с `INVALID_ARGUMENT`: их резервирует маршрутизатор. Пересечение Undo и Redo запрещено. Ctrl+Shift+Z требует отдельного Shift от адаптера; Ctrl+Y поддерживается VT-вводом.

**Результаты и диагностика**

Команды привязки возвращают `expected<void, TreeError>`, команды ссылки — владеющий `EditorCommandResult` со сведениями о фактической регистрации собственной ошибки в слабом сборщике сцены. Он не удерживает виджет. Результат проверяется логически или через `.result()`.

`ui::button` и `scene.onClick` принимают `std::function<EditorCommandResult()>`, позволяя `return field.undo()`. Ошибка, уже зарегистрированная в том же сборщике, повторно не записывается. Другие команды, исключения и сборщики различаются. Извлечение `.result()` теряет эти сведения; возврат через обычный expected-обработчик может сообщить ошибку повторно.

Отсутствующая или просроченная ссылка возвращает `CLOSED`, чужой поток — `WRONG_THREAD` без небезопасного сообщения. Принятый обработчик удерживает общее состояние привязки при удалении. Доступ к сцене после пользовательского вызова проверяет слабое время жизни. История владеет текстом; аргументы и функции разрешения могут бросить до вызова, внутренние ошибки памяти типизированы.
