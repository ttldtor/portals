# Запускаемые примеры {#examples-ru}

[Примеры контролов](control-examples.md) показывают защищённый пароль и индикатор загрузки полными программами на C++ и с ресурсным описанием сцены.

[Английская версия](../examples.md)

Начните с минимальной программы обработчиков нажатия, затем откройте галерею.
Обе используют владеющую декларативную сцену: описание контролов, обработчики
и заключительный `ui::runApp()`. Библиотека собирает типизированные ошибки
подготовки и сообщает об ошибках выполнения после восстановления терминала.

Соберите проект с `PORTALS_BUILD_EXAMPLES=ON`. Публичные программы открывают
терминал. Конечные сценарии, терминалы воспроизведения и нагрузочные проверки
находятся в `tests/` и `tools/benchmarks/` отдельно от публичных точек входа.

Галерея и dashboard содержат кнопку **Themes** и стандартное сочетание
`Ctrl+K, Ctrl+T`. Селектор показывает предварительный вариант темы; Apply
подтверждает выбор, Cancel возвращает прежнюю тему. F2 сохраняет быстрое переключение.

## Первая полная программа {#first-complete-program-ru}

Полная программа обработчиков нажатия содержит всю
программу: Add Hello добавляет отменяемое изменение, F10 запрашивает выход.
В ней нет частных вспомогательных файлов, ручных токенов привязки, stop_source
или цикла синхронизации отображения.

```cpp
// Copyright (c) 2026 ttldtor.
// SPDX-License-Identifier: BSL-1.0
#include <portals/ui.hpp>

/** @brief Run a minimal lazy scene with a late click handler.
 * @return Zero on success, one on a typed setup/runtime failure
 * after library cleanup/reporting.
 * Click Add Hello to append one undoable text change; F10
 * quits. This minimal program defines no CLI options.
 * The standard runner owns terminal restoration.
 */
int main() {
  using namespace portals;

  ui::Ref<LineEdit> message;
  ui::Ref<Button> add;

  auto scene = ui::scene(ui::vbox(ui::lineEdit(message, ""),
    ui::button(add, "Add Hello")));

  return scene
    | ui::onClick(add,
                  [message] {
                    message.text() += "Hello!";
                  })
    | ui::onKey(key::F10, ui::quit)
    | ui::runApp();
}
```

`ui::quit` принимается как команда `ui::onKey`; внутри допущенного обработчика
`ui::quit()` завершает текущую сцену. Ссылки наблюдают контролы и не продлевают
их жизнь. Подробности — [параметры и время жизни обработчиков](declarative-ui.md#pipe-click-handlers-ru).

## Темы и прикладные стили

Публичные примеры используют стандартный runner и стандартные метаданные слоёв стилей.
Явные имена источников, экспорт трассировки, часы replay и проверки транспорта
относятся к диагностическим примерам и тестам; для обычной формы они не нужны.

Галерея и собственный виджет принимают `--theme NAME`, `--ansi16` и `--help`.
Имена тем: `modern` по умолчанию, `turbo`, `nord`, `gruvbox`, `tokyo-night`,
`catppuccin-latte`. F2 проходит их по кругу. Последние четыре используют цвета
Textual, а не полное оформление его виджетов. ANSI16 кодирует цвет в палитре
из шестнадцати цветов, внешний вид которой задаётся терминалом.

Галерея — функция `gallery::form(ui::opts(options))`; стационарный класс формы
не требуется. [Объявление Lyra](#gallery-sources-ru) связывает
`-t`/`--theme` и `--ansi16` с настройками вызывающего кода. Заключительный этап
`ui::runApp(argc, argv, ui::lyra::cli(lyraCli))` разбирает аргументы до настроек
приложения, монтажа и захвата терминала. Справка возвращает 0, неверные аргументы —
2 с владеющим сообщением ошибки. Настройки должны пережить синхронный запуск.
Точка входа подключает `portals::lyra`; форма использует основной API сцены.
Подробности — [командная строка](cli.md).

```text
portals_gallery --theme nord --ansi16
portals_gallery --help
```

Для этапов стилей подключите `<portals/ui_style.hpp>`. Тема занимает слой темы.
Постоянные правила приложения добавляются через
`scene | ui::style(add, "* { bold: true; }")` и сохраняются при смене темы.
Файловый источник передаётся как `ui::file(path)` тому же этапу стилей.
[Слои стилей](style-layers.md) описывают приоритеты, ошибки и бюджеты.

Сейчас PSS задаёт конкретные значения. `$name` времени выполнения, `theme.text`,
выражения размера содержимого и импорт внешних форматов тем запланированы.
Общий движок эффектов, теней и произвольных рамок этими примерами не предоставляется.

## Компактные контролы

[Форма с рамкой](#compact-framed-form-ru) сочетает `ui::border`,
`ui::gauge`, `ui::plainButton` и `.width(24)`. Обработчик добавляет отменяемое
изменение текста; стиль по Ref действует только на кнопку Add. F10 и Ctrl+C
запрашивают штатное завершение. В примере нет парсера, эмулятора терминала
и собственной реализации виджета. Полные варианты с методами и цепочкой,
обрезка содержимого и проверяемые ограничения описаны в
[компактных примитивах](compact-primitives.md).

Dashboard использует `.flexX()` у поля и `.flexY(2)` / `.flexY()` у таблицы
и графика. Это декларации для существующего решателя компоновки; время жизни
поставщика и модели остаётся отделено от композиции интерфейса.

## Данные и загрузка dashboard

```text
portals_dashboard --rate 10000 --fps 30 --rows 1000000 --seed 42
portals_dashboard --rate 0 --delay-ms 250 --ansi16 --ascii
portals_dashboard --mode replay --duration-ms 5000
```

[Композиция UI](#dashboard-sources-ru) отделена от
[поставщика](#dashboard-sources-ru). Записанная лента — режим
данных поставщика; терминал воспроизведения и отдельный цикл событий не нужны.
Поставщик владеет ограниченными запросами страниц, повторами и отменой;
его остановка выполняется до удаления модели сценой. Размеры таблицы и графика
определяются компоновкой.

`--rate` принимает 0..10000 запланированных тиков/с; ноль показывает простой
и отложенную навигацию без обновлений цен. `--fps` принимает 1..1000 кадров/с.
`--rows` задаёт 1..1000000000 логических инструментов без виджета на каждую строку.
`--seed` задаёт синтетическую ленту. `--mode synthetic|replay` выбирает источник.
Лента `examples/replay/data.hpp` встроена в программу и циклически повторяет
16 цен: запуск из другого каталога не требует файла данных или сети.

`--delay-ms` задаёт задержку новой страницы 0..60000 мс. Первая страница готова
сразу. Полезная страница сохраняет срок загрузки при замене запроса представлением.
Промах кэша может показать заглушку; отпускать стрелку для завершения загрузки
не требуется. Таблица и график запрашивают диапазоны независимо и разделяют
ограниченное состояние доступности страниц.

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `--page-rows N` | 256 | Логические строки страницы. |
| `--cache-pages N` | 8 | Максимум записей доступности, включая первую страницу и ожидающую работу. |
| `--cache-bytes N` | 262144 | Бюджет учитываемых данных строк одного снимка в байтах. |
| `--load-jobs N` | 4 | Максимум одновременных отложенных загрузок. |
| `--prefetch-pages N` | 1 | Соседние страницы по направлению навигации; ноль отключает предзагрузку. |

Положительные размеры должны помещаться в `size_t`. Неверные или слишком малые
сочетания отклоняются при подготовке; диапазон не готовится, если окно не помещается
в эффективный бюджет. Учёт взимает полную страницу `ModelRow<Quote>`, даже для
последней короткой страницы. Накладные расходы аллокатора и старые снимки модели
не учитываются: это не предел памяти процесса. Спрос приоритетнее предзагрузки.
Отдельный конечный тест печатает попадания/промахи, полезные/отменённые задания
и максимальное использование страниц, заданий и байтов после остановки.

Поставщик кэширует доступность стабильных логических инструментов. Каждый снимок
генерирует значения заново из своего агрегата и ревизии. Повторное использование
произвольных результатов между ревизиями требует отдельного контракта источника.
Готовность публикуется и при `--rate 0`; повторных публикаций и перерисовок нет.
Полный кэш модели не создаётся.

`--pump-budget` задаёт 1..10000 тиков на обработчик, по умолчанию 512.
Поставщик учитывает каждый созданный тик в OHLC; объединяются только неизменяемые
обновления отображения. Запоздавший таймер продолжает с первого несозданного тика
в ограниченных обработчиках. Запланированные и созданные тики различаются;
остановка отменяет оставшуюся генерацию. Поставщик работает в UI-потоке,
поэтому пример не измеряет отдельный рыночный рабочий поток.

Сцена закрепляет модель один раз на кадр для таблицы и графика, включая повторы
компоновки. Инструменты используют общий OHLC с детерминированным смещением цены.
`--duration-ms` принимает 0..3600000 мс; ноль оставляет программу интерактивной.
Остановка обслуживается при следующем вызове поставщика. Зависание терминального
приложения или записи может продлить реальное время очистки.

## Диагностика и проверка

Трассировку запускает тестовая программа, собранная с `PORTALS_BUILD_TESTS=ON`:
`portals_dashboard_check --rate 0 --trace trace.json`. Переведите фокус на Inspect
и нажмите Enter: присваивание прежнего значения отличает `handler_returned`,
`value_unchanged` и `frame_not_requested`. Экспорт выполняется после восстановления,
ошибки файла сообщаются отдельно. Публичный dashboard не принимает `--trace`
или `--stress`. Смотрите [диагностику](diagnostics.md).

Публичные программы не имеют режима `--check`. Проверочные точки входа находятся
в `tests/examples/`; терминал в памяти — в `tests/support/examples/replay/terminal.hpp`.
Они завершаются автоматически и проверяют конечные сценарии, а внешний вид
и восстановление настоящего терминала требуют отдельной проверки.

## Примеры из руководств

Все небольшие программы из этих руководств находятся в `docs/examples`. Из корня исходников Portals:

```powershell
cmake -S docs/examples -B build/guide-examples -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/guide-examples
```

Запустите `build/guide-examples/docs_basic.exe` в Windows или `build/guide-examples/docs_basic` в Linux/macOS. F10 закрывает интерактивные программы. Для сценариев редактора см. [демонстрацию истории](editor-history-demo.md).

Некоторые программы руководств имеют отдельные цели корневой сборки при
`PORTALS_BUILD_TESTS=ON`. Например, после конфигурации preset соберите пример
немодального диалога командой
`cmake --build build/windows-msvc-debug --target portals_docs_nonmodal_dialog`.
Остальные примеры можно собрать отдельным проектом руководств выше.


[Руководство по обычной прокрутке](scroll-controls.md) собирается в `guide_scroll_controls`:
восемь кнопок в рамке с заголовком и внешним размером 28×6, полосу на рамке,
wheel/key/drag и выход через Exit/F10.

[Вложенная форма настроек](scroll-controls.md#nested-scroll-areas-ru) собирается как

Она использует редактируемые поля, CheckBox с внутренним состоянием и две области `ON_FRAME`.

`ui::threeState()` с фиксированным циклом переключения и завершает работу через
`ui::runApp()`. [Полный исходник](controls.md#check-box-with-three-states-ru) приведён в руководстве; необязательный
[помощник группового обновления](controls.md#check-box-with-three-states-ru) сохраняет сведения о частичных отказах.
