# Ссылки, привязки и события {#bindings-guide-ru}

[Английская версия](../bindings-guide.md)

Начните с явного обработчика события и наблюдающей ссылки на контрол. Если нескольким
контролам нужно одно значение, которым владеет интерфейс, используйте управляемое
состояние. [Наблюдающая ссылка](glossary.md) `ui::Ref<T>` позволяет обращаться к объекту, но сама по себе не является подпиской
или реактивным выражением. Общее текстовое состояние поддерживают редакторы, подписи и кнопки.
Общее наблюдение и производные привязки — **TBD — M2**.

## Изменение текста по нажатию кнопки

В этой полной программе обработчик клавиши вызывает команду выхода текущей сцены.
Для выхода из обработчика используйте контекстный `ui::quit()`.

```cpp
#include <portals/ui.hpp>

int main() {
  using namespace portals;
  ui::Ref<LineEdit> field;
  ui::Ref<Button> append;
  auto scene = ui::scene(ui::vbox(
    ui::lineEdit(field, "initial"),
    ui::button(append, "Append")));

  return scene
    | ui::onClick(append,
                  [field] {
                    field.text() += "!";
                  })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Сцена монтирует весь [рецепт](glossary.md#glossary-recipe-ru), прежде чем публиковать ссылки и регистрировать обработчики
через цепочку операторов `|`. Захват `Ref` по значению не продлевает жизнь виджета или сцены. Рецепт
создаётся до входа в завершающий `runApp` и может выбросить исключение. Если создание
нужно выполнить внутри проверяемой границы ошибок, используйте запуск через фабрику.

## Что означает присваивание текста

Эти фрагменты предназначены для UI-обработчиков с успешно смонтированными ссылками:

```cpp
field.text() = "replacement";
field.text() += "suffix";
destination.text() = field.text();
```

Последняя строка один раз копирует текущий текст. Дальнейшие изменения источника не
обновляют получателя. `TextProperty` — объект доступа к тексту существующего контрола, а `Property<T>` — компонент,
который владеет значением и уведомляет об изменениях. Сходство имён не означает
одинакового поведения.

Для явной обработки ошибок сохраните результат операции:

```cpp
auto update = field.text().set("replacement");
auto accepted = update.result();
auto snapshot = field.text().get();
```

Проверьте `accepted` и `snapshot` перед чтением их значений. `get()` возвращает
собственные байты текста и не сообщает об ошибках автоматически. Изменение сохраняет
типизированные ошибки и, где это применимо, сообщает их живому сборщику ошибок сцены.
Если новый текст отклонён, прежний сохраняется. `+=` дописывает к полному черновику
или подписи, а не заменяет выделение редактора. Принимающий контрол по-прежнему
проверяет текст согласно своей политике ширины и ограничениям.

Внутри управляемого обработчика `ui::quit()` использует сцену, в контекст которой
вошёл обработчик; без текущей живой сцены это безопасная пустая операция. Вне этих
адаптеров используйте `ui::quit(scene.ref())` или проверяемый `SceneRef::quit()`, чтобы
явно указать владельца. Ни одна ссылка не продлевает жизнь сцены. См.
[контракт контекста сцены](declarative-ui.md).

## Общее управляемое значение

Создайте необязательное общее строковое состояние в фабрике сцены. Поле публикует
изменения согласно своему режиму редактирования; подпись и кнопка показывают
значение модели. Текст кнопки меняется вместе с ним, действие по-прежнему завершает
приложение. Ошибки создания состояния проходят через checked-фабрику в runner.

[Полный исходник](../examples/docs_state.cpp).

```cpp
#include <portals/ui.hpp>
#include <string>

int main() {
  using namespace portals;

  auto scene = ui::scene([](ManagedScene &owner) {
    return owner.state(std::string("Portals")).transform([](auto model) {
      return ui::vbox(
        ui::lineEdit(model),
        ui::label(model),
        ui::button(model, [] { ui::quit(); }));
    });
  });

  return scene
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

`ManagedState<T>` слабо наблюдает за `Property<T>`, которым владеет сцена. Чужая
сцена не может привязать этот handle. Операции выполняются в UI-потоке владельца;
для доставки из рабочего потока используйте publishers моделей или scheduler.
`snapshot()` владеет значением; `set()` возвращает исходную квитанцию commit/delivery.
Значение может сохраниться при отклонении части уведомлений. Равное присваивание
не создаёт ревизию и не повторяет отклонённую доставку.

Подписи получают новую ревизию в существующей подготовке dirty-кадра. Таймер
и ручная синхронизация представления не нужны. Прямое `caption.text() = ...`
меняет только подпись: модель и привязка сохраняются, новая ревизия модели
заменит эту подпись. Ошибка преобразования текста сохраняет прежнюю подпись
и типизированную причину; последующая явная подготовка может повторить latest value.
Неуспешная подготовка сохраняет прежнюю политику ошибки/остановки runner и не
обещает автоматического восстановления активного запуска.

Недопустимый промежуточный draft остаётся видимым в поле, не меняя общие подписи.
`ON_COMPLETION` и `EXPLICIT` откладывают публикацию по прежним правилам.
[Режимы редактора](line-edit.md) и [история](editor-history.md) сохраняются.

## Выбор интерфейса событий

Эти интерфейсы предназначены для разных способов регистрации:

| Регистрация | Аргументы обработчика | Назначение |
| --- | --- | --- |
| `ui::onClick(buttonRef, callback)` | Без аргументов или `ui::ClickParams&` | Упорядоченные обработчики цепочки, которыми владеет сцена |
| Рецепт `.onClick(callback)` / `Ref<Button>::onClick(callback)` | Без аргументов или `const ClickEvent&` | Существующий управляемый адаптер активации |
| `ui::onKey(selection, callback)` | Без аргументов или `const KeyEvent&` | Перехват исходного клавиатурного события до семантической маршрутизации |
| `ui::onLayout(ref, callback)` / `ref.onLayout(callback)` | Без аргументов или `const NodeGeometry&` | Уведомление после окончательной компоновки; регистрацией владеет сцена |
| `Property<T>::observe(receiver, callback)` | `W&`, `shared_ptr<const PropertyChange<T>>` | Запланированное уведомление о значении с проверкой получателя |
| `ManagedScene::onEvent(node, callback)` | Существующий контракт пользовательского события | Явная маршрутизация для собственного виджета |

Адаптеры click/key принимают `void`, `expected<T, TreeError>` или точный тип
подтверждения команды редактора. Возвращайте подтверждение undo/redo редактора
напрямую, чтобы сохранить происхождение диагностик. `Property::observe` возвращает
подписку, которой владеет вызывающий код; управляемые регистрации сцены сохраняют
свои токены сами. Если отбросить низкоуровневую подписку, соединение не сохранится.
Успешное значение expected игнорируется и уничтожается до выхода из обработчика.
Даже `false` означает обработанное действие; успешные квитанции проверяйте до возврата.

Пример более сложного обработчика нажатия:

```cpp
scene
  | ui::onClick(append, [field](ui::ClickParams &params) {
    field.text() += params.mods.has(key::SHIFT) ? "HELLO!" : "Hello!";
    params.stop();
  });
```

`ClickParams` предоставляет доступные только для чтения `target`, `mods`, `source`
и собственные метаданные исходного `event`. `stop()` останавливает последующие
обработчики той же синхронной активации. Всплывания событий по модели DOM здесь нет.
Обработчик заимствует контекст; копия контекста владеет снимком события, но остановка
копии не останавливает исходную цепочку. Семантические модификаторы не различают
физические левые и правые клавиши.

## Выбор фаз клавиатурного события

Во фрагментах ниже предполагаются уже существующие обработчики `move` и `stop`:

```cpp
scene
  | ui::onKey("W", move);
scene
  | ui::onKey(ui::repeat("W"), move);
scene
  | ui::onKey(ui::release("W"), stop);
scene
  | ui::onKey(ui::pressRepeat("W"), move);
```

Обычные строки сочетаний выбирают PRESS; явные помощники выбирают соответствующие
фазы. Перегрузка регистрации исходного `KeyEvent` сохраняет поведение PRESS+REPEAT.
Декодер VT-байтов предоставляет только PRESS и не синтезирует RELEASE. Побеждает
последняя подходящая регистрация клавиши. Обработчики нажатий, добавленные через оператор `|`,
выполняются в порядке регистрации. `"Ctrl+K+K"` означает Ctrl+K, затем Ctrl+K;
у `"Ctrl+K,K"` вторая K без модификатора. Альтернативы, тайм-аут последовательности,
приоритеты и ограничения описаны в [руководстве по вводу](input.md).

## Время жизни, ошибки и полные примеры

Ссылки публикуются после монтирования и становятся недействительными при удалении
их целей или закрытии сцены. Копирование не продлевает жизнь владельца. Выполняйте
операции в UI-потоке и вне запрещённых границ кадра и повторного входа. Обычные
захваты C++ по ссылке по-прежнему заимствуют объекты; перемещение сцены не исправит
захваченный `&scene`.

Полные программы и сценарии ошибок есть в
[клиенте текстового свойства](../../tests/package_consumer/text_property.cpp) и
[клиенте последовательностей клавиш](../../tests/package_consumer/shortcut_sequences.cpp).
[Справка по свойствам](property.md) определяет владение, [ограничение при перегрузке](glossary.md#glossary-backpressure-ru) и отмену;
[декларативная композиция](declarative-ui.md) — сообщения об ошибках запуска.

**TBD — M2:** автоматические и производные привязки. Будущий синтаксис
выражений, граф зависимостей и политика циклов не представлены как работающие функции.
Типизированные живые параметры темы уже доступны через явные UI-обновления;
см. [темы](themes-guide.md). Их наличие не означает автоматического связывания
переменных предметной области или переменных строкового PSS.

## Наблюдение за компоновкой

`ui::onLayout(ref, callback)` сообщает первоначальную итоговую геометрию и
последующие изменения после завершения кадра дерева. Изменение сцены в
обработчике запрашивает следующий кадр. `ref.geometry()` и `ref.size()`
возвращают проверяемые копии итоговых границ или локального размера. До
окончательной компоновки, для скрытого узла и после запроса новой компоновки
они возвращают `TreeError::INVALID_GEOMETRY`. Пример и правила доставки
описаны в [наблюдении за компоновкой](layout.md).
