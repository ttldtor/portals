# Ссылки, привязки и события {#bindings-guide-ru}

[Английская версия](../bindings-guide.md)

Явный обработчик события и наблюдающая ссылка на контрол позволяют связать
действие пользователя с изменением интерфейса. Если нескольким контролам нужно
одно значение, которым владеет интерфейс, его можно хранить в управляемом состоянии. [Наблюдающая ссылка](glossary.md) `ui::Ref<T>` позволяет обращаться к объекту, но сама по себе не является подпиской
или реактивным выражением. Общее текстовое состояние поддерживают редакторы, подписи и кнопки.
Управляемое наблюдение доставляет последние значения состояния.
Производные управляемые источники доступны через те же пути наблюдения и подписей.

## Изменение текста по нажатию кнопки

В этой полной программе обработчик клавиши вызывает команду выхода текущей сцены.
Из обработчика можно выйти с помощью контекстного `ui::quit()`.

```cpp
#include <portals/ui.hpp>

int main() {
  using namespace portals;
  ui::Ref<LineEdit> field;
  ui::Ref<Button> append;
  auto scene = ui::scene(ui::vbox(
    ui::lineEdit(field, "initial"),
    ui::button(append, "Append")));

  return scene
    | ui::onClick(append,
                  [field] {
                    field.text() += "!";
                  })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Сцена монтирует весь [рецепт](glossary.md#glossary-recipe-ru), прежде чем публиковать ссылки и регистрировать обработчики
через цепочку операторов `|`. Захват `Ref` по значению не продлевает жизнь виджета или сцены. Рецепт
создаётся до входа в завершающий `runApp` и может выбросить исключение. Если создание
нужно выполнить внутри проверяемой границы ошибок, для этого подходит запуск через фабрику.

## Что означает присваивание текста

Эти фрагменты предназначены для UI-обработчиков с успешно смонтированными ссылками:

```cpp
field.text() = "replacement";
field.text() += "suffix";
destination.text() = field.text();
```

Последняя строка один раз копирует текущий текст. Дальнейшие изменения источника не
обновляют получателя. `TextProperty` — объект доступа к тексту существующего контрола, а `Property<T>` — компонент,
который владеет значением и уведомляет об изменениях. Сходство имён не означает
одинакового поведения.

Результат операции позволяет обработать ошибки явно:

```cpp
auto update = field.text().set("replacement");
auto accepted = update.result();
auto snapshot = field.text().get();
```

Перед чтением значений `accepted` и `snapshot` требуется проверить успешность результатов. `get()` возвращает
собственные байты текста и не сообщает об ошибках автоматически. Изменение сохраняет
типизированные ошибки и, где это применимо, сообщает их живому сборщику ошибок сцены.
Технический отказ сохраняет прежний текст. Принятый текст редактора может затем
не пройти проверку содержимого или публикацию модели: новый черновик остаётся
видимым, `.result()` сообщает об успешном принятии текста, а `LineEditResult` —
о результате проверки или публикации. См. [результаты изменения текста](text-property.md).
`+=` дописывает к полному черновику
или подписи, а не заменяет выделение редактора. Принимающий контрол по-прежнему
проверяет текст согласно своей политике ширины и ограничениям.

Внутри управляемого обработчика `ui::quit()` использует сцену, в контекст которой
вошёл обработчик; без текущей живой сцены это безопасная пустая операция. Вне этих
адаптеров можно вызвать `ui::quit(scene.ref())` или проверяемый `SceneRef::quit()`, чтобы
явно указать владельца. Ни одна ссылка не продлевает жизнь сцены. См.
[контракт контекста сцены](declarative-ui.md).

## Общее управляемое значение

Фабрика сцены может создать необязательное общее строковое состояние. Поле публикует
изменения согласно своему режиму редактирования; подпись и кнопка показывают
значение модели. Текст кнопки меняется вместе с ним, действие по-прежнему завершает
приложение. Ошибки создания состояния проходят через checked-фабрику в runner.

[Полный исходник](../examples/docs_state.cpp).

```cpp
#include <portals/ui.hpp>
#include <string>

int main() {
  using namespace portals;

  auto scene = ui::scene([](ManagedScene &owner) {
    return owner.state(std::string("Portals"))
      .transform([](auto model) {
        return ui::vbox(ui::lineEdit(model),
          ui::label(model),
          ui::button(model, [] {
            ui::quit();
          }));
      });
  });

  return scene
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

`ManagedState<T>` слабо наблюдает за `Property<T>`, которым владеет сцена. Чужая
сцена не может привязать этот handle. Операции выполняются в UI-потоке владельца;
для доставки из рабочего потока доступны publishers моделей или scheduler.
`snapshot()` владеет значением; `set()` возвращает исходную квитанцию commit/delivery.
Значение может сохраниться при отклонении части уведомлений. Равное присваивание
не создаёт ревизию и не повторяет отклонённую доставку.

Подписи получают новую ревизию в существующей подготовке dirty-кадра. Таймер
и ручная синхронизация представления не нужны. Прямое `caption.text() = ...`
меняет только подпись: модель и привязка сохраняются, новая ревизия модели
заменит эту подпись. Ошибка преобразования текста сохраняет прежнюю подпись
и типизированную причину; последующая явная подготовка может повторить latest value.
Неуспешная подготовка сохраняет прежнюю политику ошибки/остановки runner и не
обещает автоматического восстановления активного запуска.

Недопустимый промежуточный draft остаётся видимым в поле, не меняя общие подписи.
`ON_COMPLETION` и `EXPLICIT` откладывают публикацию по прежним правилам.
[Режимы редактора](line-edit.md) и [история](editor-history.md) сохраняются.

## Наблюдение за управляемым значением {#managed-observation-ru}

`.observe(state, callback)` позволяет наблюдать за изменениями, когда контрол представляет управляемое
значение через код приложения. Сцена владеет подпиской и обработчиком. Для обычных
общих текстовых подписей доступны прямые формы `ui::label(model)` и
`ui::button(model)`.

[Полная программа](../examples/docs_observe.cpp).

Редактор публикует принятые строки, а подпись форматирует последнее принятое значение.
В этой полной программе можно менять текст и наблюдать за обновлением подписи.
F10 и кнопка Quit завершают приложение:

```cpp
#include <portals/ui.hpp>

#include <string>

int main() {
  using namespace portals;

  auto scene = ui::scene([](ManagedScene &owner) {
    return owner.state(std::string("Portals"))
      .transform([](auto model) {
        ui::Ref<Label> summary;

        return ui::vbox(ui::lineEdit(model),
          ui::label(summary, "")
            .observe(model,
              [summary](const std::string &value) {
                summary.text() = text("Accepted: {}", value);
              }),
          ui::button("Quit", [] {
            ui::quit();
          }));
      });
  });

  return scene
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

Первый вызов обработчика происходит при первой разрешённой подготовке после
монтирования всего рецепта и публикации всех `Ref`. Регистрация и настройка
описания его не вызывают. Захваченная ссылка на соседний контрол может находиться
до или после наблюдающего контрола в рецепте. Ошибка первого вызова относится к
фазе `PREPARE` и обрабатывается runner; успешное монтирование не отменяется.
При незавершённом монтировании сцены с управляемыми наблюдателями подготовка
или вход в запуск/сессию возвращает `WOULD_BLOCK`, в том числе при вложенном mount.

Явная регистрация `owner.observe(receiver, state, callback)` ограничивает доставку
управляемым узлом; `owner.observe(state, callback)` использует корень сцены.
Обе формы возвращают `std::expected<void, ManagedError>`. Неуспешная регистрация
не оставляет управляемую привязку или подписку. Получатель и состояние
должны принадлежать этой сцене; операции выполняются в её UI-потоке. Копируемый обработчик
принимает `const T&` и возвращает `void` или `std::expected<void, TreeError>`.
Во время вызова значение поддерживается неизменяемым владеющим снимком;
данные, которые должны жить дольше вызова, требуется скопировать.

Каждая регистрация отдельно хранит последнюю успешно обработанную ревизию.
Равное присваивание не вызывает повторную доставку. Обновления используют
существующий scheduler и могут объединяться до последнего состояния; API
предназначен для представления, а не для журнала всех событий. Если доставка
отклонена, существующая подготовка dirty-кадра повторяет её по последнему снимку.
Для повторной доставки уведомления нельзя снова вызывать `set()`:
значение уже зафиксировано. Ошибка
обработчика сохраняет исходного получателя, фазу и типизированную причину;
успешная ревизия не продвигается, исходное значение не откатывается. Ошибки коротких
изменений `Ref` внутри void-обработчика также поступают в коллектор диагностики
и обрабатываются прежней политикой остановки runner.

По умолчанию `ManagedOptions::maxObservers` ограничивает сцену 256 наблюдателями,
`maxObserversPerNode` — 64 на узел. Ограничения property и scheduler также действуют.
Положительный `maxObserverRecoveryPasses` по умолчанию равен 16. Если обработчики
продолжают менять уже просмотренные значения и восстановление не сходится за
это число проходов, подготовка возвращает `WOULD_BLOCK`; таймер или повторные
попытки в простое не создаются. После устранения причины можно явно повторить
подготовку.

Удаление получателя или закрытие сцены прекращает доставку. Сохранённый обработчик
не переключается на новый узел, занявший прежний slot. Захваты C++ по ссылке
по-прежнему заимствуют объекты. Удалить получателя из его обработчика допустимо;
уничтожать активную сцену из обработчика запрещено. Регистрация и повторный вход
в подготовку, запуск или закрытие во время восстановления отклоняются
существующими проверками.

## Вычисление производного значения {#managed-derivation-ru}

`owner.derive(input, transform)` вычисляет владеющее значение из одного
управляемого состояния или ранее созданного производного источника. Возвращаемый
`ManagedSource<T>` предоставляет владеющий неизменяемый `snapshot()`, без `set()`
и преобразования в изменяемое состояние. Его принимают подписи label/button и
управляемый `.observe`. Двусторонние привязки редактора и checkbox требуют
изменяемого состояния.

Редактирование имени обновляет
подписи label и кнопки. Нажатие кнопки или F10 закрывает сцену. Для сборки включите
`PORTALS_BUILD_TESTS=ON` и соберите `portals_docs_derive`. Ошибки подготовки передаются через
`expected` фабрики сцены существующему runner.

\include{lineno} docs_derive.cpp

Перед использованием `expected<ManagedSource<Out>, ManagedError>` требуется проверить успешность результата.
Начальное вычисление синхронно: успешный источник сразу доступен при монтировании.
При начальной ошибке output и подписка не публикуются; обработанная ошибка не
останавливает последующий корректный запуск. Функция получает `const In&` и
возвращает владеющий, сравнимый на равенство Out либо `expected<Out, TreeError>`.
Конструктор Out по умолчанию не требуется. Ссылки и известные заимствующие формы
результата, включая string_view, span, указатели и range views, отклоняются.
Для собственных типов сохраняется [контракт владения Property](property.md).

Преобразование должно быть чистым синхронным вычислением. Оно не должно менять
интерфейс, входить в lifecycle-операции или зависеть от ещё не опубликованных
ссылок на соседние контролы. Один сохранённый callable используется при начальном
и последующих вычислениях. Снимок входа живёт до конца вызова. Изменение объявленного
входа при начальном вычислении отклоняет регистрацию с `WOULD_BLOCK`; произвольные
побочные действия пользовательского кода отменить нельзя.

Изменения входа проходят через существующие Scheduler и ограниченное восстановление
при подготовке dirty-кадра. Равный результат отмечает обработанную ревизию входа,
не публикуя новую ревизию output. Закоммиченный output с отклонённым уведомлением
восстанавливается из снимка без повторного `set`. Чистые цепочки сходятся до обычной
синхронизации подписей в том же dirty-кадре, если вход изменился до подготовки.
Для поздних изменений из пользовательского `onPrepare` такой гарантии нет.

Ошибка во время работы сохраняет последнее корректное значение и ревизию output;
вход остаётся закоммиченным. Возвращённый TreeError сохраняется точно, bad_alloc
преобразуется в `NO_MEMORY`, остальные исключения функции — в `CALLBACK_FAILED`.
Ошибка и место регистрации доступны через результат runner и ограниченную
диагностику сцены; snapshot по-прежнему возвращает последнее корректное значение.
Действует существующая политика остановки; повтор возможен при последующей явной
подготовке. Close прекращает вычисления, а финальный snapshot доступен до уничтожения
сцены. Сохранённые неизменяемые снимки могут пережить владельца.

Каждый derive занимает существующий слот `maxStates` и одну подписку наблюдателя на корневом узле.
По умолчанию доступны 256 состояний, 256 наблюдателей сцены, 64 наблюдателя на узел,
64 endpoint у Property и 16 проходов восстановления. Ёмкость определяется оставшимся
пересечением этих ограничений. Необязательные параметры derive задают invalidation
output (PAINT по умолчанию либо LAYOUT) и PropertyOptions; NONE отклоняется.

Каждый output новый и доступен только для чтения, поэтому объявленный цикл зависимостей
создать нельзя. Произвольные побочные действия через захваты не отслеживаются;
несходимость ограничена `WOULD_BLOCK` и не является диагностикой скрытого цикла.
`Ref::draftText()`, `captionText()` и `committedText()` задают наблюдаемую текстовую
идентичность. Метод `snapshot()` копирует значение один раз. Фабрики подписей
подключают живое наблюдение: `ui::label(field.text())`, `ui::label(field.draftText())`
и `ui::button(field.committedText())`. В остальных случаях источник сам по себе
не становится реактивным входом derive; такой мост создаёт `owner.liveText(source)`.
Адаптеры текста к спискам через `ui::words` и
`ui::graphemes`, а также производные источники `RowCollection<T>` через `owner.model`
уже доступны; см. [примеры ниже](#live-text-transforms-ru).
Общие выражения привязок остаются в планах.

## Живые подписи и события редактирования {#live-editor-captions-ru}

Эта полная программа показывает видимый черновик рядом с принятым значением.
Для одной привязки подписей разверните короткую полную программу ниже.
Введите `invalid` и нажмите Enter: валидатор отклонит запись в модель, сохранив
введённый текст. Tab переводит фокус без подтверждения в режиме `EXPLICIT`.
Escape принимает актуальное значение модели. Кнопка добавляет отменяемое
программное изменение: живые подписи обновляются, но событие пользовательского
редактирования не возникает.

`field.text()` в фабрике подписи наблюдает видимый черновик. Явный источник
`draftText()` означает то же; `committedText()` читает последнее принятое значение
модели, включая внешние обновления при конфликтующем черновике. Обычный текст
создаёт независимую подпись. `destination.text() = source.text()` по-прежнему
копирует один раз. Для независимого владеющего значения используйте `snapshot()`.

Связи заполняются после создания всех контролов, даже если подпись объявлена раньше
источника. Связь с собой и объявленный цикл подписей отклоняют mount с
`INVALID_ARGUMENT`; неуспешный mount не публикует референсы. Наблюдения не удерживают
контролы, не перенаправляются при повторном использовании референса и отключаются
при удалении получателя. После удаления источника сохраняется последняя успешно
применённая подпись. Действуют существующие бюджеты наблюдений. Цепочки во время
работы используют ограниченное число проходов восстановления — по умолчанию 16;
при несходимости возвращается `WOULD_BLOCK` без бесконечной перерисовки.

`ui::onTextEdited(field, callback)` сообщает реальные изменения текста пользователем,
включая вставку, вырезание и Undo/Redo. Движение курсора, выделение, равная замена,
программная запись и отказ без изменения текста не вызывают событие. Отклонение
валидации после принятия черновика остаётся изменением текста. Escape вызывает событие
редактирования только при успешной отмене, реально изменившей видимый текст; события
завершения он не вызывает. Обработчик принимает
`const TextEditedEvent&` либо не принимает аргументов; `result` владеет исходным
результатом операции редактора.

`ui::onEditingFinished(field, callback)` принимает `const EditingFinishedEvent&`
либо не принимает аргументов. `reason` различает `ENTER` и `FOCUS_LOST`;
`outcome` принимает `APPLIED`, `UNCHANGED`, `DEFERRED`, `VALIDATION_REJECTED`,
`CONFLICT` или `FAILED`. Поле `result` сохраняет точный результат попытки,
включая отказ доставки уведомления; при уходе фокуса без попытки оно отсутствует.

| Граница | IMMEDIATE | ON_COMPLETION | EXPLICIT |
| --- | --- | --- | --- |
| Изменение текста пользователем | Принять черновик, попытаться записать | Сохранить черновик | Сохранить черновик |
| Enter | Попытаться записать | Попытаться записать | Попытаться записать |
| Уход фокуса, изменённый черновик | Сохранить, `DEFERRED` | Попытаться записать | Сохранить, `DEFERRED` |
| Уход фокуса, чистый черновик | `UNCHANGED`, без попытки | `UNCHANGED`, без попытки | `UNCHANGED`, без попытки |

Enter не переводит фокус. Событие завершения использует существующую попытку и
не вызывает валидатор повторно. Перевод фокуса во время доставки её результата
не повторяет подтверждение или событие завершения; независимый последующий уход
фокуса остаётся отдельным событием. Старый result-callback вызывается первым;
удаление прекращает оставшуюся доставку. Pipe-обработчики выполняются в порядке
регистрации и могут возвращать существующие checked-результаты действий. Их ошибки
попадают в обычную диагностику приложения. Общие лимиты двух видов событий:
256 обработчиков на сцену и 64 на поле; настройки —
`ManagedOptions::maxEditingHandlers` и `maxEditingHandlersPerNode`.

## Выбор интерфейса событий

Эти интерфейсы предназначены для разных способов регистрации:

| Регистрация | Аргументы обработчика | Назначение |
| --- | --- | --- |
| `ui::onClick(buttonRef, callback)` | Без аргументов или `ui::ClickParams&` | Упорядоченные обработчики цепочки, которыми владеет сцена |
| Рецепт `.onClick(callback)` / `Ref<Button>::onClick(callback)` | Без аргументов или `const ClickEvent&` | Существующий управляемый адаптер активации |
| `ui::onKey(selection, callback)` | Без аргументов или `const KeyEvent&` | Перехват исходного клавиатурного события до семантической маршрутизации |
| `ui::onLayout(ref, callback)` / `ref.onLayout(callback)` | Без аргументов или `const NodeGeometry&` | Уведомление после окончательной компоновки; регистрацией владеет сцена |
| Рецепт `.observe(state, callback)` / `ManagedScene::observe(receiver, state, callback)` | `const T&` | Представление последнего управляемого значения; регистрацией владеет сцена |
| `Property<T>::observe(receiver, callback)` | `W&`, `shared_ptr<const PropertyChange<T>>` | Запланированное уведомление о значении с проверкой получателя |
| `ManagedScene::onEvent(node, callback)` | Существующий контракт пользовательского события | Явная маршрутизация для собственного виджета |

Адаптеры click/key принимают `void`, `expected<T, TreeError>` или точный тип
подтверждения команды редактора. Прямой возврат подтверждения undo/redo редактора
сохраняет происхождение диагностик. `Property::observe` возвращает
подписку, которой владеет вызывающий код; управляемые регистрации сцены сохраняют
свои токены сами. Если отбросить низкоуровневую подписку, соединение не сохранится.
Успешное значение expected игнорируется и уничтожается до выхода из обработчика.
Даже `false` означает обработанное действие; успешные квитанции требуют проверки до возврата.

Пример более сложного обработчика нажатия:

```cpp
scene
  | ui::onClick(append, [field](ui::ClickParams &params) {
    field.text() += params.mods.has(key::SHIFT) ? "HELLO!" : "Hello!";
    params.stop();
  });
```

`ClickParams` предоставляет доступные только для чтения `target`, `mods`, `source`
и собственные метаданные исходного `event`. `stop()` останавливает последующие
обработчики той же синхронной активации. Всплывания событий по модели DOM здесь нет.
Обработчик заимствует контекст; копия контекста владеет снимком события, но остановка
копии не останавливает исходную цепочку. Семантические модификаторы не различают
физические левые и правые клавиши.

## Выбор фаз клавиатурного события

Во фрагментах ниже предполагаются уже существующие обработчики `move` и `stop`:

```cpp
scene
  | ui::onKey("W", move);
scene
  | ui::onKey(ui::repeat("W"), move);
scene
  | ui::onKey(ui::release("W"), stop);
scene
  | ui::onKey(ui::pressRepeat("W"), move);
```

Обычные строки сочетаний выбирают PRESS; явные помощники выбирают соответствующие
фазы. Перегрузка регистрации исходного `KeyEvent` сохраняет поведение PRESS+REPEAT.
Декодер VT-байтов предоставляет только PRESS и не синтезирует RELEASE. Побеждает
последняя подходящая регистрация клавиши. Обработчики нажатий, добавленные через оператор `|`,
выполняются в порядке регистрации. `"Ctrl+K+K"` означает Ctrl+K, затем Ctrl+K;
у `"Ctrl+K,K"` вторая K без модификатора. Альтернативы, тайм-аут последовательности,
приоритеты и ограничения описаны в [руководстве по вводу](input.md).

## Время жизни, ошибки и полные примеры

Ссылки публикуются после монтирования и становятся недействительными при удалении
их целей или закрытии сцены. Копирование не продлевает жизнь владельца. Операции должны выполняться
в UI-потоке и вне запрещённых границ кадра и повторного входа. Обычные
захваты C++ по ссылке по-прежнему заимствуют объекты; перемещение сцены не исправит
захваченный `&scene`.

Полные программы и сценарии ошибок есть в
[клиенте текстового свойства](../../tests/package_consumer/text_property.cpp) и
[клиенте последовательностей клавиш](../../tests/package_consumer/shortcut_sequences.cpp).
[Справка по свойствам](property.md) определяет владение, [ограничение при перегрузке](glossary.md#glossary-backpressure-ru) и отмену;
[декларативная композиция](declarative-ui.md) — сообщения об ошибках запуска.

**TBD — M2:** общие выражения привязок. Синтаксис выражений и обобщённый граф
зависимостей с обработкой циклов остаются в планах; описанный выше
`owner.derive` с одним входом уже доступен.
Типизированные живые параметры темы уже доступны через явные UI-обновления;
см. [темы](themes-guide.md). Их наличие не означает автоматического связывания
переменных предметной области или переменных строкового PSS.

## Наблюдение за компоновкой

`ui::onLayout(ref, callback)` сообщает первоначальную итоговую геометрию и
последующие изменения после завершения кадра дерева. Изменение сцены в
обработчике запрашивает следующий кадр. `ref.geometry()` и `ref.size()`
возвращают проверяемые копии итоговых границ или локального размера. До
окончательной компоновки, для скрытого узла и после запроса новой компоновки
они возвращают `TreeError::INVALID_GEOMETRY`. Пример и правила доставки
описаны в [наблюдении за компоновкой](layout.md).

## Преобразование живого текста редактора {#live-text-transforms-ru}

Полное приложение показывает текущий черновик редактора в двух виртуальных
списках. При изменении поля слова и графемы обновляются при штатной подготовке
изменившегося кадра. Кнопка Quit и F10 завершают приложение. Стандартный runner
обрабатывает типизированные ошибки настройки/выполнения и восстанавливает терминал.

Программа использует `<portals/ui.hpp>` и `portals::core`; подключение описано
в [настройке потребителя](index.md).
В репозитории пример доступен как цель `portals_docs_text_transforms` при
`PORTALS_BUILD_TESTS=ON`. После сборки его можно запустить из каталога сборки. Программа открывает обычный
терминал и не имеет параметров CLI.

```cpp
// Copyright (c) 2026 ttldtor.
// SPDX-License-Identifier: BSL-1.0
#include <portals/ui.hpp>

/**
 * @brief Show whitespace-delimited words and extended graphemes
 * from the live editor draft.
 */
int main() {
  using namespace portals;

  ui::Ref<LineEdit> input;
  auto scene = ui::scene(ui::vbox(
    ui::lineEdit(input, "Hello, Portals!"),
    ui::label("Words"),
    ui::virtualList(ui::words(input.draftText())).height(4),
    ui::label("Graphemes (including spaces)"),
    ui::virtualList(ui::graphemes(input.draftText())).height(4),
    ui::button("Quit", [] {
      ui::quit();
    })));

  // clang-format off
  return scene
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
  // clang-format on
}
```

`ui::words(source)` и `ui::graphemes(source)` — отложенные описания: их создание
не читает текст и не подписывается на изменения. Mount разрешает прямые ссылки
из всего описания, включая последующих соседей, и инициализирует внутренний граф
до публикации ссылок. Начальная ошибка откатывает эту попытку mount. Сцена владеет
синхронизацией и очисткой; приложению не нужны таймер, токен подписки или ручной
счётчик ревизий.

Монтирование отложенного списка из текста сохраняет ID, классы и непустой тип,
заданные через `.id()` или `.style()`. Стандартный тип `List` назначается, если тип
не задан; сохранённую идентичность можно использовать для поиска по имени и в селекторах.

`words` разделяет токены только по целым графемам, все скаляры которых имеют
свойство Unicode `White_Space`. Пунктуация, апострофы, CJK и emoji остаются внутри
токенов. Это разбиение по пробельным символам, а не лингвистический анализ или
разбиение на слова по Unicode UAX #29. `graphemes` возвращает каждую существующую
расширенную графему, включая пробельные. Оба результата владеют исходным текстом;
`TextSegment::bytes()` возвращает view, действительный, пока сегмент сохранён
и не изменён.

По умолчанию `TextSplitOptions` допускает 4096 токенов и использует
`TextLimits{}`: 1 МиБ входных данных, 64 КиБ на кластер, 1 048 576 графем
и 2 097 152 ячейки. `maxTokens` должен быть положительным. Превышение лимита
отклоняет весь кандидат без усечения. Настройка отдельного описания:
`ui::words(input.draftText(), {.maxTokens = 1000})`. Проверка редактора, его
текстовые лимиты, политика ширины и режим подтверждения продолжают действовать;
источник черновика включает промежуточный текст без публикации в модель редактора.

ID токенов используют консервативную семантику сброса при изменении
(`RESET_ON_CHANGE`): изменённая упорядоченная последовательность получает новое
поколение. Те же байты токенов и политика ширины не вызывают обновления даже при
изменении позиций разделителей. Undo поэтому может создавать новые ID. Только
новые списки, связанные с коллекцией, очищают исчезнувшее выделение
(`CLEAR_MISSING`) по полному индексу ID; обычные списки поставщика сохраняют
свою политику.

Преобразование и применение модели коллекции — отдельные фиксации. Runtime
ошибка сохраняет последний успешный результат/модель и владеющие model pins;
уже принятый текст редактора или источника не откатывается. Сохраняются
типизированная причина и действующая политика остановки runner. Удаление исходного
контрола тихо прекращает доставку; список сохраняет последнюю владеющую коллекцию
для локальной прокрутки и изменения размера. Прежние prepared callbacks также
снимаются. Удаление списка-получателя освобождает его внутренний граф. Явный
доступ к устаревшему источнику по-прежнему даёт `STALE_NODE`, закрытие сцены —
`CLOSED`.

### Явные источники и коллекции

Чистый редактор, связанный со строковым состоянием, синхронизируется с его внешним
изменением до подготовки live-преобразований и моделей списков этого dirty frame.
Оба списка поэтому получают новый текст в том же кадре. Равные упорядоченные
значения токенов не публикуют ещё одну ревизию модели коллекции. Редактор с
неподтверждённым черновиком сохраняет политику конфликтов своего режима редактирования.

Для существующего `ManagedScene` можно передать полный рецепт поддерева в
`ui::mount(owner, recipe)`. Перед дальнейшим использованием требуется проверить результат
`std::expected<Node<T>, ManagedError>`. Он использует тот же cold bridge текста
и списка, что и полный нативный пример. `ui::mount` монтирует под корнем сцены;
публичной перегрузки с родительским узлом нет. Фабричный callback, переданный
в `ui::scene`, должен вернуть владеющее описание, при необходимости обёрнутое в
`std::expected<Description<T>, ManagedError>`; сама `ui::scene` возвращает `Scene`.
Callback не может вернуть уже смонтированный узел или результат настройки `void`.
Конструкторы описаний с callback являются
внутренними. Используйте полный рецепт, сохраняя автоматический адаптер ID
токенов внутри библиотеки.

Отдельные вызовы `ManagedScene::emplace` сохраняют ранее созданных детей при
ошибке последующего вызова; закрытие сцены очищает такую частичную форму. Полный
вызов `ui::mount` откатывает своё поддерево. Это разные границы транзакции,
даже если успешная раскладка совпадает.

Для смонтированной ссылки `owner.liveText(input.draftText())` возвращает
проверяемый `ManagedSource<GraphemeText>`, сразу инициализированный из источника.
Его `snapshot()` владеет снимком изменения свойства. Для явных преобразований
и представления доступны `owner.derive` и `owner.observe`. Конечные операции
`portals::words(text)` и `portals::graphemes(text)` возвращают
`std::expected<TextSegments, TreeError>` и не требуют сцены.

Для предметных строк со стабильными ID приложения создайте владеющую
`RowCollection<T>`, предоставьте её через read-only managed derived source
и вызовите `owner.model(source)`. Эта модель принимает данные только из источника:
`publisher()` возвращает `WOULD_BLOCK`. `CollectionModelOptions::maxRows`
и действующие бюджеты модели ограничивают регистрацию. Неудачное изменение
источника сохраняет старый источник; принятый источник при неудачной подготовке
модели оставляет новый источник и последнюю успешную модель. Присваивание равного
значения не повторяет неудачное уведомление; последующая допустимая подготовка
может повторить работу с последним значением.

Регистрация, чтение снимков и изменение живых объектов выполняются в UI-потоке
владельца между кадрами. Handles слабо наблюдают исходную сцену/контрол; копии
не продлевают их жизнь и не следуют за повторно использованным слотом. Успешные
снимки текста, сегменты, коллекции и model pins независимо владеют своими данными.
Захваты callback по C++-ссылке по-прежнему заимствуют объекты. Контракты описаны
в разделах [managed observation](bindings-guide.md), [источники
текста](text-property.md) и [виртуальные списки](virtual-list.md).
