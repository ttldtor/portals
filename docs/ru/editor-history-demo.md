# Пример истории редактора {#editor-history-demo-ru}

[К примерам](examples.md).

[Английская версия](../editor-history-demo.md)

`portals_editor_history` показывает Undo/Redo и три режима подтверждения текста на установленном публичном API ([исходник](../../examples/editor_history/editor.hpp)). Одна `ui::Scene` содержит три редактора и поля только для чтения с опубликованными моделями. Начальное значение — `base`. Отдельные строки черновика и модели позволяют увидеть отложенное подтверждение.

Соберите и запустите интерактивный пример из настроенного дерева сборки:

```powershell
cmake --build build/debug --target portals_editor_history
& ./build/debug/examples/editor_history/portals_editor_history.exe
```

Для генератора с несколькими конфигурациями укажите `--config Debug` и подкаталог `Debug` перед именем исполняемого файла. В Unix уберите `.exe`. Примеру удобно окно около 80×24; меньшее окно отсекает обычную компоновку.

## Попробуйте режимы

| Режим | Выбрать | Черновик | Опубликованная модель |
|---|---|---|---|
| IMMEDIATE, по умолчанию | F5 | Меняется при вводе и Undo/Redo | Меняется сразу |
| ON_COMPLETION | F6 | Меняется сразу | Меняется при потере фокуса или Enter |
| EXPLICIT | F7 | Меняется сразу и сохраняется при потере фокуса | Меняется на Enter |

Строки моделей — связанные `LineEdit` с `readOnly=true` и отключённой историей. Текст можно выделять; ввод и Undo/Redo не меняют его. Привязка допускает Copy, но системный сервис буфера обмена в примере не подключён. У редактируемых полей обычные лимиты истории и сочетания клавиш.

- Ctrl+Z отменяет изменение; Ctrl+Y повторяет. Кнопки Undo/Redo возвращают те же `field.undo()` / `field.redo()`.
- F3 в редакторе или **Append !** выполняет `field.text() += "!"` как отдельное обратимое изменение.
- Enter подтверждает поле. Tab или щелчок меняет фокус: ON_COMPLETION подтверждается, EXPLICIT сохраняет черновик. Кнопка команды тоже вызывает потерю фокуса.
- Escape принимает опубликованную модель и очищает локальную историю. В IMMEDIATE отменяйте уже опубликованные изменения через Undo.
- F10 закрывает приложение через runner с восстановлением терминала.

Строка последнего результата описывает изменение черновика, публикацию и отмену словами. [Проверки для разработчиков и headless replay](../testing.md).

<summary>Справка: ошибки и время жизни</summary>

Factory и configure callbacks возвращают типизированные результаты коллектору сцены. Native entry point использует `demo.scene() | ui::reportOnError() | ui::runApp(argc, argv, ui::lyra::cli(...))`. Проверка CLI через Lyra завершается до монтажа и захвата терминала. Runner восстанавливает терминал и сообщает об ошибках. Ошибки подготовки, ввода и очистки возвращают ненулевой код; восстанавливаемые ошибки коллектора сами по себе не меняют успешный код выхода.

Undo/Redo возвращают `EditorCommandResult` целиком, сохраняя сведения о том, какая ошибка уже зарегистрирована коллектором. Append использует `field.text() += "!"`; посредник записывает ошибки в тот же коллектор. Строка результата сообщает и об отказах уведомлений после фиксации без повторной мутации. Ошибка обновления самой строки сохраняет исходную типизированную причину.

Неперемещаемый `Demo` живёт дольше заимствующих его callbacks. `scene()` позволяет добавить привязки, `rows()` даёт наблюдающие дескрипторы редакторов и моделей после подготовки. Контролами и моделями владеет сцена. Конечный тестовый harness оборачивает настоящий demo и отдельно проверяет диагностику; он не дублирует интерфейс и не меняет native entry point.

См. [историю редактора](editor-history.md), [LineEdit](line-edit.md), [текстовые свойства](text-property.md) и [диагностику](diagnostics.md).

</details>
