# Пример истории редактора {#editor-history-demo-ru}

[Подробная английская версия](../editor-history-demo.md)

portals_editor_history показывает три режима подтверждения текста и Undo/Redo.
Одна ManagedScene хранит три редактора и представления только для чтения опубликованных
моделей. Все модели начинаются с base; черновик и модель показаны отдельными
строками. Для полного примера удобно окно около 80×24; меньший размер отсекается.

```powershell
cmake --build build/debug --target portals_editor_history
& ./build/debug/portals_editor_history_check.exe
```

Для генератора с несколькими конфигурациями укажите `--config Debug` и подкаталог Debug; в Unix уберите .exe.

## Управление

| Режим | Клавиша | Черновик | Модель |
| --- | --- | --- | --- |
| IMMEDIATE, по умолчанию | F5 | Меняется сразу | Публикуется сразу |
| ON_COMPLETION | F6 | Меняется сразу | Публикуется при потере фокуса или Enter |
| EXPLICIT | F7 | Меняется сразу, сохраняется при потере фокуса | Публикуется на Enter |

Строки моделей — LineEdit с readOnly=true и отключённой историей. Выделение
разрешено; ввод текста и Undo/Redo их не меняют. Граница привязки допускает Copy,
но системный сервис буфера обмена в примере не подключён.

- Ctrl+Z/Ctrl+Y и кнопки Undo/Redo вызывают те же Ref-команды.
- F3 в редакторе или Append ! выполняет `field.text() += "!"` отдельным
  отменяемым программным изменением.
- Enter подтверждает; Tab/мышь меняют фокус и подтверждают ON_COMPLETION.
  EXPLICIT сохраняет ожидающий черновик. Нажатие кнопки команды также вызывает потерю фокуса.
- Escape принимает опубликованную модель и очищает локальную историю.
  В IMMEDIATE опубликованное изменение отменяется через Undo.
- F10 закрывает приложение через `runApp` с восстановлением терминала.

Строка последнего результата показывает изменение черновика, публикацию
и отмену словами.

## Проверка без терминала

```powershell
& ./build/debug/portals_editor_history_check.exe --check
& ./build/debug/portals_editor_history_check.exe --replay
& ./build/debug/portals_editor_history_check.exe --help
```

--check проверяет настоящие кнопки, регистрацию команд после монтирования, RECORD/RESET,
Enter, Ctrl+Z, Escape и запрет ввода в поля только для чтения во всех режимах; сравнивает текст,
снимки моделей и подготовленные виджеты. RESET в проверке очищает оба стека.
Затем ReplayTerminal с VT-декодером проходит 12 контрольных точек F1 после ввода текста,
Undo/Redo, F3, потери фокуса, Enter и Escape. Итог моделей: baseA!, baseB, baseC.
Проверяются нарисованный вывод и close. --replay выполняет сценарий без проверок результатов,
печатает модели; --help не создаёт работающую сцену.

CTest: portals.editor-history-check/replay/help. Установленный потребитель
собирает тот же пример и запускает consumer.example-editor-history
и consumer.example-editor-history-replay.

## Ошибки и время жизни

Локальный checked(result, operation) — вспомогательная политика немедленной остановки при ошибке
подготовки и конечных проверок: печатает исходную фазу/причину и бросает
исключение с названием операции. Обработчики работающей сцены используют собственные
проверяемые результаты.
Undo/Redo возвращают EditorCommandResult целиком для сохранения квитанции
коллектора. Append использует объект доступа к тексту и сохраняет его ошибку без повторной
передачи через другой адаптер. Политику продолжения определяет цикл управляемой сцены.
Ошибка обновления статуса — самостоятельная причина. Отказ уведомлений после
успешной фиксации сохраняется и сообщается после run; операция не повторяется.

После восстановления проверяются run, diagnostics, потерянные записи и ошибки
observer. Любая ошибка даёт ненулевой код. Сцена освобождается перед Application;
обработчики захватывают Ref и ссылки на состояния без заимствованного Widget&.
См. [историю](editor-history.md), [LineEdit](line-edit.md),
[текстовые свойства](text-property.md), [диагностику](diagnostics.md).
