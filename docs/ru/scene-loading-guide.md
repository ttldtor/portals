# Загрузка сцен из текста и файлов {#scene-loading-guide-ru}

[Английская версия](../scene-loading-guide.md)

`ui::scene(source)` копирует текст ресурса в кодировке UTF-8 в обычную ленивую
[сцену](glossary.md#glossary-scene-ru). Разбор и создание контролов происходят при
вызове `prepareChecked()` или во время подготовки в `run` либо `runApp`, до открытия
терминала. API доступен через `<portals/ui.hpp>` или `<portals/ui_scene_resource.hpp>`;
программа связывается с `portals::core` (C++23). Именованные ссылки, обработчики
действий, модели, PSS и очистка работают через существующую среду выполнения.

## Полная форма

Полный пример доступен как цель `portals_scene_resource` при
`PORTALS_BUILD_EXAMPLES=ON`. Кнопка
Add Hello дописывает текст; Exit и F10 завершают сцену. Штатная программа запуска
восстанавливает настройки терминала и сообщает об ошибках.

\include{lineno} scene_resource/form.hpp
Исходник: [form.hpp](../../examples/scene_resource/form.hpp).

\include{lineno} scene_resource/main.cpp
Исходник: [main.cpp](../../examples/scene_resource/main.cpp).

Обычная строка всегда считается текстом ресурса. Вы можете загрузить файл
с помощью явного типа, владеющего путём:

```cpp
auto scene = ui::scene(ui::SceneResourceFile{"form.scene"});
auto message = scene.get<LineEdit>("message");
```

Файл читается один раз при подготовке; относительный путь разрешается относительно
рабочего каталога, который действует в этот момент. Автоматической перезагрузки и
слежения за изменениями файла нет. Применение PSS — отдельный этап:
`scene | ui::style(ui::file("form.pss"))`.

## Синтаксис ресурса

```text
VBox#form {
  gap = 1
  Label { text = "Message" }
  LineEdit#message { ""; width: 32 }
  HBox { Button#add { "Add" } CheckBox#enabled { "Enabled"; checked = true } }
}
```

В ресурсе должен быть ровно один корневой узел: имя типа `Type`, необязательный
идентификатор `#id`, затем свойства и дочерние узлы в фигурных скобках. Имена типов
и идентификаторы чувствительны к регистру и состоят из ASCII-символов; начинаться
они должны с буквы или подчёркивания. После первого символа в идентификаторе также
разрешён дефис. Идентификаторы должны быть уникальны в пределах ресурса. Для поиска
доступны типизированная и динамическая перегрузки `scene.get`.
Свойства задаются как `name = value` или `name: value`; элементы разделяются
пробелами, запятыми или точками с запятой. Вне строк `//` начинает комментарий до
конца строки.

Строки в двойных кавычках поддерживают следующие escape-последовательности:

```text
\"  \\  \n  \r  \t
```

Внутри строк запрещены переводы строк и другие управляющие байты ASCII. Кодировка
UTF-8 проверяется также в комментариях. Строка без имени свойства эквивалентна
`text = "..."`. Повторное задание свойства или одновременное использование двух
форм задания текста приводит к ошибке.

| Тип | Текст | Дочерние узлы | Дополнительные свойства |
|---|---|---|---|
| `VBox`, `HBox` | Нет | Да | `gap`: неотрицательное 32-битное число ячеек, по умолчанию ноль |
| `Label`, `LineEdit`, `Button` | Да | Нет | — |
| `CheckBox` | Да | Нет | `checked`: `true` или `false`, по умолчанию `false` |
| Зарегистрированный пользовательский тип | Да | Если это разрешено при регистрации | Фиксированные размеры для `SizedWidget` |

Все встроенные типы принимают свойства `width` и `height` — неотрицательные числа
ячеек в диапазоне 32 бит — и `flex`, положительное беззнаковое 32-битное число.
Они применяются в том же порядке, что и существующие операции [рецепта](glossary.md#glossary-recipe-ru):
сначала `width`, затем `height`, затем `flex`. По умолчанию текст пуст. Выражения,
привязки, действия, объявления стилей и произвольные аргументы конструктора не
поддерживаются. После поиска контролов к ним можно подключить действия и модели
средствами C++.

## Локализованный текст и собственные типы

`text = i18n("key")` и `i18n("key")` без имени свойства используют явно переданный
`TextResolver`. До вызова любой фабрики все строки разрешаются через него и
проверяются с учётом политики ширины текста сцены:

```cpp
ui::SceneResourceOptions resource;
resource.resolver = [](std::string_view key)
  -> std::expected<std::string, TextResourceError> {
  if (key == "add") {
    return "Добавить";
  }
  return std::unexpected(TextResourceError::MISSING_RESOURCE);
};
auto scene = ui::scene("Button#add{i18n(\"add\")}", std::move(resource));
```

Глобальная локаль не задаётся автоматически, а переводы не обновляются сами.
Сведения об отсутствующем ресурсе сохраняются в `ManagedError::resource`, об ошибке
текста — в `text`. Если переданный `TextResolver` заимствует внешний сервис, этот
сервис должен оставаться доступным до завершения подготовки сцены.

Зарегистрируйте конкретный публичный тип, производный от `Widget`, и копируемую
фабрику, которой владеет регистрация. Фабрика должна возвращать `Description<T>`
или именно `expected<Description<T>, ManagedError>`:

```cpp
ui::SceneResourceOptions resource;

resource.control<Meter>("Meter", [](ui::SceneResourceArguments arguments) {
  return ui::custom<Meter>(std::move(arguments.text));
});

auto scene = ui::scene("Meter#level{\"CPU\" width=20}", std::move(resource));
```

Здесь `Meter` — определённый приложением `SizedWidget`, который принимает строку
в собственное владение. `SceneResourceArguments` владеет текстом и идентификатором.
Загрузчик применяет идентификатор и общие размеры после создания рецепта фабрикой.
Третий аргумент `true` у `add` разрешает дочерние узлы. Встроенный тип и ранее
зарегистрированный тип нельзя заменить. После полной проверки грамматики, схемы,
идентификаторов и текста фабрика вызывается один раз для каждого узла: сначала для
дочерних, затем для родительских. Глобального реестра, поиска динамических
библиотек и произвольного вычислителя выражений нет.

Вызов `control<T>(name, factory, children=false)` возвращает настройки, которые
можно продолжить цепочкой вызовов. Первая ошибка регистрации сохраняется, поэтому
проверять `expected` вручную не нужно; последующие регистрации в этой цепочке
пропускаются. При вызове `prepareChecked()` или `runApp()` типизированная ошибка
передаётся в существующий обработчик до чтения файла, разбора текста, разрешения
переводов, вызова фабрик и открытия терминала. У ошибки регистрации нет позиции в
ресурсе: `line` и `column` равны нулю. Стандартный отчёт помечает её как ошибку
регистрации и не выводит вводящую в заблуждение позицию.

Внутренняя ошибка выделения памяти `bad_alloc` преобразуется в
`TreeError::NO_MEMORY`, а любое другое исключение при копировании фабрики — в
`CALLBACK_FAILED`. Создание настроек, вычисление аргументов и захватов до входа в
адаптер, а также создание сцены всё ещё могут выбрасывать исключения. Для явного
восстановления доступен проверяемый вызов `resource.registry.add<T>()`: обработанная
им ошибка не портит настройки, собранные цепочкой вызовов. Однако последующая
успешная проверяемая регистрация не сбрасывает уже сохранённую ошибку цепочки.
Чтобы исправить конфигурацию, создайте новые настройки.

```cpp
auto options = ui::SceneResourceOptions{}
  .control<Meter>("CpuMeter", cpuFactory)
  .control<Meter>("MemoryMeter", memoryFactory);
```

Показанные фабрики — копируемые вызываемые объекты приложения с сигнатурой,
приведённой выше. Ресурсы необязательны: для обычного
`ui::scene(ui::vbox(...))` реестр не нужен. Этот адаптер не добавляет собственных
свойств ресурса и не загружает исполняемый код.

`ui::resource(source, options)` возвращает такой же владеющий ленивый
`Description<Widget>`, как строковая и файловая перегрузки `scene`. Результат можно
использовать как дочерний рецепт на C++ или вернуть из существующей фабрики сцены.
Создайте управляемые модели в этой фабрике, захватите их наблюдающие дескрипторы в
зарегистрированных фабриках и верните `resource`. Дескрипторы ссылаются на модели
сцены, не продлевая их время жизни. Монтирование выполняется в
рамках общей транзакции внешней сцены; дополнительный владелец сцены не создаётся.

## Ограничения, ошибки и время жизни

По умолчанию `SceneResourceOptions::limits` ограничивает размер исходника 1 MiB,
число узлов — 4096, глубину — 64, длину одной декодированной строки или полученного
перевода — 64 KiB, а число свойств узла — 16. Каждый предел должен быть больше нуля.
Жёсткий предел глубины равен 64, поскольку парсер использует стек программы.
Настройка глубины выше этого предела приводит к `INVALID_LIMIT`; если глубина самого
ресурса превышает заданный предел — к `DEPTH_LIMIT`. Ресурсные рецепты монтируются
итеративно в рамках одной существующей транзакции. Также действуют общие ограничения
управляемых узлов, дерева, текста и состояния.

Неизвестные типы и свойства, повторные идентификаторы и свойства, неверные значения,
выражения, ошибки UTF-8 и превышение лимитов парсера обнаруживаются до вызова фабрик
и создания узлов ресурса. Рецепты монтируются одной существующей транзакцией. При
ошибке создаваемое поддерево удаляется, а наблюдающие слоты не публикуются. Откат
поддерева не отменяет внешние эффекты фабрики и не удаляет состояние сцены, созданное
отдельно. При отказе ленивая сцена выполняет свою обычную полную очистку.

`ManagedError::sceneResource` сохраняет категорию ошибки, смещение в байтах от
начала исходника, номер строки и номер байтового столбца. Нумерация начинается с
нуля для смещения и с единицы для строки и столбца. Текст исходника или путь к
файлу сохраняется в общем хранилище, поэтому диагностика не заимствует буфер
вызывающего кода. Контекст неизменяем
и добавляется по возможности: если не удалось выделить для него память, поле
остаётся пустым, а исходная типизированная причина ошибки сохраняется. Копирование
`ManagedError` не выделяет память и гарантированно не выбрасывает исключения
(`noexcept`). Для ошибки файла сохраняется также системный `error_code`. Первичные
причины ошибок фабрики, дерева и текста, а также отдельные ошибки очистки не
теряются. Стандартный отчёт в `stderr` выводит категорию и позицию, не печатая
непроверенные байты исходника. Создание фасада может завершиться исключением при
ошибке выделения памяти; проверяемая подготовка преобразует ошибки выделения памяти
и обратных вызовов.

Ресурс, реестр и `TextResolver` принадлежат ленивому рецепту; заимствованные
представления временных строк не сохраняются. Подготовка должна выполняться в
потоке UI-сцены; для `Scene` также действует запрет на повторный вход. Вложенный
вызов операции жизненного цикла возвращает `TreeError::WOULD_BLOCK`. Для обратных
вызовов и именованных ссылок продолжают действовать существующие проверки времени
жизни. См. также разделы [текстовых свойств](text-property.md), [слоёв стилей](style-layers.md)
и [управляемых контролов](managed-controls.md).

## Именованные варианты и начальные настройки {#named-control-defaults-ru}

`ui::ControlContext` хранит общие начальные настройки. Он не разделяет между
экземплярами текст, курсор, историю Undo, модели или обработчики. Именованный
вариант сохраняет конкретный C++ тип: для `ShortEdit = LineEdit` используется
`ui::Ref<LineEdit>`.

[Полная программа](../../examples/named_controls/main.cpp) объявляет контекст
один раз, создаёт два редактора и отдельно меняет лимит истории второго:

\include named_controls/main.cpp

`Description::settings(ControlSettings)` — точечные настройки экземпляра.
Отсутствующие поля наследуются. Явные `false`, `0` и значения, совпадающие со
встроенными, всё равно переопределяют унаследованное значение. Обычная фабрика
`ui::lineEdit` без config наследует настройки контекста. Явно переданный прежний
`LineEditConfig` сохраняет полную семантику options: библиотека не пытается
угадать, какие его поля пользователь «на самом деле» хотел пропустить.
При связывании с существующей managed-моделью начальный текст берётся из модели:
настройка контекста не перезаписывает её значение. Явный текстовый аргумент
фабрики подписи считается переопределением экземпляра.

Разрешение идёт от конкретного базового типа к запрошенному варианту:
встроенные настройки, defaults базы, определение варианта, defaults варианта,
настройки экземпляра. `defaults(type, patch)` допускает один блок для типа.
`overlayDefaults(type, patch)` явно объединяет локальные defaults с
унаследованными, создавая новую версию контекста. Прежние копии и уже
подготовленные сцены не меняются. Это начальные настройки, а не живая
перенастройка истории или темы.

### Та же конфигурация в ресурсе

Старый формат с одним корневым узлом остаётся форматом по умолчанию.
Для блоков definitions/defaults/scene явно выберите
`SceneResourceFormat::CONFIGURATION`. Порядок блоков и объявления базовых
типов не влияет на разрешение ссылок:

\include named_controls/resource.cpp

Передайте `ui::SceneResourceFile{"form.scene"}` вместо строки, чтобы прочитать
тот же документ из файла при подготовке. Вложенный ресурс наследует контекст
сцены. Его локальные definitions/defaults действуют только в поддереве этого
ресурса. `SceneResourceOptions::controls` позволяет явно заменить наследуемый
контекст. Повторные defaults одного типа внутри документа остаются ошибкой.

### Поддерживаемые литералы и ограничения

| Контролы | Дополнительные начальные свойства |
|---|---|
| Label, Button | `text` |
| LineEdit | `text`, `placeholder`, `editMode`, `readOnly`, `programmaticChange`, `displayMode`, `history` |
| CheckBox, ThreeState | `text`, `state`, `cycle` |
| VBox, HBox | `gap` |
| Контролы с размерами | `width`, `height`, `flex` |

История принимает `enabled`, `maxOperations`, `maxBytes`, `groupTyping` и
`groupDeletion`. Текст задаётся строкой или существующим выражением `i18n(...)`.
Для enum используются имена из C++ API. `ThreeState` фиксирует
`cycle = THREE_STATE`: попытка изменить этот цикл — ошибка.
ID, классы, модели, обработчики и живые записи Undo не наследуются.

Селектор типа совпадает с именем варианта и его предками с обычной
специфичностью типа. Глубина не повышает приоритет. ID, классы, порядок слоёв
и правил сохраняют прежний смысл.

`ControlContextLimits` по умолчанию допускает 64 пользовательские схемы и
определения, 32 предка (включая intrinsic-имена `CheckBox`, `Column` или `Row`),
8 уровней структур и 65 536 итоговых скалярных свойств
на всю mount-транзакцию. Предел наследования нельзя поднять выше жёсткой
границы стилевой системы — 32. Явное переименование стилевого типа использует
тот же бюджет предков: дополнительное имя сверх лимита приводит к
типизированной ошибке стиля и откату монтируемого поддерева. Лимиты размера исходника, числа узлов, строк и свойств
ресурса продолжают действовать. Неизвестные базы, циклы, подмена встроенных
имён, недопустимые свойства и значения enum проверяются до вызова resolver
или фабрик ресурса. Ошибка сохраняет позицию выигравшего объявления и путь
`type.property`, в том числе для унаследованных значений. При нехватке памяти
диагностический контекст может отсутствовать, но типизированная ошибка остаётся.

Грамматика не исполняет C++, не импортирует ресурсы, не отслеживает файлы и не
связывает `$parameters`. Фабрики собственных контролов по-прежнему явно
разрешаются реестром ресурса.
