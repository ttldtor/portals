# Загрузка сцен из текста и файлов {#scene-loading-guide-ru}

[Английская версия](../scene-loading-guide.md)

`ui::scene(source)` копирует UTF-8 ресурс в обычную ленивую
[Scene](declarative-ui.md). Разбор и создание выполняются при `prepareChecked()`
либо подготовке внутри `run`/`runApp`, до открытия терминала. Подключите
`<portals/ui.hpp>` либо `<portals/ui_scene_resource.hpp>` и свяжите программу
с `portals::core` (C++23). Ссылки, действия, модели, PSS и очистка используют
существующий runtime.

## Полная форма

Соберите `portals_scene_resource` с `PORTALS_BUILD_EXAMPLES=ON`. Add Hello
дописывает текст, Exit и F10 завершают сцену. Нативный runner восстанавливает
терминал и сообщает об ошибках.

\include{lineno} scene_resource/form.hpp
\include{lineno} scene_resource/main.cpp

Обычная строка всегда означает текст ресурса. Для файла нужен явный владеющий тип:

```cpp
auto scene = ui::scene(ui::SceneResourceFile{"form.scene"});
auto message = scene.get<LineEdit>("message");
```

Файл читается один раз при prepare; относительные пути используют текущий на
этот момент рабочий каталог. Автоматической перезагрузки и слежения за файлом
нет. PSS остаётся отдельным этапом: `scene | ui::style(ui::file("form.pss"))`.

## Синтаксис ресурса

```text
VBox#form {
  gap = 1
  Label { text = "Message" }
  LineEdit#message { ""; width: 32 }
  HBox { Button#add { "Add" } CheckBox#enabled { "Enabled"; checked = true } }
}
```

Нужен ровно один корень: `Type`, необязательный `#id`, затем свойства и дочерние
узлы внутри скобок. Типы и id — чувствительные к регистру ASCII идентификаторы
с буквой или подчёркиванием в начале; id также допускает `-` после первого
символа. Id уникальны в ресурсе и используют обычный typed/dynamic `scene.get`.
Свойства записываются как `name = value` или `name: value`. Пробелы, запятые и
точки с запятой разделяют элементы; `//` начинает комментарий вне строки.

Строки в двойных кавычках поддерживают следующие escape-последовательности:

```text
\"  \\  \n  \r  \t
```

Настоящие переводы строк и другие управляющие ASCII байты внутри строк запрещены. UTF-8
проверяется даже в комментариях. Позиционная строка сокращает `text = "..."`.
Повтор свойства и смешение двух форм текста возвращают ошибку.

| Тип | Текст | Дочерние узлы | Дополнительные свойства |
|---|---|---|---|
| `VBox`, `HBox` | Нет | Да | `gap`: неотрицательное 32-битное число ячеек, по умолчанию ноль |
| `Label`, `LineEdit`, `Button` | Да | Нет | — |
| `CheckBox` | Да | Нет | `checked`: `true` или `false`, по умолчанию `false` |
| Зарегистрированный custom type | Да | По разрешению при регистрации | Фиксированные размеры для `SizedWidget` |

Все builtin типы принимают неотрицательные 32-битные `width`/`height` в ячейках
и положительный беззнаковый 32-битный `flex`. Это существующие операции рецепта
в порядке width/height/flex. Текст по умолчанию пустой. Общие выражения, bindings,
действия, объявления стилей и произвольные аргументы конструктора запрещены.
Действия и модели подключаются существующим C++ API после lookup.

## Локализованный текст и собственные типы

`text = i18n("key")` и позиционное `i18n("key")` используют явно переданный
существующий `TextResolver`. Весь текст разрешается и проверяется с width policy
сцены до вызова любой фабрики:

```cpp
ui::SceneResourceOptions resource;
resource.resolver = [](std::string_view key)
  -> std::expected<std::string, TextResourceError> {
  if (key == "add") {
    return "Добавить";
  }
  return std::unexpected(TextResourceError::MISSING_RESOURCE);
};
auto scene = ui::scene("Button#add{i18n(\"add\")}", std::move(resource));
```

Неявной глобальной локали и автоматического обновления перевода нет. Ошибка
ресурса сохраняется в `ManagedError::resource`, неверный текст — в `text`.
Явно заимствованный сервис resolver должен жить до конца prepare.

Зарегистрируйте конкретный публичный подтип `Widget` и владеющую копируемую
фабрику, возвращающую `Description<T>` либо строго
`expected<Description<T>, ManagedError>`:

```cpp
ui::SceneResourceOptions resource;

resource.control<Meter>("Meter", [](ui::SceneResourceArguments arguments) {
  return ui::custom<Meter>(std::move(arguments.text));
});

auto scene = ui::scene("Meter#level{\"CPU\" width=20}", std::move(resource));
```

`control<T>(name, factory, children=false)` возвращает настройки для цепочки.
Первый сбой регистрации сохраняется без ручной проверки `expected`; последующие
fluent-регистрации пропускаются. `prepareChecked()` или `runApp()` передаёт typed
ошибку в существующий обработчик до чтения файла, разбора, resolver, фабрик и
открытия терминала. У ошибки регистрации нет позиции в ресурсе: `line` и `column`
равны нулю; стандартный отчёт выводит признак регистрации вместо ложной позиции.

Внутренний `bad_alloc` становится `TreeError::NO_MEMORY`, другое исключение при
копировании фабрики — `CALLBACK_FAILED`. Создание настроек, вычисление аргументов
и захватов до входа в адаптер, а также создание сцены по-прежнему могут бросать.
Для явного восстановления оставлен checked `resource.registry.add<T>()`:
обработанная ошибка этого метода не делает fluent-настройки ошибочными.
Последующая checked-регистрация не очищает уже сохранённую fluent-ошибку;
для исправленной конфигурации создайте новые настройки.

```cpp
auto options = ui::SceneResourceOptions{}
  .control<Meter>("CpuMeter", cpuFactory)
  .control<Meter>("MemoryMeter", memoryFactory);
```

Фабрики в примере — определённые приложением копируемые функции с показанной выше
сигнатурой. Ресурсы остаются опцией: обычный `ui::scene(ui::vbox(...))` не требует
реестра. Новых custom-свойств ресурса и загрузки исполняемого кода адаптер не вводит.


Здесь `Meter` — определённый приложением `SizedWidget`, принимающий владеющую
строку. `SceneResourceArguments` владеет текстом и id. Загрузчик применяет id и
общие размеры после фабричного рецепта. Третий аргумент `true` у `add` разрешает
детей. Заменить builtin или прежнюю регистрацию нельзя. Фабрики вызываются по
разу на узел, дети раньше родителей, после полной проверки грамматики, схемы,
id и текста. Глобального registry, поиска динамических библиотек и произвольного
evaluator нет.

`ui::resource(source, options)` возвращает тот же владеющий ленивый
`Description<Widget>`, который используют строковый и файловый overload `scene`.
Он может быть дочерним C++ рецептом или результатом существующей фабрики сцены.
Создайте managed модели внутри этой фабрики, захватите их weak handles в
типизированных адаптерах registry и верните `resource`. Используется общая
транзакция mount без дополнительного владельца сцены.

## Ограничения, ошибки и время жизни

`SceneResourceOptions::limits` по умолчанию допускает 1 MiB исходника, 4096 узлов,
глубину 64, 64 KiB в одной декодированной строке или разрешённом тексте и 16
свойств на узел. Все лимиты положительные; жёсткий предел глубины равен 64,
поскольку парсер использует нативный стек. Больший настроенный предел возвращает
`INVALID_LIMIT`, превышение глубины исходником — `DEPTH_LIMIT`. Ресурсные рецепты
монтируются итеративно одной существующей транзакцией. Ограничения managed/tree/text/state
также действуют.

Неизвестные типы и свойства, повторы id и свойств, неверные значения, выражения,
ошибки UTF-8 и лимиты парсера отклоняются до фабрик и создания узлов ресурса.
Рецепты монтируются одной существующей транзакцией. Отказ удаляет создаваемое
поддерево и не публикует наблюдающие slots. Внешние эффекты фабрики и отдельно
созданное состояние сцены не входят в откат поддерева; ленивая Scene при отказе
выполняет свою обычную полную очистку.

`ManagedError::sceneResource` сохраняет тип ошибки, смещение в байтах от нуля,
строку и байтовый столбец от единицы и shared owning исходник либо путь файла.
Этот неизменяемый общий контекст добавляется по возможности: при отказе его
выделения поле остаётся пустым, а исходная типизированная причина сохраняется.
Копирование `ManagedError` не выделяет память и остаётся `noexcept`.
Для ошибки файла сохраняется также системный `error_code`. Исходные factory/tree/text
причины и независимые ошибки cleanup не теряются. Штатный stderr report выводит
категорию и позицию без непроверенных байтов ресурса. Создание facade может бросить
ошибку выделения памяти; checked prepare переводит allocation/callback failures.

Ресурс, registry и resolver принадлежат ленивому рецепту; views на временные
строки не остаются. Подготовка подчиняется UI affinity и запрету reentry Scene:
вложенная lifecycle операция возвращает TreeError::WOULD_BLOCK. Callbacks и именованные
refs сохраняют свои checked lifetime правила. Последующие операции описаны
в разделах [текстовых свойств](text-property.md), [слоёв стилей](style-layers.md)
и [managed контролов](managed-controls.md).
