# Запуск с командной строкой Lyra {#cli-ru}

[Английская версия](../cli.md)

## Подключение адаптера

Необязательная цель `portals::lyra` предоставляет встроенную однозаголовочную
[Lyra 1.8.0](https://github.com/bfgroup/Lyra/releases/tag/1.8.0)
и адаптер `<portals/ui_lyra.hpp>`. Подключите её явно:

```cmake
find_package(Portals CONFIG REQUIRED)
target_link_libraries(my_application PRIVATE portals::lyra)
```

Та же цель доступна через `add_subdirectory`. Заголовки, метаданные CMake,
лицензия и манифест зависимости входят в SDK: сеть и системная установка Lyra
не нужны. Приложение без адаптера подключает `portals::core` и не разбирает
заголовки Lyra при компиляции.

## Разбор параметров приложения

Объявите параметры средствами Lyra, свяжите их с типизированными настройками
и передайте адаптер заключительному этапу ленивого запуска:

```cpp
#include <portals/ui.hpp>
#include <portals/ui_lyra.hpp>

struct Options {
  int width{80};
  std::string theme{"modern"};
  bool ansi16{};
};

int main(int argc, char **argv) {
  namespace ui = portals::ui;
  Options options;

  auto parser = ::lyra::cli()
    | ::lyra::opt(options.width, "columns")["-w"]["--width"](
        "Requested columns.")
    | ::lyra::opt(options.theme, "theme")["-t"]["--theme"](
        "Palette.").choices("modern", "classic")
    | ::lyra::opt(options.ansi16)["--ansi16"](
        "Use 16 ANSI colors.");

  return ui::scene([&](portals::ManagedScene &) {
    return ui::vbox(
      ui::label(options.theme),
      ui::label(std::to_string(options.width)));
  })
    | ui::applicationOptions([&] {
        portals::ApplicationOptions settings;

        settings.writer.colorMode = options.ansi16
          ? portals::ColorMode::ANSI16
          : portals::ColorMode::TRUE_COLOR;

        return settings;
      })
    | ui::onKey(portals::key::F10, ui::quit)
    | ui::reportOnError()
    | ui::runApp(argc, argv,
        ui::lyra::cli(parser,
          {.version = "my_application 1.0"}));
}
```

## Время жизни связанных настроек

`ui::lyra::cli` хранит копию объявления парсера. При создании он не захватывает
argv и не выполняет разбор. Связанные переменные Lyra и захваты по ссылке остаются
заимствованными: они должны пережить синхронный `runApp`. Ленивая фабрика сцены
читает уже разобранные настройки. Через `ui::opts(options)` можно передать те же
настройки в переиспользуемую фабрику как типизированное представление для чтения.
Создание парсера, описаний и владеющих захватов может выделять память до входа
в runner. Вызываемые runner обработчики используют его проверяемую политику ошибок.

<details>
<summary>Владение текстом диагностики и выделение памяти</summary>

`CommandLineError::message` и `LaunchAction::output` используют `LaunchText`,
совместно владеющий неизменяемыми байтами. Создание пустого значения, копирование
и перемещение не выделяют память, в том числе в MSVC Debug. Методы `view()`,
`data()`, `size()`, `empty()` и `find()` доступны для чтения. Пока используются
заимствованные байты, сохраняйте копию текста. Непустой текст копирует байты
и может выделять память. Внутри обработчика парсера нехватка памяти становится
`NO_MEMORY` с пустым сообщением и кодом завершения 2. Создание текста до вызова
runner подчиняется обычной границе создания объектов, описанной выше.

</details>

## Справка и версия

По умолчанию адаптер добавляет справку Lyra `-?`, `-h`, `--help`.
Непустой `version` добавляет `--version`. Эти параметры используют штатное
досрочное завершение Lyra и возвращают владеющий `LaunchAction` с `FINISH`.
`runApp` печатает результат и завершается до фабрики сцены и захвата терминала;
`std::exit` не вызывается. Не объявляйте эти имена повторно в переданном парсере.

Для собственной справки добавьте `::lyra::help(showHelp)` в парсер и передайте
`{.automaticHelp = false, .helpRequested = &showHelp}`. Флаг заимствуется и должен
пережить вызов; перед каждым запуском задавайте ему false. Явный наблюдаемый флаг
нужен потому, что Lyra скрывает флаг справки за обработчиком; просмотр строк argv
обошёл бы парсер.

## Ошибки аргументов

Неверные числа, пропущенные значения, неизвестные параметры и отказ `.choices`
становятся `CommandLineErrorCode::INVALID_ARGUMENT` с владеющим сообщением Lyra;
ошибка командной строки завершает `runApp` кодом 2. Исключения обработчика парсера
обрабатываются границей запуска отдельно от ошибок виджетов. До последующей
ошибки разбора Lyra может изменить часть связанных значений или вызвать
обработчики. Адаптер сохраняет это поведение и не создаёт приложение после отказа.

## Unicode в аргументах

Lyra получает строки из снимка аргументов запуска. Узкий Windows `main` не
преобразуется адаптером в Unicode: не-ASCII аргументы зависят от способа получения
argv приложением. Снимок Unicode-окружения Windows — отдельная возможность,
которая не исправляет узкий argv. В POSIX сохраняются исходные байты аргументов.

## Чтение аргументов и окружения

`ui::app::args()`, `ui::app::environment()` и синоним `ui::app::env()` возвращают
проверяемые владеющие снимки для чтения после успешного `ui::app::initialize`,
в том числе вызванного через `ui::runApp(argc, argv, parser)`. До инициализации
они возвращают `ProcessContextError::UNINITIALIZED`.
`Environment::get(name)` без исключений возвращает
`std::expected<std::optional<std::string_view>, ProcessContextError>`.
Ошибка обозначает неверный запрос или отказ захвата/преобразования;
успешный `std::nullopt` — отсутствующую переменную, а непустой optional
с пустым view — существующее пустое значение. Сохраняйте снимок, пока используете
его view. Windows сравнивает Unicode-имена без учёта регистра; POSIX сохраняет
исходные байты и сравнивает имена точно. Чтение снимка не обновляет и не меняет
окружение процесса. Захватывайте окружение до запуска потоков, которые могут его
менять: Portals не синхронизирует сторонние записи в окружение.
