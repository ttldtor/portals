# Описания сцен во время компиляции {#compile_time_scenes-ru}

[Подробная английская версия](../compile-time-scenes.md)

Экспериментальный `<portals/ui_static.hpp>` позволяет описать Label, Button,
LineEdit, Row и Column через `ui::ct` с вычислением во время компиляции C++23.
Обычная управляемая сцена создаёт описанные контролы в дереве и обеспечивает ввод, состояние и очистку.

## Структура и обработчики

Фрагмент предполагает `<portals/ui_static.hpp>` и `using namespace portals;`.

```cpp
constexpr auto FORM = ui::ct::scene(
  ui::ct::column<"form">(
    ui::ct::label("Name"),
    ui::ct::lineEdit<"name">("Portals"),
    ui::ct::button<"apply">("Apply")));

ui::Ref<LineEdit> name;

auto description = ui::ct::describe(
  FORM, ui::ct::reference<"name">(name),
  ui::ct::onClick<"apply">([name] {
    name.text() += "!";
  }));

auto scene = ui::scene(std::move(description));
```

Фрагмент создаёт сцену. Для запуска вызовите runApp или обработайте типизированный
результат run выбранного терминала; см. [декларативный API](declarative-ui.md).
Фабрики владеют литералами и детьми. Необязательные непустые идентификаторы в параметрах шаблонов
должны быть уникальны; scene завершает описание. Неверные политики размеров,
повторные ID, неизвестные ID адаптеров, неверный тип `Ref` и дублирование
адаптера одного вида дают ошибку компиляции.

`reference`, `onClick` и `bind` подключают поведение во время выполнения.
`bind<"name">(state)` принимает `ManagedState<std::string>`; начальный текст
берётся из текущего состояния. [Наблюдающая ссылка](glossary.md) `ui::Ref<T>` обращается к смонтированному контролу
до завершения его времени жизни.

## Что проверяется при запуске

UTF-8, сегментация графем, WidthPolicy и TextLimits проверяются текстовым
движком при монтаже. Некорректный UTF-8 литерала может пройти компиляцию
и дать TextError при монтаже. Захваты, живое состояние и владение UI
сохраняются как данные времени выполнения.
`describe` создаёт владеющее перемещаемое описание. Исходное статическое
описание после этого можно освободить. Откат частичного монтажа, публикация Ref, смена темы
и одноразовость сцены сохраняют обычные контракты. Отключённые захваты могут
оставаться в маршрутизаторе событий до очистки или уничтожения `Application`.

В этом эксперименте отсутствуют виртуальные и произвольные пользовательские виджеты,
загружаемые файлы, согласование изменяемых описаний с существующим деревом и разбор стилей во время компиляции.
Описание не уменьшает число элементов управления времени выполнения автоматически.

Полный [пример](../../tests/package_consumer/static_scene.cpp) редактирует имя,
активирует Apply, обновляет статус, меняет размер и закрывает терминал воспроизведения ввода.
--failure проверяет типизированную ошибку обработчика и очистку.
[Общее окружение](../../tests/package_consumer/static_scene_support.hpp)
содержит выполнение примера, сообщения об ошибках и очистку.
