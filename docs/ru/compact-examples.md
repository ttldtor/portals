# Форматирование текста и колонки таблицы {#compact-examples-ru}

[Английская версия](../compact-examples.md)

Начните с [приложений-примеров](examples.md) и [декларативного API](declarative-ui.md).
Здесь описаны проверяемое форматирование текста, ресурсные значения и колонки таблицы.

## Форматирование и проверка текста

Подключите `<portals/text_format.hpp>`. `formatText("Price {:.2f}", value)`
проверяет спецификацию формата при компиляции и возвращает
`expected<GraphemeText, TextError>`. Функция проверяет UTF-8 результата и сохраняет
исходную категорию ошибки и смещение в байтах. Для явной политики отображения
используйте `formatText(policy, "Price {:.2f}", value)`.
Исключения выделения памяти и пользовательских форматтеров стандартной библиотеки
могут выйти из вызова.

Для колонки `cellFormat<double>("{:.2f}", policy)` хранит шаблон и политику,
принимает заимствованный `const double&` и возвращает собственный `GraphemeText`.
Прямой вызов может бросить `bad_expected_access<TextError>` при некорректных
байтах результата. Подготовка таблицы преобразует исключение в `CALLBACK_FAILED`.
Когда приложению нужна конкретная ошибка текста, используйте проверяемый `formatText`.

## Фиксированная схема таблицы

Фрагмент предполагает тип `Ohlc` с полями `open` и `close` типа `double`
и переменную `policy` типа `portals::WidthPolicy`. Подключите
`<portals/table_column.hpp>` и `<portals/text_format.hpp>`.

```cpp
const auto price = portals::cellFormat<double>("{:.2f}", policy);

auto columns = portals::tableColumns(policy,
  portals::tableColumn("Open", &Ohlc::open, price, 9),
  portals::tableColumn("Close", &Ohlc::close, price, 9));

if (!columns) {
  // Report columns.error(): the original header TextError.
}
```

Тип записи выводится из указателя на поле. Описания колонок (`TableColumnSpec<T>`)
хранят заголовки и обработчики. Сборка проверяет заголовки и назначает ID от 1 до N
с начальным поколением в порядке аргументов, независимо для каждой таблицы.
Фиксированную схему достаточно собрать один раз. Перестановка готовых колонок
сохраняет ID; повторная сборка описаний в другом порядке создаёт другую позиционную
схему. Для динамической замены используйте явный `ColumnId`.

Таблица проверяет ширины при подготовке. Форматтер, заголовки и таблица должны
использовать одну политику ширины. Строки данных при создании колонок не копируются.
`columnOptions(id, caption, width, policy)` возвращает проверяемые метаданные
для полей агрегата или явных лямбда-проекций. Заголовки могут быть строками времени
выполнения; они не задают идентичность и не считаются ключами перевода автоматически.

## Текстовые значения и ресурсы

Подключите `<portals/text_value.hpp>` для `text("literal")`, `text("{}", 123.0)`
и `i18n("currency")`. Выражение хранит свои байты или ключ ресурса.
При наличии аргументов строка формата проверяется во время компиляции.
Без аргументов `text("{}")` означает буквальный текст со скобками.
Создание литерала/ключа и чтение ключа доступны в `constexpr`; форматирование
и проверка графем в C++23 выполняются во время работы. Это не гарантирует,
что любую владеющую строку можно хранить в постоянном объекте `constexpr`.
Форматирование происходит сразу; проверка UTF-8 и измерение ширины — в `resolve`
с явными `WidthPolicy` и `TextLimits` принимающего контекста.

```cpp
using namespace portals;

const auto amount = text("{:.2f}", 123.0);
const auto unit = i18n("currency");
const auto translated = unit.resolve(
  WidthPolicy{}, [](std::string_view key) -> std::expected<std::string, TextResourceError> {
    if (key == "currency") {
      return "USD";
    }

    return std::unexpected(TextResourceError::MISSING_RESOURCE);
  });
const auto formatted = amount.resolve(WidthPolicy{});
```

Результат — `expected<GraphemeText, TextValueError>`. Вариант ошибки сохраняет
исходный `TextError` либо сообщает через `TextResourceError`, что отсутствует
функция разрешения ресурса, ресурс не найден или разрешение завершилось ошибкой.
Литерал функцию разрешения не вызывает. Ресурс разрешается при каждом использовании;
Portals не кеширует переводы и не хранит глобальную локаль. Функция вызывается
синхронно и возвращает собственный `expected<std::string, TextResourceError>`.

Исключения выделения памяти и превышения ёмкости выходят из вызова. Другие
исключения функции разрешения преобразуются в `RESOLVER_FAILED` без сохранения
объекта исключения. Исключения форматтера выходят из `text` до разрешения ресурса.
`resourceKey()` заимствует сохранённый ключ; ссылка действительна, пока выражение
живо и не изменено.

Эти значения применимы к [свойствам текста](text-property.md):
`message.text() = text("{}", 123.0)` или `message.text() += i18n("currency")`.
Для ресурсов явно задайте функцию разрешения у текстового свойства.
Автоматическая смена языка и загрузка ресурсов из файлов — отдельные задачи;
их статус указан в [плане возможностей](planned-features.md).

## Поля агрегатов

Подключите цель `portals::aggregate` и заголовок `<portals/aggregate_columns.hpp>`,
если нужна рефлексия агрегатов. Эта дополнительная цель подключает ядро,
закреплённую версию заголовков Boost.PFR и настройки C++23. `portals::core`
не добавляет PFR в пути поиска и определения компилятора. Для сборки и использования
установленного адаптера не нужны сеть, полный Boost или подмодуль Git.

`aggregateColumns<Record>(std::array{ColumnCaption{"Bid", 9}, ColumnCaption{"Ask", 9}}, formatter)`
проверяет заголовки и назначает ID фиксированной схемы автоматически.
Перегрузка с `TableColumnOptions` сохраняет явную идентичность динамической схемы.
Обе формы проецируют все поля в порядке объявления; каждая колонка хранит
независимый форматтер. Число метаданных должно совпадать с числом полей;
форматтер должен принимать каждый тип константного поля и возвращать ровно
`GraphemeText`. `aggregateColumn<I, Record>` выбирает одно поле.
Для вложенных записей, неагрегатных типов и разных форматов полей используйте
явные проекции.

Переносимая область SimpleAggregate в PFR исключает базовые классы,
поля-ссылки, константные поля и поля-массивы C. Для неподдерживаемой формы
понятная диагностика ограничений не гарантируется. Позиция поля не является
стабильным ID схемы: при изменении записи сохраняйте явные ID колонок.
Рефлексия не определяет заголовки, единицы, валидацию, команды редактирования,
ресурсы или перевод. Она не копирует наборы данных и не меняет владение моделью.

Цель задаёт `BOOST_PFR_USE_CPP26=0`, чтобы последовательно выбрать реализацию C++23.
Версия и конфигурация PFR должны совпадать во всех единицах трансляции.
Совместимость с другой версией Boost.PFR в том же приложении проверяйте отдельно.
[Сведения о зависимости](../../vendor/pfr/README.md) содержат происхождение и хеши.

## Сопоставление клавиш

Подключите `<portals/input_match.hpp>` для предикатов C++23 `constexpr`.
Фрагмент предполагает `InputEvent event` внутри обработчика, возвращающего `bool`.

```cpp
if (keyPressed(event, InputKey::F2)) {
  // Switch theme, preserving its typed failure handling.
}

if (!keyPressed(event, {InputKey::LEFT, InputKey::RIGHT})) {
  return false;
}
```

Сопоставление принимает PRESS и REPEAT, исключает RELEASE и события другого типа.
Предикат не поглощает события и не отслеживает физически удерживаемые клавиши.
Перегрузки с одной клавишей и списком игнорируют модификаторы.
Для точного сочетания используйте `keyPressed(event, InputKey::F2, {.control = true})`:
должны совпасть все поля модификаторов, включая поля со значением false.
CHARACTER сопоставляет только идентичность: символ читайте из `KeyEvent::scalar`
или `TextInputEvent`. Список проверяется линейно без выделения памяти.
Маршрутизация и фокус остаются ответственностью маршрутизатора событий.
