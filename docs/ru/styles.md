# Справочник стилей и PSS v0 {#styles-ru}

[Подробная английская версия](../styles.md)

Практические примеры находятся в [гайде по стилям](styling-guide.md)
и [гайде по темам](themes-guide.md). Здесь собраны контракты парсера и движка.

`<portals/style.hpp>` предоставляет типизированные объявления и парсер PSS.
Оба используют `resolveStyle`. Строки и правила принадлежат таблице стилей.
Разбор и отдельное вычисление стиля выполняются без ввода-вывода.
StyleEngine заимствует WidgetTree и работает на его потоке UI;
дерево должно пережить движок. Метаданные хранят проверяемые идентичности узлов.
Один узел должен обслуживаться одним движком.

Управляемые Label, Button, CheckBox, LineEdit и KeyHints автоматически получают
эти имена типов; `ui::plainButton` использует `Button`. Их автоматические цели задают
`StyleTarget::control = true`, разрешая также совпадение с селектором `Control`.
Специфичность определяется самим селектором; флаг не добавляет наследования или
скрытого приоритета. Пользовательские подклассы Control сохраняют стандартное
имя `Control`, а не имя, полученное через RTTI.

У явно заданного низкоуровневого `StyleTarget` поле `control` по умолчанию равно
false. Тип совпадает точно, если этот флаг не включён. Полное назначение цели
через `scene.style(node, target)` заменяет метаданные, включая флаг.
`.style(target)` рецепта использует тот же контракт с существующими правилами
модификатора ID; `.id()` меняет ID, сохраняя остальные поля.

## Источники и установка

Для фасада подключите `<portals/ui_style.hpp>`. `ui::style(source, options)`
принимает строгий PSS, проверяемый `PssDocument`, `sc::CompactSheet`
или `ui::FileSource`. Изменяемый документ проверяется и глубоко копируется;
буферы нужны только во время создания [стадии UI](glossary.md#glossary-ui-stage-ru) `ui::StyleStage`. `ui::file(path)` копирует
собственный путь файловой системы и читает файл при применении этапа к Scene.
`parsePssDocument(bytes, sourceName)` файлов не читает.
Наблюдение за файлами, подключение других файлов и автоматическая перезагрузка отсутствуют.

`scene.style(source, options)`, `ui::style(scene, ui::style(source, options))`
и `scene | ui::style(source, options)` используют одну проверяемую границу.
По умолчанию StyleOptions выбирает `APPLICATION`; `USER` выбирается явно.
Повторное применение одного этапа проверяет исходный слой и сохраняет позицию.
Удалённый слой даёт типизированную ошибку устаревшей ссылки.
Непустое имя включает замену по паре `(tier, name)` с сохранением позиции слоя.
Имя необязательно; независимые группы описаны в [гайде](styling-guide.md).

Сначала установите слои, затем `ui::liveTheme(...)`.
Текущая тема сохраняется в `THEME`, слои APPLICATION/USER — выше неё.
`LiveTheme<S>` хранит типизированные параметры; `LiveThemeRef<S>` из `ref()`
наблюдает контроллер. Копии этапа разделяют одну идентичность одной Scene.
Неуспешное первое подключение допускает повтор; успешное подключение фиксирует
сцену. Очистка закрывает ссылки и освобождает контроллер.
После внешней замены темы устаревший этап сам не переустанавливается:
для нового подключения нужен новый этап.

Координаты PSS: смещения с нуля, строки и столбцы байтов с единицы.
Метка ошибки хранит ограниченный корректный префикс UTF-8; при NUL или
некорректном UTF-8 метка пуста. `ManagedScene::styleSources()` возвращает
метаданные источников по слоям. Полный инспектор правил запланирован.
Равные вычисленные значения при изменении метаданных не требуют кадра.
Лимиты документа и слоя учитывают логические данные, без ограничения RSS процесса.

## Синтаксис и свойства

```css
/* ASCII identifiers are case sensitive. */
* { foreground: #dce1e8; background: #181c24; }
Button.primary#save { min-width: 20; bold: true; }
Button.primary#save:focused { background: #4bb4dc; }
Table:selected { background: #2d4b6e; }
Table:header { foreground: #4bb4dc; bold: true; }
```

Селектор содержит необязательный тип или `*`, классы `.class`, не более одного
`#id` и одного `:state`, без пробелов между частями. Порядок частей допускает
вариации; все условия должны совпасть. Без типа селектор начинается с `.`, `#`
или `:`. Идентификатор начинается с ASCII-буквы или `_`, затем допускает буквы,
цифры, `_` и `-`; регистр значим. Комментарий — `/* ... */`, после значения
обязателен `;`. Списки, комбинаторы, экранирование символов, переменные, наследование и единицы
измерения в PSS v0 отсутствуют.

| Свойство | Значение | Влияние |
| --- | --- | --- |
| `foreground`, `background` | `#RRGGBB` | Отрисовка |
| `bold`, `italic`, `underline` | `true`, `false` | Отрисовка |
| `min-width` | 0..INT32_MAX ячеек | Компоновка и отрисовка |
| `frame-line-foreground`, `frame-title-foreground`, `frame-ends-foreground` (также `-background`) | `#RRGGBB` | Отрисовка части рамки |
| `frame-line-bold`, `frame-title-bold`, `frame-ends-bold` (также `-italic`, `-underline`) | `true`, `false` | Отрисовка части рамки |

`min-width` разрешён только без состояния. Ноль сохраняет собственное измерение.
Политики размеров, доступная область и отсечение по-прежнему действуют.
Размер шрифта, политика ширины текста, символы рамок и высоты строк не входят
в PSS v0.

Состояния: `normal`, `focused`, `disabled`, `selected`, `header`, `caret`.
Они выбирают вариант отображения. Правило без состояния подходит всем вариантам;
`:normal` подходит обычному. Фокус и доступность определяет существующая
синхронизация; выбор списка/таблицы хранит стабильную идентичность строки,
редактор — собственные выделение и курсор. Пользовательский виджет выбирает
вариант из полного ComputedStyle.

Каждое объявление участвует в каскаде независимо. Специфичность сравнивается
лексикографически: `(есть id, число классов и состояний, есть тип)`.
При равенстве выигрывает позднее правило. Отсутствующее свойство сохраняет
значение меньшего приоритета. Каждый вариант начинается с текущих ручных
параметров `Widget::styleDefaults()`. Тема перекрывает заданные ею поля.
После ручного изменения привязанного виджета вызовите `styles.refresh()` до кадра.
Пустая таблица восстанавливает последние значения по умолчанию.
Уничтожение движка оставляет последние вычисленные стили установленными.

## Атомарность и ошибки

`replace`, `replacePss`, `bind` и `refresh` сначала проверяют границу и готовят
все привязанные виджеты. Другой поток и активный кадр отклоняются.
Ошибки метрик, состояний, бюджетов, устаревших целей и памяти возвращают
StyleError с причиной TreeError. Аргументы и фабрики тем могут бросить исключение
до входа в операцию. Частичная таблица или обновление виджетов не публикуются.

`styleDefaults()` работает на этапе подготовки под заимствованием кадра.
Запрещены I/O, изменение моделей, сохранение ссылок, уничтожение дерева/движка
и рекурсивные расширения. Изменение дерева и рекурсивная установка отклоняются.
`bad_alloc` даёт `NO_MEMORY`, другое исключение — `CALLBACK_FAILED`.
После подготовки существование узлов проверяется повторно. Фиксация выполняет
одну объединённую инвалидацию, небросающие присваивания и обмены без расширений.
Устаревшие записи очищаются при следующей успешной операции.

Каждая зафиксированная операция увеличивает общую ревизию всех привязанных
виджетов. Равные значения не требуют кадра; изменение цвета даёт PAINT,
минимальной ширины — LAYOUT. Установка внутри кадра даёт `WOULD_BLOCK`:
повтор выполняет приложение между кадрами. Рисование читает установленный стиль.
`MAX_PSS_BYTES`, `MAX_STYLE_RULES` и `maxBindings` ограничивают хранение.

## Палитры и ANSI16

Доступны Modern, Turbo, Nord, Gruvbox, Tokyo Night и светлая Catppuccin Latte.
Фабрики могут выделять память до установки. `themes/modern.pss` и `turbo.pss`
соответствуют типизированным фабрикам; `themeFromTokens(ThemeTokens)` настраивает
шесть цветовых токенов. Четыре дополнительные палитры адаптированы из
[Textual](https://github.com/Textualize/textual/blob/06dbeef4bb70fb718236aa418ed658ef4667a126/src/textual/theme.py);
лицензия и исходная версия сохранены в [vendor/textual](../../vendor/textual/README.md).
Подробная таблица цветов находится в [гайде по темам](themes-guide.md).

Украшения стандартных контролов, таблиц и редактора используют ASCII.
Пользовательский текст сохраняет Unicode и заданную политику ширины.

```cpp
portals::FrameWriterLimits limits;
limits.colorMode = portals::ColorMode::ANSI16;
portals::FrameWriter writer(output, limits);
```

ANSI16 выбирает ближайший из 16 стандартных цветов по квадрату расстояния RGB;
при равенстве — меньший индекс. Выводит SGR 30–37/90–97 и 40–47/100–107.
Внешний вид определяется палитрой терминала. Близкие цвета могут совпасть;
жирное выделение и контраст курсора сохраняются. Поддержка атрибутов зависит
от терминала.

FrameWriter сохраняет режим до уничтожения, включая частичный вывод.
Прямые вызовы `encodeDiff(previous, next, cap, mode)` требуют одинакового режима;
при смене задайте `previous == nullptr` для полной перерисовки.
По умолчанию используется TRUE_COLOR. Владелец терминала задаёт возможности явно.

## Передача значений

Цели, селекторы, правила и таблицы остаются агрегатами. Их передача копирует
строки/векторы и может бросать: проверяемая STL MSVC может выделять память
для итераторов внутри `noexcept`-перемещения. Парсер и движок перехватывают
внутренние копии, включая возвращаемый expected. Создание аргументов и отдельные
фабрики тем сохраняют обычные исключения C++.
Подготовка может копировать правила и метаданные; стоимость зависит от числа
правил, виджетов и сопоставляемых классов. Установка выполняется между кадрами;
фиксация только обменивает хранилища и присваивает значения фиксированного размера.
