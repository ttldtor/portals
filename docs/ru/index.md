# Portals: краткое руководство {#short-guide-ru}

[Английская версия](../index.md) · [Содержание](guides.md) · [Глоссарий](glossary.md)

Portals — разрабатываемая библиотека терминального интерфейса на C++23.
Основной способ создания интерфейса — декларативный API `ui`.
Эта страница поможет начать работу с библиотекой.
В [содержании документации](reference-map.md) приведены полный список разделов
и ссылки для изучения API.

## Начните с декларативного API

`<portals/ui.hpp>` предоставляет сцены, рецепты и обработчики событий.
`<portals/ui_style.hpp>` добавляет операции со стилями, используемые в примере.

Опишите дерево контролов, затем добавьте стиль и обработчики через [стадии UI](glossary.md#glossary-ui-stage-ru) — объекты, задающие операции над сценой через `|`.
В примере `ui::vbox(...)` создаёт [рецепт](glossary.md#glossary-recipe-ru) —
описание создаваемых контролов. `ui::scene(...)` сохраняет его в
[сцене](glossary.md#glossary-scene-ru), которая управляет подготовкой и запуском.
Кнопка дописывает текст в редактор, F10 запрашивает штатное завершение.

```cpp
#include <portals/ui.hpp>
#include <portals/ui_style.hpp>

int main() {
  using namespace portals;

  ui::Ref<LineEdit> message;
  ui::Ref<Button> add;

  auto scene = ui::scene(ui::vbox(
    ui::label("Greeting"),
    ui::lineEdit(message, ""),
    ui::button(add, "Add Hello")));

  return scene
    | ui::style("Button { bold: true; }")
    | ui::onClick(add,
                  [message] {
                    message.text() += "Hello!";
                  })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

`runApp` пытается восстановить терминал и сообщает об ошибках. В этой короткой
форме рецепт создаётся до входа в `runApp`; фабричная перегрузка нужна, если
создание рецепта тоже должно попасть под проверяемую границу ошибок.
Команда завершения определяет активную сцену внутри обработчика, вызванного этой сценой.
Явный `SceneRef` остаётся вариантом для действия, адресованного конкретной сцене.
[Декларативная композиция](declarative-ui.md) описывает обработчики,
ошибки настройки и низкоуровневый типизированный результат `run()`.

## Соберите своё приложение

Создайте каталог `my-app`. Сохраните полный пример выше в файл `main.cpp`,
а следующую конфигурацию — в `CMakeLists.txt` в этом каталоге:

```cmake
cmake_minimum_required(VERSION 3.24)
project(MyApplication LANGUAGES CXX)

include(FetchContent)
FetchContent_Declare(portals
  GIT_REPOSITORY https://github.com/ttldtor/portals.git
  GIT_TAG 7f09c7db9547c34c547b05e4fbf18d5c9f492ee5
)
FetchContent_MakeAvailable(portals)

add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE portals::core)
```

Выполните команды из каталога `my-app`. При конфигурации CMake загрузит
выбранную ревизию Portals, затем соберёт ваше приложение `my_app`:

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --target my_app
./build/my_app
```

На Windows используйте x64 Developer PowerShell для Visual Studio. На Linux
нужны совместимые компилятор C++ и стандартная библиотека. Для сборки необходимы
Git, CMake 3.24+, Ninja и инструментарий с поддержкой C99 и C++23, включая
заголовки стандартной библиотеки C++ `<expected>` и `<format>`.

Запустите `my_app` в терминале: нажмите кнопку **Add Hello**, чтобы дописать текст,
и F10 для выхода. На Windows исполняемый файл — `build/my_app.exe`, на Linux —
`build/my_app`. Команды выше используют одноконфигурационный генератор Ninja.

`GIT_TAG` закрепляет ревизию исходников для этого примера. Измените её при
выборе более новой версии Portals. Подключение через FetchContent описано в
[документации CMake (EN)](https://cmake.org/cmake/help/latest/module/FetchContent.html).

### Локальные исходники или установленный SDK

Если исходники Portals уже находятся в подкаталоге `portals` вашего проекта,
замените `include(FetchContent)` и оба вызова `FetchContent_*` на
`add_subdirectory(portals)`. Загрузка не потребуется.

Для установленного SDK замените те же строки на
`find_package(Portals CONFIG REQUIRED)` и при конфигурации передайте каталог
установки в `CMAKE_PREFIX_PATH`. Во всех вариантах используется
`target_link_libraries(my_app PRIVATE portals::core)`. Установка и совместимость
инструментария описаны в [подключении пакета](package.md).

## Что доступно

- Формы: Label, Button, CheckBox, LineEdit, Row/Column, Grid/Overlay и наблюдающие ссылки.
- Данные: неизменяемые модели, виртуальные списки/таблицы, прокрутка и графики.
- Стили: темы, слои и PSS с разбором при компиляции или выполнении.
- Асинхронность: необязательные UI-корутины с ограниченными ресурсами поверх существующего Scheduler.
- Ввод: строковые сочетания, альтернативы, последовательности и явный выбор фаз.
  Доставка событий терминалом зависит от реализации ввода. Согласование Kitty и отдельные физические
  модификаторы пока не реализованы: **TBD — M7/U89**.
- Ошибки: обработчик `onError` во время операции и отдельный итоговый отчёт после очистки.
  Встроенный индикатор и панель диагностики — **TBD**, общий фундамент
  M2/U22/U24 и M3/U33.

API развивается. Поддержанные платформы и точные ограничения выполнения описаны
в [ограничениях](limitations.md).
