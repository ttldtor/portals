# Portals: краткое руководство {#short-guide-ru}

[Английская версия](../index.md) · [Руководства по задачам](guides.md) · [Содержание документации](reference-map.md) · [Глоссарий](glossary.md)

Portals — разрабатываемая библиотека терминального интерфейса на C++23.
Основной способ создания интерфейса — декларативный API `ui`.
Эта страница поможет начать работу с библиотекой.
В [содержании документации](reference-map.md) приведены полный список разделов
и ссылки для изучения API.

Markdown-файлы описывают текущую ветку исходников. [Опубликованная HTML-справка](https://ttldtor.github.io/portals/) соответствует последнему стабильному релизу; HTML-черновик изменений доступен в артефактах CI соответствующего PR.

В [руководстве по первому приложению](first-application.md) форма заметки
появляется в четыре этапа: от запускаемого поля ввода до оформления и действий
с сохранением и очисткой текста.

## Декларативный API

`<portals/ui.hpp>` предоставляет сцены, рецепты и обработчики событий.
`<portals/ui_style.hpp>` добавляет операции со стилями, используемые в примере.

В примере дерево контролов дополняют стиль и обработчики, подключённые через
[стадии UI](glossary.md#glossary-ui-stage-ru) — объекты, задающие операции над
сценой после `|`. Здесь `ui::vbox(...)` создаёт [рецепт](glossary.md#glossary-recipe-ru),
то есть описание контролов. `ui::scene(...)` сохраняет этот рецепт в
[сцене](glossary.md#glossary-scene-ru), которая управляет подготовкой и запуском.
Кнопка дописывает текст в редактор, а F10 запрашивает штатное завершение.

```cpp
#include <portals/ui.hpp>
#include <portals/ui_style.hpp>

int main() {
  using namespace portals;

  ui::Ref<LineEdit> message;
  ui::Ref<Button> add;

  auto scene = ui::scene(ui::vbox(
    ui::label("Greeting"),
    ui::lineEdit(message, ""),
    ui::button(add, "Add Hello")));

  return scene
    | ui::style("Button { bold: true; }")
    | ui::onClick(add,
                  [message] {
                    message.text() += "Hello!";
                  })
    | ui::onKey("F10", ui::quit)
    | ui::runApp();
}
```

`runApp` пытается восстановить терминал и сообщает об ошибках. В этой короткой
форме рецепт создаётся до входа в `runApp`; фабричная перегрузка нужна, если
создание рецепта тоже должно попасть под проверяемую границу ошибок.
Команда завершения определяет активную сцену внутри обработчика, вызванного этой сценой.
Явный `SceneRef` остаётся вариантом для действия, адресованного конкретной сцене.
[Декларативная композиция](declarative-ui.md) описывает обработчики,
ошибки настройки и низкоуровневый типизированный результат `run()`.

## Подключение библиотеки к приложению

Для приложения можно создать каталог `my-app` и сохранить полный пример выше
в `main.cpp`. В том же каталоге находится `CMakeLists.txt` со следующей
конфигурацией:

```cmake
cmake_minimum_required(VERSION 3.24)
project(MyApplication LANGUAGES CXX)

include(FetchContent)
FetchContent_Declare(portals
  GIT_REPOSITORY https://github.com/ttldtor/portals.git
  GIT_TAG 7f09c7db9547c34c547b05e4fbf18d5c9f492ee5
)
FetchContent_MakeAvailable(portals)

add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE portals::core)
```

Из каталога `my-app` эти команды настраивают сборку, загружают выбранную
ревизию Portals и собирают приложение `my_app`:

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --target my_app
./build/my_app
```

В Windows сборку можно выполнять в x64 Developer PowerShell для Visual Studio.
В Linux необходимы совместимые компилятор C++ и стандартная библиотека.
Для сборки нужны Git, CMake 3.24+, Ninja и инструментарий с поддержкой C99 и C++23, включая
заголовки стандартной библиотеки C++ `<expected>` и `<format>`.

При запуске `my_app` в терминале кнопка **Add Hello** дописывает текст, а F10
завершает приложение. В Windows исполняемый файл — `build/my_app.exe`, в Linux —
`build/my_app`. В командах выше используется одноконфигурационный генератор Ninja.

`GIT_TAG` закрепляет ревизию исходников для этого примера. При выборе более
новой версии Portals это значение можно обновить. Подключение через FetchContent
описано в
[документации CMake (EN)](https://cmake.org/cmake/help/latest/module/FetchContent.html).

### Локальные исходники или установленный SDK

Если исходники Portals уже находятся в подкаталоге `portals` проекта,
`include(FetchContent)` и оба вызова `FetchContent_*` можно заменить на
`add_subdirectory(portals)`. Тогда сборка использует локальные исходники без загрузки.

Для установленного SDK те же строки можно заменить на
`find_package(Portals CONFIG REQUIRED)`, указав каталог установки в
`CMAKE_PREFIX_PATH` при конфигурации. Во всех вариантах используется
`target_link_libraries(my_app PRIVATE portals::core)`. Установка и совместимость
инструментария описаны в [подключении пакета](package.md).

## Что доступно

- Формы: Label, Button, CheckBox, LineEdit, Row/Column, Grid/Overlay и наблюдающие ссылки.
- Данные: неизменяемые модели, виртуальные списки/таблицы, прокрутка и графики.
- Стили: темы, слои и PSS с разбором при компиляции или выполнении.
- Асинхронность: необязательные UI-корутины с ограниченными ресурсами поверх существующего Scheduler.
- Ввод: строковые сочетания, альтернативы, последовательности и явный выбор фаз.
  Доставка событий терминалом зависит от реализации ввода. Согласование Kitty и отдельные физические
  модификаторы пока не реализованы: **TBD — M7/U89**.
- Ошибки: обработчик `onError` во время операции и отдельный итоговый отчёт после очистки.
  Приложение может явно показывать [уведомления](notifications.md), включая
  постоянные сообщения и необязательные индикаторы. Автоматические сообщения
  об ошибках и ведение журнала определяет приложение.

API развивается. Поддержанные платформы и точные ограничения выполнения описаны
в [ограничениях](limitations.md).
